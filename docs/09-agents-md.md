# AGENTS.md：全局指令

pi 启动时会读入全局 `~/.pi/agent/AGENTS.md`，以及从当前工作目录往上各级目录里的上下文文件，包括 `~/AGENTS.md` 和项目里的 `AGENTS.md`。同一目录下 `AGENTS.override.md` 优先；`CLAUDE.md` 也能识别。本页讲全局这一份（[`config/AGENTS.md`](../config/AGENTS.md)），仓库副本里的家目录统一写成 `~`。

这份全局指令的用途很单一：把反复踩过的坑写成规矩，让模型每次会话都照做。一共三块，每块对应一类真实发生过的问题。

## 1. 云盘排除

Dropbox、OneDrive 这类云盘目录划为排除区，模型要读取、查找、索引其中任何内容，都得先经过我明确同意。

原因在于云盘的工作方式：“仅在线”文件在本地只是占位符，一读内容就会触发下载。模型一次批量搜索或索引，就可能把大量云盘文件拉到本地，白白消耗流量、磁盘和时间；在云盘目录里生成的文件还可能被同步上传。要注意，这条规则约束的是模型的行为，真正的文件访问权限仍由操作系统控制。

## 2. 搜索纪律：内置 find/grep 即 FFF

pi-fff 运行在 `override` 模式（见 [03-进阶阶段.md](03-进阶阶段.md)）：内置 `find`/`grep` 的名字和参数不变，底层换成了 FFF，自带预索引、frecency 排序、模糊匹配和 git 感知。内置工具已经够好，所以这部分指令只讲怎么权衡、怎么避坑，不再规定必须用哪个工具：

- **工具让模型自己选**：内置 `find`/`grep` 和 bash 各有擅长的场景，由模型当场判断。指令只管 bash 那一侧的用法。
- **bash 里优先 fd/rg**：找路径用 `fd`，搜内容用 `rg`。它们的语法和 find/grep 不同，要按各自的写法表达搜索意图，直接照搬 find/grep 的参数会得到错误结果；拿不准就先看 `fd --help` / `rg --help`。
- **小心默认过滤**：fd/rg 默认会悄悄跳过隐藏文件和被忽略的文件（rg 还跳过二进制内容）。结果意外为空时，先怀疑是被过滤了，再下“目标不存在”的结论。
- **隐藏路径的盲区**：工作目录不在 git 仓库里时，FFF 索引会跳过隐藏条目，内置工具因此看不到 `~/.pi` 这类路径。这时改用 bash，直接以那个隐藏目录为起点搜索。

## 3. 子代理委托策略

这是整份文件的核心，和 [`config/agents/pico.md`](../config/agents/pico.md) 配套使用（pico 的设计见 [08-agents.md](08-agents.md)）。

- **默认自己做。** 每次委托都有固定开销：子代理冷启动、重新读文件，主模型写任务书、验收结果，加起来至少一分钟。主模型手上没有别的活时，这一分钟全算在用户的等待里。规则开头先把这笔账算清楚，模型就不会把“便宜”误当成“免费”。
- **三个条件同时满足才委托：** 任务量够大（约 10 次以上工具调用，或原始输出远多于需要的摘要）；能一次写清任务书；委托期间主会话有别的事可做，或者原始输出会塞满上下文。“约 10 次”是经验值，可以按 pico 的实际耗时调整。
- **留在主会话做的事：** 几次工具调用就能完成的活（包括 search → read → edit 这种短链条）、单次查找、小改动和小 bug、设计决策和没说清的偏好、破坏性操作。云盘排除规则已经写进 pico 正文，这里不再重复。
- **适合委托的事：** 仓库级调研、大改动里的独立实现切片、给模块写测试、只关心结论的长时间测试/构建、多源联网调研。
- **任务书要自包含。** 子代理只看得到 prompt，看不到对话历史。委托时写清目标、文件路径、预期行为、约束和验证步骤。
- **报告写盘。** 调研类任务给 pico 一个 slug，报告写到磁盘，主会话只收摘要。这是控制主模型 token 成本的关键，对应 pico.md 正文里的“大报告写盘”。
- **编排规矩。** 决定委托就尽早派出去；主会话自己还有活时放后台，只能干等时用前台；多个并行任务在同一轮一起发出。按文件切分任务，避免多个子代理改同一个文件；子代理完成后先检查实际改动，再向用户报告。子代理因为缺信息或超出范围停下来时，由主会话补上决策、接手处理。

这部分规则最容易迁移：换成别的模型、别的 AI 编码工具，“什么时候委托、怎么写委托”这套做法照样适用。
