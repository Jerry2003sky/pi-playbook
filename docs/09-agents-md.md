# AGENTS.md：全局指令

pi 启动时读入全局 `~/.pi/agent/AGENTS.md`，以及从当前工作目录向上各级目录的上下文文件，包含适用的 `~/AGENTS.md` 和项目 `AGENTS.md`。同一目录中的 `AGENTS.override.md` 优先，常规文件也支持 `CLAUDE.md`。本页讲全局这一份（见 [`config/AGENTS.md`](../config/AGENTS.md)），仓库副本将个人家目录统一写成 `~`。

我的这份全局指令只解决一个问题：把反复踩过的工程坑写成纪律，让模型每次会话都遵守。三块内容，每一块对应一类真实的失败。

## 1. 云盘排除

Dropbox、OneDrive 这类云盘目录被列为排除区，模型对其任何读取、查找、索引操作都要先经过我显式批准。

这条规则针对的是云盘的工作方式：Dropbox 的“仅在线”文件在本地只留占位符，读取内容会触发下载。模型的批量内容搜索、索引或读取可能让大量云盘文件落到本地，增加流量、磁盘和时间消耗；在云盘目录生成的文件还可能被同步上传。因此，全局指令要求模型在访问这些路径前取得显式批准。这是模型执行纪律；文件系统访问权限仍由操作系统决定。

## 2. 搜索纪律：内置 find/grep 即 FFF

pi-fff 跑 `override` 模式（[03-进阶阶段.md](03-进阶阶段.md)）：内置 `find`/`grep` 的名字与参数形态不变，实现在后台整个换成 FFF——预索引、frecency 排序、模糊匹配、git 感知。纪律从“点名工具”放宽成“权衡 + 避坑”：

- **工具选择交给模型**：内置 `find`/`grep` 与 bash 各有适用场景，当场权衡着选，指令层只约束 bash 侧的质量。
- **bash 里 fd/rg 优先**：路径用 `fd`、内容用 `rg`。二者有自己的语法体系，把搜索意图翻译成目标工具自身的写法，照搬 grep/find 参数会跑出错误结果；拿不准先 `fd --help` / `rg --help`。
- **默认过滤的坑**：fd/rg 静默跳过隐藏与忽略文件（rg 还跳过二进制内容），结果意外为空时先怀疑这道过滤，再下“目标不存在”的结论。
- **隐藏路径的盲区**：workspace 处在 git repo 之外时，FFF 索引跳过隐藏条目，`~/.pi` 这类路径对内置工具不可见——改走 bash，从隐藏目录本身根起搜。

## 3. 子代理委托策略

整份文件的核心，与 [`config/agents/pico.md`](../config/agents/pico.md) 配套（设计详解在 [08-agents.md](08-agents.md)）。

- **默认自己做**——每次委托都有固定开销：子代理冷启动、重读文件，主模型写任务书、验收结果，至少一分钟。主模型手上没有并行的活时，这段时间全部变成用户的等待。规则开头把这笔账写明，模型才不会把“便宜”当成“免费”。
- **三条同时满足才委托**：切片够大（约 10 次以上工具调用，或原始输出远大于所需摘要）；能一次写完任务书；委托期间主会话有别的活可干，或原始输出会灌满上下文。“约 10 次”是经验值，按 pico 的实际往返时间调整。
- **Inline 清单**——几次工具调用能完成的活（包括 search → read → edit 这样的短链条）、单次查找、小改动和小 bug、设计决策与未定偏好、破坏性操作，都留在主会话。云盘排除规则已写进 pico 正文，这里不再单列。
- **Good fits**——仓库级调研、大改动中的独立实现切片、为模块写测试、只需结论的长测试/构建、多源联网调研。
- **Prompt 契约**——子代理只看到 prompt，看不到历史。委托必须自包含：目标、文件路径、预期行为、约束、验证步骤。
- **Report-to-disk**——调研类任务给 pico 一个 slug，报告写盘，主会话只收摘要。这是控制主模型 token 成本的关键机制，和 pico.md 正文的“大报告规则”呼应。
- **编排纪律**——决定委托就尽早派发；主会话有自己的活时后台运行，只能干等结果时前台运行；并行切片在同一轮批量启动。切片按文件划分，避免重叠编辑；派发后检查实际改动，再报告完成。子代理因缺信息或超出范围停下时，主会话负责补齐决策并接手。

这段规则是可移植性最强的部分：换任何模型、任何 AI 编码工具，“何时委托 + 如何写委托”的纪律都成立。
