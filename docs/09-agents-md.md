# AGENTS.md：全局指令

`AGENTS.md` 是 pi 每次会话都自动读入的指令文件，读三个位置：家目录 `~/AGENTS.md`、项目 `<repo>/AGENTS.md`、pi 全局 `~/.pi/agent/AGENTS.md`。我的这份指最后一个（见 [`config/AGENTS.md`](../config/AGENTS.md)）。

我的这份全局指令只解决一个问题：把反复踩过的工程坑写成纪律，让模型每次会话都遵守。三块内容，每一块对应一类真实的失败。

## 1. 云盘排除

Dropbox、OneDrive 这类云盘目录被列为排除区，模型对其任何读取、查找、索引操作都要先经过我显式批准。

这条规则针对的是云盘的工作方式：Dropbox 的“仅在线”文件在本地只留占位符，任何扫描——搜索、索引、读取——都会触发它把真实内容下载下来。模型干活时的批量扫描（比如大范围 grep、目录遍历）会把整个云盘一点点拖回本地：流量、磁盘、时间全部白费，扫描产生的文件还可能被同步回云盘。所以在指令层面把这些路径物理隔离掉：模型默认不能碰，真要碰必须显式批准。

## 2. 搜索纪律：ffgrep/fffind 即 FFF

搜索一律走 `ffgrep`（内容）与 `fffind`（路径）——@ff-labs/pi-fff 注册的搜索工具（[03-进阶阶段.md](03-进阶阶段.md)），frecency 排序让常用文件先命中，结果带光标分页；目录列表用内置 `ls`。规则把搜索纪律写死了：每次搜索用 `path` 圈定范围，先定位再精读命中区；Bash 整体禁用于搜索、列表、读取，确有必要的操作回退 `rg`（内容）/ `fd`（路径）、说明理由并限定输出（如 `head -50`）；回退时把搜索意图翻译成 rg/fd 自身语法，照搬 grep/find 参数会跑出错误结果，拿不准先 `rg --help` / `fd --help`。

## 3. 子代理委托策略

整份文件的核心，与 [`config/agents/pico.md`](../config/agents/pico.md) 配套（设计详解在 [08-agents.md](08-agents.md)）。

- **默认委托给 pico**——便宜、快、自带工具扩展。
- **决策规则是两条硬标准**：能写出完整规格 +（会灌满主上下文 或 与下一步独立）。两条都满足才委托，任何一条不满足就自己做。这条规则的目的是防止模型在两个极端间摇摆：事无巨细都委托（慢、贵、质量差）或从不委托（主上下文被原始材料灌爆）。
- **Keep 清单**——设计决策、未定偏好、破坏性操作、云盘排除区四类永远留在主会话。委托边界划清楚，模型才不会把不可逆操作外包出去。
- **Prompt 契约**——子代理只看到 prompt，看不到历史。委托必须自包含：目标、文件路径、预期行为、约束、验证步骤。
- **Report-to-disk**——调研类任务强制写盘报告，主会话只收摘要。这是控制主模型 token 成本的关键机制，和 pico.md 正文的“大报告规则”呼应。
- **编排纪律**——任务开始就分解、中期超 3 次调用就移交、前台留给依赖项、批量并行、不空等。

这段规则是可移植性最强的部分：换任何模型、任何 AI 编码工具，“何时委托 + 如何写委托”的纪律都成立。
