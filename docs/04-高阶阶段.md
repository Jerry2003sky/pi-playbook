# 高阶阶段：子代理与剪枝

本阶段是整套配置里改造最深的两件东西（定位见 [01-理念与路线.md](01-理念与路线.md)）：子代理引入多代理并行与隔离，剪枝把上下文占用从线性增长压成近似恒定。两者都动到了 pi 的工作方式本身，权衡也最明显——子代理有权限边界问题，剪枝丢历史细节。所以它们放在最高阶，前面的阶段是它们的底座。

本页内容：**@tintinweb/pi-subagents**（子代理系统）· **pi-condense**（上下文剪枝）

## @tintinweb/pi-subagents —— 子代理系统

> 商店：[pi.dev/packages/@tintinweb/pi-subagents](https://pi.dev/packages/@tintinweb/pi-subagents) · 仓库：[tintinweb/pi-subagents](https://github.com/tintinweb/pi-subagents)

pi 默认是单模型单会话：所有工作在一个上下文里完成，决策和执行挤在一起。任务规模变大后，机械执行的部分占用大量上下文和 token，和决策部分互相干扰。

pi-subagents 引入子代理：主代理通过 `Agent` 工具派发任务给独立会话的代理，支持前台阻塞、后台异步、并行执行、定时调度；子代理可以嵌套委托；支持 git worktree 隔离；可以用 `@代理名` 在输入框直接点名；跑一半可以用 `steer_subagent` 中途干预。

这套机制是“便宜模型做执行”理念的载体：大任务的机械部分交给 flash 级子代理，主模型只做决策和汇总。子代理自带隔离（独立上下文、可选 worktree），任务拆解也有了安全边界。

安装：

```bash
pi install npm:@tintinweb/pi-subagents@0.19.0
```

配置分两层：持久设置在全局 `~/.pi/agent/subagents.json`（项目 `.pi/subagents.json` 覆盖）；每个自定义代理是一个 Markdown 文件，YAML frontmatter 定义属性、正文是它的 system prompt，放在 `.pi/agents/<name>.md`（项目级）或 `~/.pi/agent/agents/<name>.md`（全局），项目级覆盖全局同名。

**我的配置**：没有 subagents.json，持久设置全默认（并发 10、深度 2、fallback general-purpose）。唯一自定义是 `pico` 执行代理（[`config/agents/pico.md`](../config/agents/pico.md)），设计详解在 [08-agents.md](08-agents.md)：模型钉 deepseek 的 `deepseek-flash`、thinking max、工具白名单收紧、`prompt_mode: replace`、不开嵌套权限。

**常用参数**

| 参数 | 位置 | 作用 |
|------|------|------|
| `maxConcurrent` | subagents.json | 后台代理并发上限（默认 10） |
| `maxSubagentDepth` | subagents.json | 嵌套委托深度上限（默认 2），`0` / `1` 全局关嵌套 |
| `fallbackSubagent` | subagents.json | 类型名解析失败时的兜底，`none` 是严格模式直接报错 |
| `model` | 代理 frontmatter | 该代理用的模型，成本控制的第一旋钮 |
| `tools` | 代理 frontmatter | 限定代理能用的工具 |
| `allowed_subagents` | 代理 frontmatter | 嵌套委托白名单，不开则子代理不能再派发 |

**参数详解**

持久设置（subagents.json）：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `maxConcurrent` | number，10 | 后台代理并发上限 |
| `maxSubagentDepth` | number，2 | 嵌套深度上限（主会话=0 → 子代理=1 → 嵌套=2） |

## pi-condense —— 上下文剪枝

> 商店：[pi.dev/packages/pi-condense](https://pi.dev/packages/pi-condense) · 仓库：[jjuraszek/pi-condense](https://github.com/jjuraszek/pi-condense)

上下文是长会话最贵的资源，而 pi 的默认行为是让工具输出永久占住大量上下文：读过的大文件、跑过的命令输出、搜过的结果，全都堆在窗口里，越聊越贵越慢，最后触发 compact 把整个会话压进摘要——那是质量损失最大的一种处理。

pi-condense 做的是逐批归档而不是整体压缩：已消耗的工具输出在 flush 时交给摘要模型压缩成短 stub（原始内容归档到会话本地索引），模型要用时经 `context_tree_query` 按引用取回。这样历史细节默认不占上下文，需要时还能拿回来。上下文占用从线性增长变成近似恒定，长会话才可持续。

代价有三个：历史细节默认不可见（需要模型主动按引用取回），每批摘要本身的模型调用成本，以及剪枝所带来的上下文缓存打断。尤其是缓存打断会带来不同程度的成本上升，所以摘要模型的选型和剪枝的处理方式是这个插件的核心配置点。

安装：

```bash
pi install npm:pi-condense@2.10.3
```

装完要 `enabled: true`（或会话内 `/pruner on`）才会工作——默认关闭。配置写在 `settings.json` 的 `contextPrune` 段。命令族：`/pruner on|off|now|status|tree|compact|model|min-batch-chars|protected-tools|protected-paths`。

**我的配置**（settings.json 的 contextPrune 段，完整文件见 [`config/settings.json`](../config/settings.json)）：

```json
{
  "enabled": true,
  "showPruneStatusLine": false,
  "summarizerModel": "deepseek/deepseek-flash",
  "summarizerThinking": "low",
  "pruneOn": "agent-message",
  "batchingMode": "agent-message",
  "quietOversizedSkips": true,
  "minBatchChars": 8000,
  "recoveryGraceTurns": 3,
  "summarizerIdleTimeoutMs": 20000,
  "summarizerMaxTimeoutMs": 100000,
  "protectedTools": [
    "ask_user_question",
    "planmode",
    "Agent",
    "get_subagent_result",
    "web_search",
    "source_check",
    "get_search_content"
  ],
  "protectedPaths": ["**/skills/**/*.md"],
  "chainCompression": {
    "enabled": false,
    "rollingWindow": 3,
    "stripFinalAssistantThinking": true,
    "fuseRangeSummary": true
  },
  "purgeErrors": {
    "enabled": true,
    "cooldownTurns": 2,
    "minArgChars": 500
  },
  "dedupByContentHash": true,
  "autoBudgetThreshold": null,
  "spillThreshold": 16384,
  "spillPreviewBytes": 2048,
  "budgetTurnDelta": null,
  "frontierGapThresholdTokens": null
}
```

> **⚠️ 调整剪枝参数时，一起观察缓存命中率与摘要成本。** 剪枝会修改会话前缀，影响后续请求的缓存复用。摘要模型、批量门槛、链压缩开关与 spill 阈值共同决定成本和延迟；换模型后可用 `/pruner status` 和 `/cache graph` 检查实际效果。

几个关键决定：

- **摘要模型使用 `deepseek/deepseek-flash`，thinking 用 low。** 与 pico 和会话命名共用执行档模型；pico 的思考档位为 max，摘要单独设为 low。
- **minBatchChars 拉到 8000。** 默认 1000 会让小工具调用也走一遍摘要 LLM——摘要比原文还大就是浪费。攒够 8000 字符再剪一批，摘要调用次数大幅下降。
- **chainCompression 关闭。** 链级压缩会动滚动窗口外的历史链，让前缀缓存的稳定分段失效。当前剪枝模式已经够用，关掉换缓存命中率——效果可以用 pi-cache-graph 验证。
- **protectedTools 保护七个工具。** `ask_user_question`（提问）、`planmode`（计划）、`Agent`、`get_subagent_result`（子代理）、`web_search`、`source_check`、`get_search_content`（联网）——这些输出是决策关键信息，剪了模型就失去上下文依据。2.10.3 起有个例外：受保护调用如果带字符串 `path` 参数，同名路径只保留最新一次读取，更早的变成 `[Superseded: …]` stub；这七个工具基本没有 `path` 参数，影响主要在 `protectedPaths`。
- **protectedPaths 只列 skills 一条。** 2.10.2 起插件默认值是 `["**/skills/**/*.md", "**/gauntlet-overrides.md"]`，用户显式配置会整体替换默认值；当前显式列表只包含技能文件，gauntlet 覆盖文件处于保护范围之外。
- **spillThreshold 压到 16384。** 超大输出更早旁路，上下文里只留 2KB 预览。
- **summarizerMaxTimeoutMs 收紧到 100000。** 廉价档做摘要足够快，收紧超时防止“滴水”流拖时间。

**常用参数**

| 参数 | 作用 |
|------|------|
| `enabled` | 总开关 |
| `summarizerModel` | 摘要用模型，`default` 复用活跃模型或 `provider/model-id` |
| `minBatchChars` | 批量摘要的最小字符门槛 |
| `pruneOn` | 触发时机：`agent-message` 自动 / `on-demand` 全手动 |
| `protectedTools` | 永不摘要的工具输出（精确名匹配；同名路径只留最新读取） |
| `spillThreshold` | 超长输出的旁路阈值 |

**参数详解**

主开关与触发：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `enabled` | bool，false | 总开关 |
| `pruneOn` | `agent-message` / `on-demand` | 触发时机 |
| `autoBudgetThreshold` | number/null，null | 窗口占比 0–1，达阈值无视时机强制 flush |
| `budgetTurnDelta` | number/null，null | 单轮用量涨幅超限强制 flush |
| `frontierGapThresholdTokens` | number/null，null | 未剪尾部达 N token 即在轮末强制 flush（绝对值触发，与窗口占比无关；官方建议起始值 80000） |
| `showPruneStatusLine` | bool，true | footer 状态行 |

摘要模型：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `summarizerModel` | `default` 或 `provider/model-id` | 摘要模型 |
| `summarizerThinking` | `default` 或 off–xhigh | 摘要思考档位 |
| `summarizerIdleTimeoutMs` | number，20000 | 流空闲超时 |
| `summarizerMaxTimeoutMs` | number，180000 | 流总时长上限 |

批量与质量门：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `batchingMode` | `turn` / `agent-message` | 每助手轮一条 / 一轮用户消息到最终回复合并一条 |
| `minBatchChars` | number，1000 | 低于则整批跳过 |
| `quietOversizedSkips` | bool，false | 跳过批次时静默 |
| `dedupByContentHash` | bool，true | 重复输出直接 stub 化 |
| `recoveryGraceTurns` | number，3 | 恢复输出的原样保留轮数，防 retrieve→re-stub 循环 |

保护与恢复：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `protectedTools` | array，[] | 永不摘要的工具输出，精确名匹配；带字符串 `path` 参数的受保护调用只保留最新一次读取，更早的变成 `[Superseded: …]` stub |
| `protectedPaths` | array，`["**/skills/**/*.md", "**/gauntlet-overrides.md"]` | 按 args.path glob 匹配；用户显式设置会整体替换默认值 |

链压缩与错误清理：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `chainCompression.enabled` | bool，true | 对滚动窗口外的老封闭链做链级压缩 |
| `chainCompression.rollingWindow` | number，3 | 最近 N 条封闭链保持原文 |
| `chainCompression.stripFinalAssistantThinking` | bool，true | 剥掉最终助手思考 |
| `chainCompression.fuseRangeSummary` | bool，true | 多批摘要融合成一条 |
| `purgeErrors.enabled` | bool，true | 失败调用的参数体换成紧凑 stub |
| `purgeErrors.cooldownTurns` | number，2 | 错误清理冷却轮数 |
| `purgeErrors.minArgChars` | number，500 | 参数体最小字符门槛 |

超长输出：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `spillThreshold` | number，65536 | 超长单条输出整体旁路到 sidecar 文件 |
| `spillPreviewBytes` | number，2048 | 内联保留的预览字节 |

## 整体架构

装完四个类别之后，这份配置的全貌：

```
主模型（GPT-6 Astra）
  ├─ Agent 工具 → pico 子代理（deepseek-flash）：机械执行、报告写盘
  ├─ ask_user_question：需求不明时弹结构化问卷
  └─ 上下文：pi-condense 剪枝（deepseek-flash 摘要）
              ↓ 观测
  pi-context-view（占用图）+ pi-cache-graph（命中率）+ pi-token-speed（速度）
```

两处联动值得注意：pico 子代理的委托决策规则写在全局 AGENTS.md 里（[09-agents-md.md](09-agents-md.md)）；剪枝改变前缀内容直接影响缓存命中，两者的关系在 pi-cache-graph 里看得见（[03-进阶阶段.md](03-进阶阶段.md)）。
