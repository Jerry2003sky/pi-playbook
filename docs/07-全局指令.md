# AGENTS.md：全局指令

pi 启动时会自动读入全局 `~/.pi/agent/AGENTS.md`，以及从当前工作目录逐级向上找到的上下文文件（含 `~/AGENTS.md` 与项目级 `AGENTS.md`）。同级目录下 `AGENTS.override.md` 优先，`CLAUDE.md` 同样会被识别。本页拆解全局这一份（[`config/AGENTS.md`](../config/AGENTS.md)），仓库副本中的家目录统一脱敏为 `~`。

这份指令的目的很单纯：把反复踩过的坑写成明文规矩，让模型每次启动都照办。自己写的内容共三块，每块都对应一类真实撞上的问题。

文件开头另附两段通用规则：一段是 `talk-normal`（先给结论、准确优先于简短、省去开场客套与结尾寒暄），另一段是流传较广的 Karpathy Guidelines（动手前先想清楚、能简单就不复杂、只改必须改的地方、用可验证目标驱动执行）。两段原样收录，下文只讲自己写的三块。

## 1. 云盘排除

Dropbox、OneDrive 这类云盘目录一律划为禁区：模型无论要读取、查找还是索引其中的内容，都须先获得明确同意。

症结在于云盘的按需同步机制：“仅在线”文件在本地只是占位符，一旦被读取内容就会触发下载。模型顺手跑一次全盘检索或建索引，就可能把大批云盘文件拉到本地，白白耗掉流量、磁盘和时间；往云盘目录写出的临时文件还会被自动上传同步。须知这条规则只约束模型行为，真正的文件访问权限仍由操作系统把关。

## 2. 搜索纪律：内置 find/grep 即 FFF

本机将 pi-fff 设在 `override` 模式（见 [03-进阶阶段.md](03-进阶阶段.md)）：内置 `find` / `grep` 的名字和参数不变，底层已经换成了 FFF，自带预索引、frecency 排序、模糊匹配与 git 感知。既然内置工具足够好用，指令就要求优先走它们，其余几条补齐 bash 侧的用法与盲区：

- **优先内置工具**：找路径用内置 `find`，搜内容用内置 `grep`，优先于 shell 命令。
- **bash 侧优先 fd / rg**：确需在 shell 中检索时，路径用 `fd`，内容用 `rg`。二者语法与传统 `find` / `grep` 不同，应按各自规则组织参数，切忌硬套旧写法；拿不准就先查 `fd --help` / `rg --help`。
- **警惕默认过滤**：`fd` / `rg` 默认会静默跳过隐藏文件和被忽略文件（`rg` 还会跳过二进制内容）。结果意外为空时，先怀疑被过滤，再下“目标不存在”的结论。
- **隐藏路径盲区**：工作目录不在 git 仓库内时，FFF 索引会跳过隐藏条目，导致内置工具看不到 `~/.pi` 这类配置目录。遇到这类路径直接改走 bash，以该隐藏目录为起点搜索。

## 3. 子代理委托策略

这是整份文件的核心，与 [`config/agents/pico.md`](../config/agents/pico.md) 配套生效（`pico` 的设计见 [06-pico子代理.md](06-pico子代理.md)）。

- **默认自己做。** 每次委托都有固定成本：子代理冷启动、重新读文件，加上主模型写任务书与验收结果，全程至少耗时一分钟。如果主模型此时无事可做，这整段时间都会直接变成用户的干等。开篇先把这笔账挑明，能防止模型把“便宜”误当成“免费”。
- **同时满足三个条件才委托：** 任务规模够大（约 10 次以上工具调用，或原始输出远超最终摘要）；能一次性写清完整任务书；委托期间主会话有别的工作可推进，或者原始输出会迅速塞满主上下文。“约 10 次”属于经验阈值，可随 `pico` 实测耗时调整。
- **留在主会话完成的活：** 几步工具调用就能收尾的任务（包括 search → read → edit 这类短链条）、单次查找、小改动与小修补、架构决策与未说清的偏好、破坏性操作。云盘排除规则已写入 `pico` 正文，此处不再重复。
- **适合委托的活：** 仓库级摸底调研、大改动里的独立实现切片、模块测试编写、只关心结果的长耗时测试与构建、多源联网调研。
- **任务书必须自包含。** 子代理只看得到 prompt，看不到对话历史与全局 AGENTS.md，因此每次派发都要写清目标、精确文件路径、预期行为、约束边界和验证步骤。
- **报告落盘。** 调研类任务为 `pico` 指定唯一 slug，全文写进磁盘，主会话只收摘要。这是压低主模型 token 消耗的关键，直接对应 `pico.md` 里的“大报告写盘”。
- **编排纪律。** 确定外包就尽早派出；主会话手头还有事就放后台，只能干等则用前台；多个并行子任务在同一轮集中发出。并行改动必须按文件切分边界，避免多人改同一文件；子代理交差后先核对实际改动再汇报。若子代理因缺信息或超范围中途停手，由主会话补齐决策并接手，不再原样重派。

这一块的规则迁移成本最低：哪怕换用其他模型或其他 AI 编码工具，“何时委托、如何写委托书”这套准则依然成立。
