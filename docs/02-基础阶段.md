# 基础阶段：联网与命名

本阶段补 pi 最底层的两个缺口：联网和会话管理（定位见 [01-理念与路线.md](01-理念与路线.md)）。两个插件各管一件事，配置项都很少。

本页内容：**pi-web-access**（联网能力）· **pi-autoname**（会话命名）

## 前置：装 pi、配模型

```bash
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
pi --version   # 验证

pi
/login <供应商名>   # 如 /login deepseek，按提示粘贴 API key
```

凭证保存在 `~/.pi/agent/auth.json`。供应商与模型清单见 [07-models.md](07-models.md)。

## pi-web-access —— 联网能力

> 商店：[pi.dev/packages/pi-web-access](https://pi.dev/packages/pi-web-access) · 仓库：[nicobailon/pi-web-access](https://github.com/nicobailon/pi-web-access)

pi 本体不能联网。pi-web-access 补上一整套联网工具：

- `web_search`：联网搜索，后端可选 34 个提供方（OpenAI、xAI 等）；
- `fetch_content`：抓网页、PDF、视频内容，拉取 GitHub 仓库；
- `source_check`：带引用的事实查证；
- `get_search_content`：取回之前存下的搜索内容。

抓取请求默认经过 SSRF 防护。后面的查证、读网页、查外部资料，都建立在这套工具之上。

联网工具何时挂载由 `toolActivation` 决定，默认 `auto`：

- 会话模型支持中途加工具时，新会话只先挂一个 `web_enable`，模型调用它之后联网工具才出现。激活时不重发会话，前缀缓存保持有效。
- 模型不支持中途加工具时，联网工具从第一条请求起就全部挂上。

`dynamic` 总是先挂 `web_enable`，`eager` 始终直接挂全套。动态激活需要 Pi 0.86.0 及以上；恢复的会话沿用当时记录的工具集。

安装：

```bash
pi install npm:pi-web-access@0.34.0
```

配置文件是 `~/.pi/agent/web-search.json`（不存在时回退到旧路径 `~/.pi/web-search.json`）。所有字段都可选，不写就用内置默认值。

**我的配置**（[`config/web-search.json`](../config/web-search.json)）：

```json
{
  "provider": ["openai"],
  "openaiSearchModel": "gpt-6-astra",
  "xaiSearchModel": "grok-4.7",
  "xaiSearchTools": ["x_search"],
  "workflow": "none",
  "toolActivation": "eager",
  "ssrf": {
    "allowRanges": ["198.18.0.0/15"]
  }
}
```

逐项说明：

- `provider: ["openai"]`：只用 OpenAI 搜索源，复用已有订阅。写成数组会走多源聚合逻辑，这里只列了一个；想要按顺序回退，改用 `searchRouting.providers`。
- `xaiSearchTools: ["x_search"]`：保留 xAI 的 X 搜索设置，显式选择 `provider: "xai"` 时生效。
- `openaiSearchModel: gpt-6-astra`：固定 OpenAI 侧的搜索模型。id 原样发给解析出的 OpenAI 鉴权（默认优先用 openai-codex 登录态），网关专属的模型 id 也可以填。
- `xaiSearchModel: grok-4.7`：显式选择 xAI 时使用的搜索模型。
- `workflow: none`：关闭结果总结，直接返回搜索原文。
- `toolActivation: eager`：联网工具从第一条请求起全部挂上，省掉 `web_enable` 这一步。代价是工具定义常驻工具列表，好处是随时可用。
- `ssrf.allowRanges` 里的 `198.18.0.0/15`：放行 Surge 的 fake-IP 地址池。本机走系统代理时，抓取请求会解析到这个网段，不放行就会被 SSRF 防护拦下。

### 常用参数

| 参数 | 作用 |
|------|------|
| `provider` | 默认搜索源：字符串钉死单源，数组并发聚合多源，不写走内置回退链 |
| `toolActivation` | 联网工具的挂载方式：`auto` 按模型自行选择，`dynamic` 总是先挂 `web_enable`，`eager` 从不使用它 |
| `workflow` | 搜索结果的处理方式：`summary-review` 开浏览器策展界面，`auto-summary` 自动生成摘要，`none` 直接流式返回 |
| `ssrf.allowRanges` | 豁免 SSRF 防护的 CIDR 列表，挂 fake-IP 代理时必须放行 |
| `openaiSearchModel` | OpenAI 搜索使用的模型 |
| `xaiSearchModel` | xAI 搜索使用的模型 |
| `xaiSearchTools` | xAI 使用的搜索工具列表 |

### 参数详解

以下按本机安装的源码和 README 核对。所有字段都可选；涉及工具和命令注册的开关（`toolActivation`、`tools.*`、`commands.*`、`webSearch.enabled`、`toolNames`、`shortcuts`）改完要重启 pi 才生效。

#### 选择搜索源

`provider`（旧名 `searchProvider`，两者等价）决定 `web_search` 调用没指定 `provider`、或指定为 `auto` 时用哪个源：

| 写法 | 效果 |
|------|------|
| 不写，或 `"auto"` | 走内置回退链：按下面的顺序逐个尝试**已经配好、可用**的源，第一个成功就停，前面失败才试下一个。顺序是 SearXNG（配了地址才参与）→ OpenAI（当前会话模型是 OpenAI 订阅登录时排到这里）→ Exa（不配 key 也能用）→ OpenAI → Brave → Parallel → TinyFish → Search1API → Searchinfinity → Querit → Tavily → Firecrawl → Jina → SERPdive → Kagi → Bocha → Ollama → Perplexity → Gemini。下表中带 * 的源永远不会进入这条链 |
| `"all"` | 把同一个查询**同时**发给所有可用的不带 * 的源，各家结果分段合并返回；一家失败不影响其他家。最全，也最费额度 |
| 单个名字，如 `"openai"` | 只用这一个源；它失败就直接报错，不回退 |
| 名字数组，如 `["brave", "exa"]` | 只在列出的几家之间同时搜索并合并（合并方式同 `all`）；数组里不能写 `auto` 或 `all` |

设置了 `provider` 时，下面的 `searchRouting` 不生效。

各个源（带 * 的只能显式指定：写进 `provider`、单次调用的 `provider` 参数或 `searchRouting.providers`，`auto` 和 `all` 都不会动用它们，避免悄悄花钱或消耗套餐额度）：

| 提供方 | 鉴权与费用 | 说明 |
|--------|-----------|------|
| `openai` | 复用 Pi 里的 `openai-codex`/`openai` 登录态；都没有时用 `openaiApiKey` | 调 OpenAI Responses API 的 web_search 工具，模型检索后给出带引用的回答。可用 `openaiResponsesUrl` 指向兼容网关 |
| `exa` | 不配 key 走 Exa 托管 MCP，免费；配 `exaApiKey` 走官方 API | 零配置也能用，所以是 `auto` 链里的保底 |
| `brave` | `braveApiKey`，按 Brave 套餐计费 | Brave 自有索引；多个搜索同时发起时会按 Brave 返回的限速排队 |
| `parallel` | `parallelApiKey` | Parallel 公司的搜索 REST API（面向 AI agent 的检索） |
| `parallel-mcp` * | 免 key；配 `parallelApiKey` 可提高限额 | Parallel 的 MCP 通道 |
| `tinyfish` | `tinyfishApiKey`；目前不扣积分，免费档每分钟 30 次搜索 | `includeContent` 时用 TinyFish Fetch 抓全文 |
| `search1api` | `search1apiApiKey`，按积分：一次搜索 1 积分，`includeContent` 时每抓一页再加 1 积分 | — |
| `searchinfinity` | `searchinfinityApiKey`，每月有免费额度，限 5 QPS | BytePlus Searchinfinity，即火山引擎豆包搜索的国际版 |
| `querit` | `queritApiKey` | Search 和 Contents（抓全文）是两个独立订阅，只开了 Search 时 `includeContent` 会 403 |
| `tavily` | `tavilyApiKey` | 面向 AI 的搜索 API；可设 `TAVILY_API_KEY_1` 到 `_20` 组成 key 池，额度耗尽自动换下一个 |
| `you` * | `youApiKey`，按 You.com API 积分计费 | You.com Web Search API |
| `firecrawl` | 配 `firecrawlBaseUrl`（可自托管），托管版另需 `firecrawlApiKey` | 同时作为 `fetch_content` 的提取回退 |
| `jina` | `jinaApiKey` | 不带 `includeContent` 时只返回搜索摘要；带上则抓取全文，耗时更长、耗 Jina token 更多 |
| `serpdive` | `serpdiveApiKey` | `serpdiveModel` 决定抓取深度：`krill`（默认，免费，返回提取的正文）、`mako`（1 积分，加关键句和合成答案）、`moby`（1.5 积分，全文加带引用答案）；写错值按 `krill` 处理 |
| `kagi` | `kagiApiKey`，付费 | Kagi 搜索；同时提供 Kagi Extract 抓取回退 |
| `bocha` | `bochaApiKey` | 博查搜索 |
| `ollama` | `ollamaApiKey`（Ollama Cloud 账号 key） | Ollama 云端搜索，不需要本地 daemon；单次最多 10 条 |
| `anysearch` * | 可匿名，`anysearchApiKey` 可选 | 只发送查询词和条数，时间、域名过滤不生效 |
| `xai` * | 优先用 Pi 里的 xAI 订阅登录态（SuperGrok/X Premium），没有才用 `xaiApiKey` | 搜索在 Grok 推理内部完成，一次提问常触发十几次工具调用，消耗的是聊天额度；工具范围见 `xaiSearchTools` |
| `mistral` * | `mistralApiKey` | Mistral Conversations 的 web_search 工具；`mistralSearchTool` 可改为付费的 `web_search_premium` |
| `brightdata` * | `brightdataApiKey` + `brightdataSerpZone`（必须是 `serp` 类型的 zone），按请求计费 | 付费 Google SERP 代理，查询经过 Bright Data 网络 |
| `serpbase` * / `serpapi` * / `serper` * / `serply` * | 各自的 API key，按次扣费 | 都是付费的 Google SERP API |
| `valyu` * | `valyuApiKey` | 面向研究的搜索 API |
| `xcrawl` * | `xcrawlApiKey` | 只发送查询词，域名过滤在本地做 |
| `searxng` | `searxngBaseUrl` 指向自托管实例 | 自托管元搜索，查询不离开自己的设施；配了就是 `auto` 链的第一站。可用 `searxngHeaders` 加反代鉴权头 |
| `duckduckgo` * | 免 key | 抓 DuckDuckGo 的 HTML 结果页；时间过滤不保证生效 |
| `perplexity` | `perplexityApiKey` | 客户端限速每分钟 10 次 |
| `gemini` | `geminiApiKey`（API grounded search），或浏览器 cookie（Gemini Web，需开 `allowBrowserCookies`） | 只有 cookie 时不会被 `all` 选中，要显式指定 |
| `kimi` * | 先 `/login kimi-coding`，用 Kimi Code Plan 套餐额度 | 不支持时间过滤 |
| `baizhi` * | `baizhiApiKey`，可能扣积分 | 百智云的 MCP 搜索 |
| `zai` * | `zaiApiKey`（GLM Coding Plan 的 key），用套餐额度 | 国内 bigmodel.cn 的 key 要同时设 `zaiEndpoint: "china"`，默认 `global` 走 api.z.ai；域名过滤只支持一个包含域名 |

所有 `*ApiKey` 字段支持三种写法：字面量；`$NAME` 或 `${NAME}` 读环境变量；`!命令` 在每次请求时运行命令取值（如 1Password CLI）。纯大写字符串会被当成字面量，读环境变量必须带 `$`。

#### 路由与回退

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `searchRouting.providers` | 数组，未设置 | 自定义的有序回退链：先试第一个，失败且失败类型在 `fallbackOn` 里才试下一个。和 `auto` 的区别是顺序由你定，且可以放带 * 的源；不能写 `all`。只在没设 `provider` 时生效 |
| `searchRouting.fallbackOn` | 数组，用 `searchRouting` 时必填 | 哪些失败允许继续往下试：<br>`transient`：服务端临时故障（5xx、408、425）<br>`quota`：限流或额度耗尽（402、429）<br>`network`：连不上、超时、DNS 失败<br>`invalid-response`：请求成功但返回内容解析不出结果<br>`unsupported`：OpenAI 端点或模型不支持 web_search 工具<br>不在列表里的失败直接报错停下；鉴权失败（401/403）和请求参数错误无法列入，总是直接报错 |
| `searchRouting.useCurrentModel` | bool，false | `true`：自动搜索时先用当前会话的 OpenAI GPT 模型自带的 Hosted Search（沿用它的端点、凭据和请求头），失败再走 `providers`<br>`false`：不这样做 |
| `fetchRouting.providers` | 数组，默认内置顺序 | `fetch_content` 抓网页时依次尝试的提取器：`http`（本地直连加 Readability 提取正文）、`firecrawl`、`crawl4ai`、`jina`、`tinyfish`、`search1api`、`querit`、`kagi`、`ollama`、`parallel`、`parallel-mcp`、`brightdata`、`gemini`。不写时先本地提取，失败或只拿到 cookie 提示页才往后试已配置的提取器 |
| `fetchRouting.allowRemoteHostedProviders` | bool，false | `false`：抓远程网页时只用本地抓取和自托管的 Firecrawl/Crawl4AI，第三方托管提取器（Jina Reader、TinyFish、Kagi、Parallel、Gemini 等）不参与<br>`true`：允许它们兜底，JS 重的页面、被 Cloudflare 拦的页面更容易抓到；代价是目标 URL 会交给第三方，对方发生的跳转不受本地 SSRF 检查 |

#### 结果处理（工作流与策展页）

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `workflow` | `none` / `summary-review` / `auto-summary`，默认 `none` | 搜索结果怎么交给模型：<br>`none`：不总结，直接返回有长度上限的原始结果，完整内容存起来，模型可用 `get_search_content` 翻页取回；不开浏览器，最快<br>`summary-review`：在浏览器打开策展页，列出所有结果，摘要模型先起草总结，你勾选结果、修改或批准后才发回模型；超时自动提交<br>`auto-summary`：不开浏览器，由 `summaryModel` 直接写总结返回<br>模型单次调用可以用 `workflow` 参数覆盖；会话里 `/curator` 切换并写回配置文件 |
| `curatorTimeoutSeconds` | number，20，最大 600 | 策展页无操作多少秒后自动提交（有已批准的草稿就用它，没有就用不调模型的确定性摘要）；开启 `curatorRemote` 后默认值变为 60 |
| `curatorRemote` | 未配置 | 策展页的本地服务器对谁开放：<br>不写或 `false`：只监听 127.0.0.1，只有本机能打开<br>`true`：监听所有网卡（0.0.0.0），链接里用本机主机名<br>`{host, bind}`：`host` 只改打印出的链接主机名，`bind` 才决定实际监听哪个地址，建议绑到单个私网地址（如 Tailscale IP）<br>远程访问走明文 HTTP，只靠链接里的 token 防护 |
| `autoOpenBrowser` | bool，本地默认 true，远程默认 false | `true`：需要策展时自动打开浏览器（或 Glimpse 窗口）<br>`false`：只在输出里打印链接，自己打开。Docker、WSL、SSH 环境下设 false |
| `shortcuts.curate` | string，`ctrl+shift+s` | 有搜索在等策展时，按它打开最近那次的策展页 |
| `shortcuts.activity` | string，`ctrl+shift+w` | 开关联网活动监视器，实时显示每个请求的状态码和耗时 |

#### 模型

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `openaiSearchModel` | string，自动选 | OpenAI 搜索用的模型 id。不写时自动挑最新的 terra 档模型，其次最新的 `gpt-N`/`gpt-N.N`；写了就原样发送，网关专属的 id 也可以 |
| `openaiSearchProviders` | 数组，`["openai-codex", "openai"]` | OpenAI 搜索按此顺序从 Pi 的登录态找凭据，没登录的跳过；写 `[]` 则完全不用 Pi 登录态，改用 `openaiApiKey`/`OPENAI_API_KEY` 计费。有多个 Codex 账号时可用它指定 |
| `openaiResponsesUrl` | string，OpenAI 官方地址 | 把 OpenAI 搜索指向支持 Responses API 和 web_search 工具的第三方网关 |
| `xaiSearchModel` | string，自动选 | xAI 搜索模型；不写时按内置候选表取第一个 Pi 认识的 id |
| `xaiSearchTools` | 数组，`["web_search"]` | 允许 Grok 用哪些搜索工具：<br>`["web_search"]`：只搜网页<br>`["x_search"]`：只搜 X（推特）<br>`["web_search", "x_search"]`：两者都给，由 Grok 自己选<br>X 搜索可能单独计费；只在使用 `xai` 源时生效 |
| `searchModel` | string，`gemini-3.6-flash` | Gemini API 搜索用的模型，不影响视频和网页提取 |
| `summaryModel` | string，按内置候选表挑 | `summary-review`/`auto-summary` 起草总结的模型，写 `provider/model-id`，可加思考后缀如 `:low`。不写时依次尝试 claude-haiku-4-5、gpt-5.6-luna 等内置候选；受 pi `enabledModels` 白名单限制，白名单里没有可用模型时退回确定性摘要 |
| `summaryGenerationDeadlineMs` | number，30000，最大 600000 | 单次起草总结的时限（毫秒），超时视为失败 |
| `youtube.preferredModel` / `video.preferredModel` | string | 理解 YouTube 视频和本地视频文件用的 Gemini 模型 |

#### 抓取内容

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `fetch.defaultMode` | `readable` / `raw` / `answer`，默认 `readable` | `fetch_content` 不指定 `mode` 时用哪种：<br>`readable`：提取网页正文转成 Markdown，失败会走提取回退链<br>`raw`：原样返回 HTTP 响应文本（JSON、源码、接口返回），不提取、不回退，非 2xx 也返回<br>`answer`：抓取后让模型针对调用里的 `prompt` 基于页面内容作答，只把答案返回，节省上下文 |
| `fetch.allowedModes` | 数组，三种全开 | 模型能用哪些模式；列表外的模式会被直接拒绝。`defaultMode` 必须在列表里 |
| `fetch.answerProvider` / `fetch.answerModel` | 成对设置，未设置 | `answer` 模式默认用的模型；不设则用当前会话模型。设了会把网页内容发给这个模型，注意隐私和费用 |
| `fetch.timeout` | number（秒），30 | 本地直连和 Jina Reader 的超时；其他托管提取器有各自的时限 |
| `maxInlineContentChars` | number，30000（1000–200000） | `fetch_content` 一次直接返回给模型的字符上限，也是 `get_search_content` 每页的默认和最大长度；超出部分存着，可翻页取回 |
| `githubClone.enabled` | bool，true | `true`：GitHub 仓库链接直接 clone 到本地，模型拿到真实文件和本地路径<br>`false`：不做 GitHub 特殊处理，按普通网页抓取 |
| `githubClone.maxRepoSizeMB` | number，350 | 超过这个大小的仓库改用 API 轻量浏览，不 clone；单次调用 `forceClone: true` 可强制 |
| `githubClone.cloneTimeoutSeconds` / `githubClone.clonePath` | 30 / 临时目录 | clone 超时与存放目录；会话切换时清空 |
| `githubPrIssue.enabled` | bool，true | `true`：PR/issue 链接用 `gh` 渲染成一份结构化文档（状态、评审、检查、评论）<br>`false`：按普通网页抓取 |
| `pdf.enabled` | bool，true | 是否处理 PDF；PDF 转成 Markdown 存到临时目录，模型按需 `read` |
| `pdf.provider` | `auto` / `datalab` / `gemini` / `unpdf`，默认 `auto` | PDF 转换引擎：<br>`datalab`：Datalab 托管转换，保留表格和多栏版式，需 key、按页计费<br>`gemini`：Gemini 视觉模型，擅长扫描件，需 key<br>`unpdf`：本地纯文本提取，免费离线，无版式无 OCR<br>`auto`：有 Datalab key 先用它，再 Gemini，最后本地 |
| `pdf.maxSizeMB` / `pdf.maxPages` | 20（最大 50）/ 100 | PDF 大小上限与只处理前多少页 |
| `video.enabled` / `video.maxSizeMB` | true / 50 | 本地视频分析开关与上传 Gemini 的大小上限 |
| `youtube.enabled` | bool，true | 是否用 Gemini 理解 YouTube 视频 |
| `image.enabled` | bool，true | `false` 时禁止直接抓图片、禁止视频抽帧和缩略图 |

#### 网络、安全与鉴权

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `ssrf.allowRanges` | 数组，空 | SSRF 防护默认拦截所有内网和保留地址。Surge、Clash 这类 TUN + fake-IP 代理会把公网域名解析成保留网段（如 `198.18.0.0/15`），不放行就什么都抓不了。只填代理 fake-IP 池那一段，`0.0.0.0/0` 这类全放行会被拒绝 |
| `ssrf.trustEnvProxy` | bool，false | `true`：只有代理能解析域名的网络（如某些沙箱）里，对走代理的主机名跳过本地 DNS 预检；localhost、字面内网 IP 和 `NO_PROXY` 仍然拦截。它不负责配置代理本身 |
| `proxy` | string，未设置 | 让本插件的所有请求改用 `curl` 经此 HTTP 代理发出（如 `"http://127.0.0.1:6152"`），解决 Node fetch 不认 `HTTP(S)_PROXY` 的问题；只影响本插件，不影响模型 API 请求。单次调用传 `proxy: ""` 可强制直连 |
| `fetchContent.domainPolicy` | `{allow: [], deny: []}`，未设置 | `fetch_content` 的域名黑白名单，每个域名同时匹配其子域名；两边都命中时 `deny` 优先。设了 `allow` 就只能抓名单内的站 |
| `webSearch.allowedProviders` | 数组，未设置（全部允许） | 搜索源白名单：名单外的源一律拒绝，`auto`、`all`、`source_check` 和策展页也只在名单内选。不会让带 * 的源变成自动可选 |
| `authFetch` | 对象，未设置 | 给 `fetch_content` 用的浏览器 cookie 登录配置，如 `{"work": ["docs.company.com"]}`，模型调用时传 `auth: "work"` 即带上本机浏览器的登录态抓取。只允许 HTTPS、只发往列出的主机，带 cookie 的内容不会交给托管提取器 |
| `allowBrowserCookies` | bool，false | `true`：允许读取本机 Chromium 系浏览器的 cookie（Gemini Web 和 `authFetch` 需要），macOS 上可能弹钥匙串授权<br>`false`：完全不碰浏览器数据 |
| `browserCookies` | `{browser, profile}`，未设置 | 指定读哪个浏览器和 profile 的 cookie，`browser` 可选 helium/chrome/brave/arc/chromium/edge；不写则自动扫描。旧的顶层 `chromeProfile` 已被拒绝，改写到 `browserCookies.profile` |

#### 工具与命令开关

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `toolActivation` | `auto` / `dynamic` / `eager`，默认 `auto` | 联网工具什么时候出现在模型的工具列表里：<br>`dynamic`：新会话只挂一个很小的 `web_enable`，模型需要联网时先调用它，下一次请求起完整工具才出现。省工具描述的上下文；但对不支持中途加工具的模型，激活那一下 pi 要重发整段对话，缓存会失效一次<br>`eager`：从第一条请求起就挂全套工具，没有激活步骤，工具描述常驻上下文；也适合不太会主动调 `web_enable` 的模型<br>`auto`：新会话开始时按当前模型自动选，支持中途加工具就用 `dynamic`，否则用 `eager`；之后换模型不再改变<br>恢复的旧会话沿用当时的工具集 |
| `tools.webSearch` / `tools.sourceCheck` / `tools.fetchContent` / `tools.getSearchContent` 的 `.enabled` | bool，true | 单独关掉某个工具（不注册，模型看不到） |
| `webSearch.enabled` | bool，true | 旧的简写：`false` 同时关掉 `web_search` 和 `source_check`，抓取工具保留；`tools.*` 的设置优先于它 |
| `commands.websearch` / `curator` / `search` / `google-account` 的 `.enabled` | bool，true | 单独关掉 `/websearch`、`/curator`、`/search`、`/google-account` 命令 |
| `toolNames` | 对象，默认原名 | 给四个工具改名（键为 `webSearch`、`sourceCheck`、`fetchContent`、`getSearchContent`），用于和其他扩展的同名工具冲突时；行为不变 |

## pi-autoname —— 会话命名

> 商店：[pi.dev/packages/pi-autoname](https://pi.dev/packages/pi-autoname) · 仓库：[ssdiwu/pi-autoname](https://github.com/ssdiwu/pi-autoname)

pi 的会话名一般取首条消息或文件名，看名字很难想起会话内容，翻找旧会话时不好定位；每次手动起名又太麻烦。

pi-autoname 在首轮对话结束后调用一次 LLM，起一个“修 auth 模块竞态”这样能看懂的名字。之后它定期在后台评估，话题明显变了就更新名字。

安装：

```bash
pi install npm:pi-autoname@0.6.8
```

配置文件是 `~/.pi/agent/pi-autoname.json`，首次使用时自动生成，所有字段都可选。

**我的配置**（[`config/pi-autoname.json`](../config/pi-autoname.json)）：

```json
{
  "enabled": true,
  "model": "deepseek/deepseek-flash",
  "fallbackModels": ["openai-codex/gpt-6-luna"],
  "cooldownMinutes": 20,
  "debug": false,
  "respectManualName": true
}
```

命名用 `deepseek/deepseek-flash`，失败时回退到 `openai-codex/gpt-6-luna`，再失败就用当前会话模型。

最关键的改动是 `respectManualName: true`。默认情况下，手动起的名字只保留一个冷却周期，之后会被自动命名覆盖；开启后，手动名永久保留。`cooldownMinutes` 从 10 调到 20，命名调用次数减半，实际用下来足够。

### 常用参数

| 参数 | 作用 |
|------|------|
| `model` | 命名用的模型；留空则用当前会话模型 |
| `fallbackModels` | 主模型失败时依次尝试的模型 |
| `cooldownMinutes` | 重命名评估间隔 |
| `respectManualName` | 手动 `/name` 过的标题是否永保 |

### 参数详解

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `enabled` | bool，true | `true`：首轮对话结束后自动起名，之后定期评估是否改名<br>`false`：插件完全不调模型，自动命名、定期改名和 `/autoname` 都不再生效 |
| `model` | string，空 | 起名用的模型，写 `provider/model-id`；留空就用当前会话模型。起名只需要很短的输入输出，填便宜快速的模型即可 |
| `fallbackModels` | 字符串数组，`[]` | `model` 失败时按顺序尝试的备选模型。完整的回退顺序是 `model` → `fallbackModels` 逐个 → 当前会话模型 → 不调 AI、从你的消息里提取文字当名字；所有 AI 尝试共用 30 秒预算 |
| `cooldownMinutes` | number，10 | 两次“是否需要改名”评估之间至少间隔多少分钟。每次评估都要调一次模型：调大则改名更迟钝、调用更少，调小则名字更快跟上话题变化。评估时名字仍然贴切就保持原样，不会无谓改动 |
| `respectManualName` | bool，false | 你用 pi 自带的 `/name` 手动改名后怎么处理：<br>`false`：手动名只保护一个 `cooldownMinutes` 周期，之后话题变了仍可能被自动改掉<br>`true`：手动名一直保留，除非你主动运行 `/autoname` |
| `debug` | bool，false | `true`：往 stderr 打印 `[pi-autoname 时间]` 开头的调试日志，包括用了哪个模型、失败原因、改名前后的名字，排查“为什么没改名”时打开 |

起名前插件会把发给模型的对话片段里的 API key、token、私钥、`*_PASSWORD=` 之类内容打码。名字的语言跟随你消息里的主要语言。
