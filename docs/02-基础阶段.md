# 基础阶段：联网与命名

本阶段补 pi 最底层的两个缺口：联网和会话管理（定位见 [01-理念与路线.md](01-理念与路线.md)）。两个插件各管一件事，配置项都很少。

本页内容：**pi-web-access**（联网能力）· **pi-autoname**（会话命名）

## 前置：装 pi、配模型

```bash
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
pi --version   # 验证

pi
/login <供应商名>   # 如 /login deepseek，按提示粘贴 API key
```

凭证保存在 `~/.pi/agent/auth.json`。供应商与模型清单见 [07-models.md](07-models.md)。

## pi-web-access —— 联网能力

> 商店：[pi.dev/packages/pi-web-access](https://pi.dev/packages/pi-web-access) · 仓库：[nicobailon/pi-web-access](https://github.com/nicobailon/pi-web-access)

pi 本体不能联网。pi-web-access 补上一整套联网工具：

- `web_search`：联网搜索，后端可选 34 个提供方（OpenAI、xAI 等）；
- `fetch_content`：抓网页、PDF、视频内容，拉取 GitHub 仓库；
- `source_check`：带引用的事实查证；
- `get_search_content`：取回之前存下的搜索内容。

抓取请求默认经过 SSRF 防护。后面的查证、读网页、查外部资料，都建立在这套工具之上。

联网工具何时挂载由 `toolActivation` 决定，默认 `auto`：

- 会话模型支持中途加工具时，新会话只先挂一个 `web_enable`，模型调用它之后联网工具才出现。激活时不重发会话，前缀缓存保持有效。
- 模型不支持中途加工具时，联网工具从第一条请求起就全部挂上。

`dynamic` 总是先挂 `web_enable`，`eager` 始终直接挂全套。动态激活需要 Pi 0.86.0 及以上；恢复的会话沿用当时记录的工具集。

安装：

```bash
pi install npm:pi-web-access@0.34.0
```

配置文件是 `~/.pi/agent/web-search.json`（不存在时回退到旧路径 `~/.pi/web-search.json`）。所有字段都可选，不写就用内置默认值。

**我的配置**（[`config/web-search.json`](../config/web-search.json)）：

```json
{
  "provider": ["openai"],
  "openaiSearchModel": "gpt-6-astra",
  "xaiSearchModel": "grok-4.7",
  "xaiSearchTools": ["x_search"],
  "workflow": "none",
  "toolActivation": "eager",
  "ssrf": {
    "allowRanges": ["198.18.0.0/15"]
  }
}
```

逐项说明：

- `provider: ["openai"]`：只用 OpenAI 搜索源，复用已有订阅。写成数组会走多源聚合逻辑，这里只列了一个；想要按顺序回退，改用 `searchRouting.providers`。
- `xaiSearchTools: ["x_search"]`：保留 xAI 的 X 搜索设置，显式选择 `provider: "xai"` 时生效。
- `openaiSearchModel: gpt-6-astra`：固定 OpenAI 侧的搜索模型。id 原样发给解析出的 OpenAI 鉴权（默认优先用 openai-codex 登录态），网关专属的模型 id 也可以填。
- `xaiSearchModel: grok-4.7`：显式选择 xAI 时使用的搜索模型。
- `workflow: none`：关闭结果总结，直接返回搜索原文。
- `toolActivation: eager`：联网工具从第一条请求起全部挂上，省掉 `web_enable` 这一步。代价是工具定义常驻工具列表，好处是随时可用。
- `ssrf.allowRanges` 里的 `198.18.0.0/15`：放行 Surge 的 fake-IP 地址池。本机走系统代理时，抓取请求会解析到这个网段，不放行就会被 SSRF 防护拦下。

### 常用参数

| 参数 | 作用 |
|------|------|
| `provider` | 默认搜索源：字符串钉死单源，数组并发聚合多源，不写走内置回退链 |
| `toolActivation` | 联网工具的挂载方式：`auto` 按模型自行选择，`dynamic` 总是先挂 `web_enable`，`eager` 从不使用它 |
| `workflow` | 搜索结果的处理方式：`summary-review` 开浏览器策展界面，`auto-summary` 自动生成摘要，`none` 直接流式返回 |
| `ssrf.allowRanges` | 豁免 SSRF 防护的 CIDR 列表，挂 fake-IP 代理时必须放行 |
| `openaiSearchModel` | OpenAI 搜索使用的模型 |
| `xaiSearchModel` | xAI 搜索使用的模型 |
| `xaiSearchTools` | xAI 使用的搜索工具列表 |

### 参数详解

提供方。`provider` 可以写 `auto`（默认回退链）、`all`（并发请求所有可用源）、单个提供方，或提供方数组（并发聚合）。带 * 的只能显式指定，`all` 不会选中它们：

| `openai` | 复用 Codex 登录态，可指向兼容网关 |
| `exa` | 免 key 开箱 |
| `brave` | Brave Search API |
| `parallel` | 并行多源 |
| `parallel-mcp` * | Parallel 的 MCP 通道 |
| `tinyfish` | TinyFish 搜索 |
| `search1api` | 按积分计费 |
| `searchinfinity` | 火山引擎，每月免费额度 |
| `querit` | Querit 搜索 |
| `tavily` | 面向 AI 的搜索 API |
| `you` * | You.com Web Search API，按 API 积分计费 |
| `firecrawl` | 可自托管 |
| `jina` | Jina 搜索 |
| `serpdive` | 三档抓取深度 krill/mako/moby |
| `kagi` | 付费优质搜索 |
| `bocha` | Bocha 搜索 |
| `ollama` | 云搜索，免本地 daemon |
| `anysearch` * | AnySearch |

| `mistral` * | Mistral 搜索，API 鉴权 |

路由与回退：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `searchRouting.providers` | array | 显式有序回退链 |
| `searchRouting.fallbackOn` | `transient` / `quota` / `network` / `invalid-response` / `unsupported` | 只对列出的失败类型继续下一个候选 |
| `fetchRouting.providers` | array | 抓取回退链 |
| `fetchRouting.allowRemoteHostedProviders` | bool，false | 是否允许远端托管提供方 |

工作流：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `workflow` | `summary-review` / `auto-summary` / `none` | 搜索结果处理方式，见上；不写默认 `none` |
| `curatorTimeoutSeconds` | number，20 | 策展器超时 |
| `curatorRemote` | bool 或 `{host, bind}`，未配置 | 远程访问策展器；`true` 取主机名并绑 `0.0.0.0`，建议用对象绑单个私网接口；token 走明文 HTTP |
| `autoOpenBrowser` | bool，true | 自动开浏览器；Docker/WSL/SSH 环境需要关 |
| `shortcuts.curate` / `shortcuts.activity` | string | 快捷键 |

模型：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `openaiSearchModel` | string | OpenAI 搜索模型 |
| `xaiSearchModel` | string | xAI 搜索模型 |
| `searchModel` | string，gemini-3.6-flash | Gemini 搜索模型 |
| `summaryModel` | string | 策展摘要模型，受 enabledModels 白名单限制 |
| `summaryGenerationDeadlineMs` | number，30000 | 摘要生成时限 |
| `youtube.preferredModel` / `video.preferredModel` | string | 视频理解模型 |

网络与鉴权：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `ssrf.allowRanges` | array | 豁免 SSRF 防护的 CIDR 列表，只加最窄的 fake-IP 池 |
| `ssrf.trustEnvProxy` | bool，false | 信任环境代理变量 |
| `authFetch` | object | 命名鉴权 profile 映射：`{"<name>": [hosts]}` 或 `{"<name>": {hosts, chromeProfile, redirects, cache}}`，供 `fetch_content` 的 `auth: "<name>"` 使用 |
| `browserCookies` | object | Gemini Web cookie 用的浏览器预设与 profile：`{browser, profile}`，browser 可取 helium/chrome/brave/arc/chromium/edge |
| `allowBrowserCookies` | bool，false | 是否打开 Chromium cookie 提取（Gemini Web 用） |

所有 `*ApiKey` 字段支持三种写法：字面量、`$ENV` 读环境变量、`!命令` 每次取凭据。纯大写字符串会被当字面量，读环境变量必须带 `$` 前缀。顶层 `chromeProfile` 在 0.28.0 已被拒绝，profile 名写进 `browserCookies.profile`。

内容与开关：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `maxInlineContentChars` | number，30000 | 内联内容上限 |
| `githubClone` | object，`{enabled: true, maxRepoSizeMB: 350}` | GitHub 克隆开关与大小上限 |
| `githubPrIssue.enabled` | bool，true | PR/issue 专用视图开关 |
| `pdf` | object，`{enabled: true, maxSizeMB: 20}` | PDF 抓取开关与大小上限 |
| `fetch.defaultMode` / `fetch.allowedModes` | `readable`（默认） / 数组，三种模式全开 | `fetch_content` 的默认模式与可用模式集合 |
| `webSearch.enabled`、`tools.*`、`commands.*` | bool | 功能总开关 |
| `webSearch.allowedProviders` | array | 搜索提供方白名单，未列出的一律拒绝；`auto`、`all`、`source_check` 与策展器只在白名单内选源 |
| `toolActivation` | `auto` / `dynamic` / `eager` | 联网工具的挂载方式；改动后重启 Pi 生效 |
| `fetchContent.domainPolicy` | `{allow:[], deny:[]}` | 主机名黑白名单 |

## pi-autoname —— 会话命名

> 商店：[pi.dev/packages/pi-autoname](https://pi.dev/packages/pi-autoname) · 仓库：[ssdiwu/pi-autoname](https://github.com/ssdiwu/pi-autoname)

pi 的会话名一般取首条消息或文件名，看名字很难想起会话内容，翻找旧会话时不好定位；每次手动起名又太麻烦。

pi-autoname 在首轮对话结束后调用一次 LLM，起一个“修 auth 模块竞态”这样能看懂的名字。之后它定期在后台评估，话题明显变了就更新名字。

安装：

```bash
pi install npm:pi-autoname@0.6.8
```

配置文件是 `~/.pi/agent/pi-autoname.json`，首次使用时自动生成，所有字段都可选。

**我的配置**（[`config/pi-autoname.json`](../config/pi-autoname.json)）：

```json
{
  "enabled": true,
  "model": "deepseek/deepseek-flash",
  "fallbackModels": ["openai-codex/gpt-6-luna"],
  "cooldownMinutes": 20,
  "debug": false,
  "respectManualName": true
}
```

命名用 `deepseek/deepseek-flash`，失败时回退到 `openai-codex/gpt-6-luna`，再失败就用当前会话模型。

最关键的改动是 `respectManualName: true`。默认情况下，手动起的名字只保留一个冷却周期，之后会被自动命名覆盖；开启后，手动名永久保留。`cooldownMinutes` 从 10 调到 20，命名调用次数减半，实际用下来足够。

### 常用参数

| 参数 | 作用 |
|------|------|
| `model` | 命名用的模型；留空则用当前会话模型 |
| `fallbackModels` | 主模型失败时依次尝试的模型 |
| `cooldownMinutes` | 重命名评估间隔 |
| `respectManualName` | 手动 `/name` 过的标题是否永保 |

### 参数详解

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `model` | string，空 | 命名模型；空 = 当前会话模型 |
| `fallbackModels` | array | 失败回退链，全部失败落回会话模型，再败退化为无 AI 的本地文本提取；AI 链共享 30 秒预算 |
| `enabled` | bool，true | 总开关 |
| `cooldownMinutes` | number，10 | 重命名评估间隔 |
| `respectManualName` | bool，false | 手动 `/name` 过的标题永保 |
| `debug` | bool，false | 调试输出 |
