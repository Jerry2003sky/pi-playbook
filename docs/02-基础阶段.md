# 基础阶段：联网与命名

本阶段补 pi 最底层的两个缺口：联网和会话管理（定位见 [01-理念与路线.md](01-理念与路线.md)）。两个插件各管一件事，配置项都很少。

本页内容：**pi-web-access**（联网能力）· **pi-autoname**（会话命名）

## 前置：装 pi、配模型

```bash
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
pi --version   # 验证

pi
/login <供应商名>   # 如 /login deepseek，按提示粘贴 API key
```

凭证保存在 `~/.pi/agent/auth.json`。供应商与模型清单见 [07-models.md](07-models.md)。

## pi-web-access —— 联网能力

> 商店：[pi.dev/packages/pi-web-access](https://pi.dev/packages/pi-web-access) · 仓库：[nicobailon/pi-web-access](https://github.com/nicobailon/pi-web-access)

pi 本体不能联网。pi-web-access 补上一整套联网工具：

- `web_search`：联网搜索，后端可选 34 个提供方（OpenAI、xAI 等）；
- `fetch_content`：抓网页、PDF、视频内容，拉取 GitHub 仓库；
- `source_check`：带引用的事实查证；
- `get_search_content`：取回之前存下的搜索内容。

抓取请求默认经过 SSRF 防护。后面的查证、读网页、查外部资料，都建立在这套工具之上。

联网工具何时挂载由 `toolActivation` 决定，默认 `auto`：

- 会话模型支持中途加工具时，新会话只先挂一个 `web_enable`，模型调用它之后联网工具才出现。激活时不重发会话，前缀缓存保持有效。
- 模型不支持中途加工具时，联网工具从第一条请求起就全部挂上。

`dynamic` 总是先挂 `web_enable`，`eager` 始终直接挂全套。动态激活需要 Pi 0.86.0 及以上；恢复的会话沿用当时记录的工具集。

安装：

```bash
pi install npm:pi-web-access@0.35.0
```

配置文件是 `~/.pi/agent/web-search.json`（不存在时回退到旧路径 `~/.pi/web-search.json`）。所有字段都可选，不写就用内置默认值。

**我的配置**（[`config/web-search.json`](../config/web-search.json)）：

```json
{
  "provider": ["openai"],
  "openaiSearchModel": "gpt-6-astra",
  "xaiSearchModel": "grok-4.7",
  "xaiSearchTools": ["x_search"],
  "workflow": "none",
  "toolActivation": "auto",
  "ssrf": {
    "allowRanges": ["198.18.0.0/15"]
  }
}
```

逐项说明：

- `provider: ["openai"]`：只用 OpenAI 搜索源，复用已有订阅。写成数组会走多源聚合逻辑，这里只列了一个；想要按顺序回退，改用 `searchRouting.providers`。
- `xaiSearchTools: ["x_search"]`：保留 xAI 的 X 搜索设置，显式选择 `provider: "xai"` 时生效。
- `openaiSearchModel: gpt-6-astra`：固定 OpenAI 侧的搜索模型。id 原样发给解析出的 OpenAI 鉴权（默认优先用 openai-codex 登录态），网关专属的模型 id 也可以填。
- `xaiSearchModel: grok-4.7`：显式选择 xAI 时使用的搜索模型。
- `workflow: none`：关闭结果总结，直接返回搜索原文。
- `toolActivation: auto`：即默认值，写出来是为了显式。新会话按当前模型决定：能中途加工具的模型先只挂 `web_enable`，用到联网时再展开；不能的模型从第一条请求起挂全套，避免缓存失效。
- `ssrf.allowRanges` 里的 `198.18.0.0/15`：放行 Surge 的 fake-IP 地址池。本机走系统代理时，抓取请求会解析到这个网段，不放行就会被 SSRF 防护拦下。

### 常用参数

| 参数 | 作用 |
|------|------|
| `provider` | 默认搜索源：字符串钉死单源，数组并发聚合多源，不写走内置回退链 |
| `toolActivation` | 联网工具的挂载方式：`auto` 按模型自行选择，`dynamic` 总是先挂 `web_enable`，`eager` 从不使用它 |
| `workflow` | 搜索结果的处理方式：`summary-review` 开浏览器策展界面，`auto-summary` 自动生成摘要，`none` 直接流式返回 |
| `ssrf.allowRanges` | 豁免 SSRF 防护的 CIDR 列表，挂 fake-IP 代理时必须放行 |
| `openaiSearchModel` | OpenAI 搜索使用的模型 |
| `xaiSearchModel` | xAI 搜索使用的模型 |
| `xaiSearchTools` | xAI 使用的搜索工具列表 |

### 参数详解

以下按 0.35.0 整理。表里“默认”指不写该字段时的行为。工具注册、命令、快捷键和 `toolActivation` 改完要重启 Pi；`workflow` 和 `provider` 在下一次 `web_search` 调用时生效。

#### 选择搜索源

| 参数 | 默认 | 取值与效果 |
|------|------|-----------|
| `provider`（别名 `searchProvider`） | `auto` | `"auto"`：按内置回退链逐个尝试，只用有凭据的源，带 * 的源永远不会被选中。顺序：配置了 SearXNG 就先试它；当前会话模型走 ChatGPT 订阅（`openai-codex`，或用 ChatGPT 登录的 `openai`）时先试 OpenAI，否则先 Exa 再 OpenAI；之后依次是 Brave、Parallel、TinyFish、Search1API、Searchinfinity、Querit、Tavily、Firecrawl、Jina、SERPdive、Kagi、Bocha、Ollama、Perplexity、Gemini API，最后是 Gemini Web（需开 `allowBrowserCookies`）<br>`"all"`：同一查询并发发给所有可用的非 * 源，结果去重合并；单个源失败不影响其他源，全部失败才报错<br>单个名字，如 `"openai"`：只用这一个源，失败直接报错，不回退<br>名字数组，如 `["brave", "exa"]`：列出的源并发聚合，相当于限定范围的 `all`；数组里不能写 `auto` / `all`<br>设置了 `provider` 时 `searchRouting` 不生效。在策展页里切换源会回写这个字段 |
| `searchRouting.providers` | 未设置 | 有序回退链：先试第一个，失败且失败类型在 `fallbackOn` 里才试下一个。不能写 `all`（这里是顺序回退，不是聚合）。带 * 的源可以写进来。只在 `provider` 未设置时生效 |
| `searchRouting.fallbackOn` | 未设置 = 不回退 | 允许继续回退的失败类型，可多选：<br>`transient`：临时性故障（服务端出错等可重试的情况）<br>`quota`：额度用尽或被限流<br>`network`：网络不通<br>`invalid-response`：返回了内容但解析不出结果<br>`unsupported`：该源不支持这次请求（端点返回 404/405/501、要求的域名过滤做不到等）<br>没列出的失败类型直接报错，不再往下试 |
| `searchRouting.useCurrentModel` | `false` | `true`：回退链走到 `openai` 这一步时，如果当前会话模型是官方 OpenAI / Codex 端点上的 GPT，直接用它的 Hosted `web_search`；第三方网关、Azure 等不满足条件时跳到下一项<br>`false`：`openai` 这一步按独立搜索处理，模型由 `openaiSearchModel` 决定 |
| `webSearch.allowedProviders` | 不限制 | 搜索源白名单（非空、不重复）。设置后，显式点名白名单外的源会在发请求前被拒绝；`auto`、`all`、`searchRouting`、`source_check` 和策展页都只在白名单内选源。`provider` 或 `searchRouting.providers` 里出现白名单外的源会被判为配置错误。白名单不会让带 * 的源进入 `auto` / `all`。只管搜索，不管抓取和摘要模型 |
| `openaiSearchProviders` | `["openai-codex", "openai"]` | OpenAI 搜索从哪些 pi 登录态取凭据，按顺序找第一个已登录的。写空数组 `[]` 表示不用登录态，改用 `openaiApiKey` / `OPENAI_API_KEY`（按 API 计费）。有多个 Codex 账号时用它指定走哪个 |
| `openaiResponsesUrl` | `https://api.openai.com/v1/responses` | OpenAI 搜索和 `source_check` 的请求地址，可指向兼容 Responses API 的第三方网关 |

#### 搜索与摘要用的模型

| 参数 | 默认 | 取值与效果 |
|------|------|-----------|
| `openaiSearchModel` | 自动选 | 未设置：依次挑最新的 terra 档模型、最新的 `gpt-N` / `gpt-N.N`、最新的其他 `gpt-<版本>`<br>设置后：id 原样发给解析出的 OpenAI 鉴权，网关专属 id 也能用 |
| `xaiSearchModel` | 自动选 | 未设置：登录态路径按内置候选表取第一个 pi 认识的模型；API key 路径从 `grok-4.5` 起（开了 `x_search` 时用 `grok-4.6`）<br>设置后：固定用这个 id，xAI 下线旧模型时用它救急 |
| `xaiSearchTools` | `["web_search"]` | 只在使用 `xai` 源时生效：<br>`["web_search"]`：只搜网页<br>`["x_search"]`：只搜 X（推特）<br>`["web_search", "x_search"]`：两种工具都交给 Grok，由它自己决定用哪个<br>必须非空且不重复；开 `x_search` 可能产生额外的工具调用费用 |
| `searchModel` | `gemini-3.6-flash` | Gemini API 搜索用的模型，不影响 URL、YouTube、视频解析 |
| `summaryModel` | 自动选 | 策展页和 `auto-summary` 生成摘要的模型，写 `provider/model-id`，可加思考后缀如 `:low`（`off` / `minimal` / `low` / `medium` / `high` / `xhigh` / `max`）。受 settings.json 的 `enabledModels` 限制：白名单里没有可用模型时，不调模型，直接返回按规则拼出的摘要 |
| `summaryInstructions` | 未设置 | 追加到摘要提示词里的要求，按 `- ` 一行一条写，比如“价格、版本号原样保留”。只增不减，内置规则仍然生效 |
| `summaryGenerationDeadlineMs` | `30000` | 单次摘要生成的时限（毫秒），上限 600000 |
| `fetch.answerProvider` + `fetch.answerModel` | 未设置 | `fetch_content` 的 `answer` 模式默认用哪个模型答题，两项必须成对写。未设置时用当前会话模型。注意页面内容会发给这个模型 |
| `youtube.preferredModel` / `video.preferredModel` | `gemini-3.6-flash` | YouTube / 本地视频理解用的模型 |
| `mistralSearchModel` / `mistralSearchTool` | `mistral-small-latest` / `web_search` | 使用 `mistral` 源时的模型和工具；工具只能是 `web_search` 或付费的 `web_search_premium` |

#### 搜索结果的处理：workflow 与策展页

| 参数 | 默认 | 取值与效果 |
|------|------|-----------|
| `workflow` | `none` | `"none"`：搜索原文直接返回给模型，不调摘要模型，也不开浏览器，最快最省<br>`"auto-summary"`：用 `summaryModel` 把结果压成一段带来源的摘要再返回，不开浏览器；每次搜索多一次模型调用，换来更少的上下文占用<br>`"summary-review"`：打开浏览器策展页，先自动生成摘要草稿，你在页面里勾选结果、修改摘要后提交；超时没操作会自动提交<br>单次调用可用 `workflow` 参数覆盖；会话里 `/curator on` / `off` 切换并回写此字段 |
| `curatorTimeoutSeconds` | `20`（开 `curatorRemote` 时为 60） | 策展页无操作多少秒后自动提交，上限 600；页面里也能临时调 |
| `curatorRemote` | 未配置 | 让策展页能从别的机器打开（Pi 跑在远程机、容器里时用）：<br>不写或 `false`：只绑 `127.0.0.1`，链接是 `localhost`<br>`true`：绑 `0.0.0.0`（所有网卡），链接用本机主机名<br>`{"host": "h"}`：链接用 `h`，仍绑 `0.0.0.0`<br>`{"bind": "b"}`：只绑网卡 `b`，链接用本机主机名<br>`{"host": "h", "bind": "b"}`：两者都指定（推荐，绑单个私网网卡）<br>唯一的访问控制是链接里的 token，且走明文 HTTP |
| `autoOpenBrowser` | 本地 `true`，远程 `false` | `true`：需要策展时自动打开 Glimpse 窗口或浏览器<br>`false`：只在终端打印链接，自己去开。Docker / WSL / SSH 环境建议关 |
| `shortcuts.curate` | `ctrl+shift+s` | 打开待审阅的策展页 |
| `shortcuts.activity` | `ctrl+shift+w` | 显示 / 隐藏联网请求活动面板 |

#### 工具挂载与开关

| 参数 | 默认 | 取值与效果 |
|------|------|-----------|
| `toolActivation` | `auto` | `"auto"`：新会话开始时看当前模型能否中途加工具。能，就按 `dynamic` 处理；不能，就按 `eager` 处理。只在新会话开始时判断一次，之后换模型不变<br>`"dynamic"`：新会话只挂一个很小的 `web_enable`，模型调用它后，联网工具在下一次请求出现。不需要联网的会话省掉工具定义的上下文；但对不支持中途加工具的模型，pi 会重发整段对话，那一次请求缓存失效<br>`"eager"`：从第一条请求起挂全套联网工具，不用 `web_enable`。没有缓存失效问题，代价是工具定义常驻上下文；也适合不爱主动调 `web_enable` 的模型<br>需要 Pi 0.86.0 及以上，改完重启；恢复的旧会话沿用当时记录的工具集 |
| `tools.webSearch.enabled` / `tools.sourceCheck.enabled` / `tools.fetchContent.enabled` / `tools.getSearchContent.enabled` | `true` | `false`：不注册对应工具，模型看不到它 |
| `webSearch.enabled` | `true` | 旧写法。`false` 同时注销 `web_search` 和 `source_check`，抓取工具不受影响；与 `tools.*` 冲突时以 `tools.*` 为准 |
| `commands.websearch` / `curator` / `search` / `google-account` 的 `.enabled` | `true` | `false`：不注册对应的斜杠命令 |
| `toolNames.webSearch` 等 | 原名 | 给工具改公开名字（比如和其他扩展撞名时），行为不变 |

#### 抓取（fetch_content）

| 参数 | 默认 | 取值与效果 |
|------|------|-----------|
| `fetch.defaultMode` | `readable` | 调用时没写 `mode` 用哪种：<br>`"readable"`：提取正文转成 Markdown；GitHub、YouTube、PDF 走专门处理，提取失败按兜底链重试<br>`"raw"`：原样返回 HTTP 响应的文本，非 2xx 也返回，只走直连 HTTP，不做正文提取、不用任何兜底服务。适合抓 API、JSON、源码<br>`"answer"`：抓取后让模型根据页面回答 `prompt` 里的问题，只把答案返回给主模型。多一次模型调用，页面内容会发给答题模型 |
| `fetch.allowedModes` | 三种全开 | 允许使用的模式列表，必须包含 `defaultMode`。不在列表里的模式直接报错，不会悄悄换成别的模式 |
| `fetch.timeout` | `30`（秒） | 直连 HTTP 和 Jina Reader 的超时；其他兜底服务各有自己的时限 |
| `fetchRouting.providers` | 内置顺序 | 正文提取失败时的兜底链，可选 `http`、`firecrawl`、`crawl4ai`、`jina`、`tinyfish`、`search1api`、`querit`、`kagi`、`ollama`、`parallel`、`parallel-mcp`、`brightdata`、`gemini`。`parallel-mcp` 默认不在链里，要显式写 |
| `fetchRouting.allowRemoteHostedProviders` | `false` | `false`：兜底只用直连和自托管的 Firecrawl / Crawl4AI，目标 URL 不交给第三方<br>`true`：允许 Jina、TinyFish、Kagi、Parallel、Bright Data、Gemini 等托管服务替你抓取。能过更多反爬，但这些服务会看到目标 URL，部分按次计费 |
| `fetchContent.domainPolicy` | 关闭 | `{"allow": [...], "deny": [...]}`，按主机名限制能抓的地址，写一个域名同时匹配其子域；两边都命中时 `deny` 优先。只是额外限制，SSRF 防护照常生效 |
| `maxInlineContentChars` | `30000` | `fetch_content` 一次直接返回给模型的最大字符数（1000–200000）。超出的部分存起来，模型用 `get_search_content` 分段取 |
| `githubClone.enabled` | `true` | `true`：GitHub 仓库链接会克隆到本地，返回文件内容和本地路径<br>`false`：不克隆，当普通网页抓 |
| `githubClone.maxRepoSizeMB` | `350` | 超过这个大小不克隆；单次调用可用 `forceClone` 强制 |
| `githubClone.cloneTimeoutSeconds` / `githubClone.clonePath` | `30` / `/tmp/pi-github-repos` | 克隆超时和存放目录 |
| `githubPrIssue.enabled` | `true` | `true`：PR / issue 链接走 GitHub 专用视图（正文、评论、讨论串）<br>`false`：当普通网页抓 |
| `pdf.enabled` | `true` | `false`：不处理 PDF |
| `pdf.provider` | `auto` | `"auto"`：有 Datalab key 先用 Datalab，再试 Gemini（有 key 时），最后用本地 `unpdf`<br>`"datalab"`：云端版面解析，保留表格和多栏顺序，按页计费<br>`"gemini"`：用 Gemini 视觉模型转写，扫描件效果好，偶尔会漏段<br>`"unpdf"`：本地提取纯文本，免费离线，没有表格和 OCR<br>指定 `datalab` / `gemini` 时出错仍会退到 `unpdf` |
| `pdf.maxSizeMB` / `pdf.maxPages` | `20`（上限 50） / `100` | PDF 大小上限和最多处理的页数 |
| `image.enabled` | `true` | `false`：不直接抓图片，也不做视频抽帧和缩略图 |
| `youtube.enabled` / `video.enabled` | `true` | `false`：不做 YouTube / 本地视频理解 |
| `video.maxSizeMB` | `50` | 本地视频大小上限 |

#### 网络、代理与鉴权

| 参数 | 默认 | 取值与效果 |
|------|------|-----------|
| `ssrf.allowRanges` | `[]` | 豁免 SSRF 防护的 CIDR 列表。默认所有私网和保留地址都会被拦；Surge、Clash 这类代理开 TUN + fake-IP 时，公网域名会解析到保留网段，必须把那个网段加进来，否则抓取全部失败。只加最窄的范围，`0.0.0.0/0` 和 `::/0` 会被拒绝 |
| `ssrf.trustEnvProxy` | `false` | `true`：经代理发出的请求（配置了 `proxy`，或环境里有有效的 `HTTP(S)_PROXY`）跳过本地 DNS 预检，适合只有代理能解析域名的网络；仍拦 localhost、写死的私网 IP 和 `NO_PROXY` 命中的主机<br>`false`：每个主机名都先在本地解析，再判断是不是私网<br>它不负责设置代理本身 |
| `proxy` | 未设置 | 全局代理，如 `"http://host:4444"`。设置后本扩展的出站请求改用 `curl` 走代理（Node 自带的 fetch 不认 `HTTP(S)_PROXY`）。只影响联网工具，不影响模型 API 请求。单次调用传 `proxy: ""` 强制直连 |
| `authFetch` | 未设置 | 带登录态抓取的命名 profile：`{"<名字>": [主机...]}` 或 `{"<名字>": {hosts, chromeProfile, redirects, cache}}`。`fetch_content` 传 `auth: "<名字>"` 时使用本机浏览器 cookie；只走直连、只限 HTTPS 和列出的主机，拒绝跨域跳转，不会把 cookie 交给托管服务。需要同时开 `allowBrowserCookies` |
| `allowBrowserCookies` | `false` | `true`：允许读取本机 Chromium 系浏览器的 cookie（Gemini Web 搜索和 `authFetch` 要用）。会访问浏览器数据，macOS 上可能弹钥匙串授权<br>`false`：不读 cookie，Gemini Web 和 `authFetch` 不可用。也可用环境变量 `PI_ALLOW_BROWSER_COOKIES=1` 打开 |
| `browserCookies` | 自动发现 | `{"browser": ..., "profile": ...}`。`browser` 取 `helium` / `chrome` / `brave` / `arc` / `chromium` / `edge`，指定后只查这一个浏览器，避免其他浏览器弹授权；不写则自动查找。`profile` 是 profile 目录名，如 `"Profile 2"` |

所有 `*ApiKey` 字段（以及 `crawl4aiApiToken`）支持三种写法：

- 字面量：直接写 key。
- `$NAME` 或 `${NAME}`：读这个环境变量。只写纯大写字符串会被当成字面量，读环境变量必须带 `$`。
- `!命令`：每次发请求前运行这条本地命令，取它输出的一行作为 key（5 秒超时），适合接 1Password CLI 这类密码管理器。

要写以 `$` 或 `!` 开头的字面量，分别转义成 `$$` 和 `$!`。没用 `$` / `!` 写法时，同名环境变量（如 `OPENAI_API_KEY`）优先于配置文件里的字面量。顶层 `chromeProfile` 在 0.28.0 已被拒绝，profile 名改写进 `browserCookies.profile`。

## pi-autoname —— 会话命名

> 商店：[pi.dev/packages/pi-autoname](https://pi.dev/packages/pi-autoname) · 仓库：[ssdiwu/pi-autoname](https://github.com/ssdiwu/pi-autoname)

pi 的会话名一般取首条消息或文件名，看名字很难想起会话内容，翻找旧会话时不好定位；每次手动起名又太麻烦。

pi-autoname 在首轮对话结束后调用一次 LLM，起一个“修 auth 模块竞态”这样能看懂的名字。之后它定期在后台评估，话题明显变了就更新名字。

安装：

```bash
pi install npm:pi-autoname@0.6.8
```

配置文件是 `~/.pi/agent/pi-autoname.json`，首次使用时自动生成，所有字段都可选。

**我的配置**（[`config/pi-autoname.json`](../config/pi-autoname.json)）：

```json
{
  "enabled": true,
  "model": "deepseek/deepseek-flash",
  "fallbackModels": ["openai-codex/gpt-6-luna"],
  "cooldownMinutes": 20,
  "debug": false,
  "respectManualName": true
}
```

命名用 `deepseek/deepseek-flash`，失败时回退到 `openai-codex/gpt-6-luna`，再失败就用当前会话模型。

最关键的改动是 `respectManualName: true`。默认情况下，手动起的名字只保留一个冷却周期，之后会被自动命名覆盖；开启后，手动名永久保留。`cooldownMinutes` 从 10 调到 20，命名调用次数减半，实际用下来足够。

### 常用参数

| 参数 | 作用 |
|------|------|
| `model` | 命名用的模型；留空则用当前会话模型 |
| `fallbackModels` | 主模型失败时依次尝试的模型 |
| `cooldownMinutes` | 重命名评估间隔 |
| `respectManualName` | 手动 `/name` 过的标题是否永保 |

### 参数详解

配置文件改完不用重启，插件按文件修改时间自动重读。

| 参数 | 默认 | 取值与效果 |
|------|------|-----------|
| `enabled` | `true` | `true`：首轮对话结束后自动命名，之后按冷却间隔复查<br>`false`：整个插件停用，自动命名、定期复查和 `/autoname` 都不起作用 |
| `model` | `""` | 命名用的模型，写 `provider/model-id`。留空则直接用当前会话模型 |
| `fallbackModels` | `[]` | `model` 失败后依次尝试的模型。完整顺序：`model` → `fallbackModels` → 当前会话模型 → 不调模型、从首条消息里截取文字。所有模型尝试共用 30 秒预算 |
| `cooldownMinutes` | `10` | 两次自动复查的最小间隔（分钟），范围 1–1440。复查时模型判断当前标题是否还贴切，贴切就保持原名。调大则调用更少、标题跟进更慢 |
| `respectManualName` | `false` | `false`：用 `/name` 手动起的名字只保留一个冷却周期，之后如果话题变了，自动命名会覆盖它<br>`true`：手动名永久保留，自动命名不再动它；只有显式运行 `/autoname` 才会改 |
| `debug` | `false` | `true`：把命名过程（选用的模型、请求失败原因、名字变化）打印到 stderr，排查用<br>`false`：不输出 |

发给命名模型的对话片段会先脱敏（API key、token、私钥、`*_PASSWORD` 等）。名字的语言跟随用户消息的主要语言。
