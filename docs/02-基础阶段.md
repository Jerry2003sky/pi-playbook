# 基础阶段：联网与命名

本阶段补 pi 最底层的两个缺口：联网和会话管理（定位见 [01-理念与路线.md](01-理念与路线.md)）。两个插件各管一件事，真正需要改的配置都很少。

本页内容：[前置：装 pi、配模型](#前置装-pi配模型) · [pi-web-access](#pi-web-access--联网能力)（联网能力）· [pi-autoname](#pi-autoname--会话命名)（会话命名）

## 前置：装 pi、配模型

```bash
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
pi --version   # 验证

pi
/login <供应商名>   # 如 /login deepseek，按提示粘贴 API key
```

凭证保存在 `~/.pi/agent/auth.json`。供应商与模型清单见 [ref-models.md](ref-models.md)。

## pi-web-access —— 联网能力

> **一句话**：给 pi 补上联网搜索、网页 / PDF / 视频抓取和带引用的事实查证\
> **收益**：查资料、读外部文档、核对事实都不用离开 pi；搜索源可选 36 个，能复用已有的 OpenAI 登录态\
> **代价**：部分搜索源按次计费或消耗套餐额度；走 fake-IP 代理时要手动放行地址池，否则抓取会被 SSRF 防护拦下\
> **适合**：几乎所有人，pi 本体不能联网。**不必装**：完全离线、只处理本地代码\
> **改动深度**：只新增联网工具，不改内置行为

商店：[pi.dev/packages/pi-web-access](https://pi.dev/packages/pi-web-access) · 仓库：[nicobailon/pi-web-access](https://github.com/nicobailon/pi-web-access) · 本机版本 `0.37.0`

pi 本体不能联网。pi-web-access 补上一整套联网工具，后文的查证、读网页、查外部资料都靠它们：

- `web_search`：联网搜索，后端可选 36 个提供方（OpenAI、xAI 等）；
- `fetch_content`：抓网页、PDF、视频内容，拉取 GitHub 仓库；
- `source_check`：带引用的事实查证；
- `get_search_content`：取回之前存下的搜索内容。

抓取请求默认经过 SSRF 防护。走 fake-IP 代理时要放行代理的地址池，做法见下文“我的配置”。

联网工具何时挂载由 `toolActivation` 决定。默认的 `auto` 按模型能力选择：

- 模型支持中途加工具：新会话只挂一个 `web_enable`，模型调用它后，其余联网工具从下一次请求起可用。整个过程不重发会话，前缀缓存不受影响。
- 模型不支持：从第一条请求起挂上全部联网工具。

另外两个选项不看模型：`dynamic` 总是先挂 `web_enable`，`eager` 总是一开始就挂全套。动态激活需要 Pi 0.86.0 及以上。挂载方式在新建会话时确定，之后换模型或恢复会话都沿用当时记录的工具集。

配置文件是 `~/.pi/agent/web-search.json`（不存在时回退到旧路径 `~/.pi/web-search.json`）。所有字段都可选，未写的取内置默认值。

**我的配置**（[`config/web-search.json`](../config/web-search.json)）：

```json
{
  "provider": ["openai"],
  "openaiSearchModel": "gpt-6-astra",
  "xaiSearchModel": "grok-4.7",
  "xaiSearchTools": ["x_search"],
  "workflow": "none",
  "toolActivation": "auto",
  "ssrf": {
    "allowRanges": ["198.18.0.0/15"]
  }
}
```

逐项说明：

- `provider: ["openai"]`：只用 OpenAI 搜索，复用已有订阅。数组写法走的是多源聚合，这里只列了一个源；要按顺序回退，应改用 `searchRouting.providers`。
- `openaiSearchModel: gpt-6-astra`：固定 OpenAI 搜索模型。id 原样传给 OpenAI 接口，鉴权默认优先用 openai-codex 登录态，因此网关专属的模型 id 也能填。
- `xaiSearchModel: grok-4.7`：显式选用 xAI 时的搜索模型。
- `xaiSearchTools: ["x_search"]`：xAI 只搜 X。与上一项一样，仅在显式设 `provider: "xai"` 时生效，平时只是预留。
- `workflow: none`：不做总结，直接返回搜索原文。
- `toolActivation: auto`：按模型能力决定挂载方式，机制见上文。
- `ssrf.allowRanges` 里的 `198.18.0.0/15`：Surge 的 fake-IP 地址池。本机走系统代理，抓取时域名会解析到这个网段，不放行就会被 SSRF 防护拦截。

### 参数

**常用参数**

| 参数 | 默认 | 说明 |
|------|------|------|
| `provider` | `auto` | 默认搜索源。<br>· 字符串：固定用这一个源<br>· 数组：并发查询多个源再合并，费用可能更高<br>· `auto`：按内置顺序选可用的源 |
| `toolActivation` | `auto` | 联网工具的挂载方式，一般保持 `auto`，修改后重启生效。<br>· `auto`：按模型能力自动选<br>· `dynamic`：先只挂 `web_enable`，初始上下文更小，但可能丢一次缓存<br>· `eager`：一开始就挂全套 |
| `workflow` | `none` | 搜索结果的处理方式；要人工把关选 `summary-review`，要省掉摘要调用选 `none`。<br>· `summary-review`：打开浏览器审核摘要草稿<br>· `auto-summary`：自动生成摘要<br>· `none`：直接返回结果 |
| `ssrf.allowRanges` | 不设 | 不受 SSRF 防护拦截的 CIDR 网段。用 fake-IP 代理时只放行它的地址池，不要为了解决连接失败放开整个内网。 |
| `openaiSearchModel` | 自动选择 | 指定 OpenAI 搜索模型的 ID，不再自动选择。适合固定成本或使用网关专属模型；所选模型须支持该端点的搜索。 |
| `xaiSearchModel` | 自动选择 | 固定 xAI 搜索的模型。控制费用或旧模型退役时调整，不影响主会话模型。 |
| `xaiSearchTools` | `["web_search"]` | xAI 搜索可用的工具，仅在选用 xAI 时生效。<br>· `["x_search"]`：只搜 X<br>· `["web_search", "x_search"]`：两者都开 |

## pi-autoname —— 会话命名

> **一句话**：首轮对话结束后调用一次 LLM 给会话起名，话题变了再自动更新\
> **收益**：翻旧会话时，看名字就知道聊的是什么，不用逐个点开\
> **代价**：每次命名多一次模型调用（可指定廉价模型）；默认手动起的名字只保留一个冷却周期，之后会被覆盖\
> **适合**：会话多、常回头找旧会话的人。**不必装**：会话很少，或习惯自己用 `/name` 起名\
> **改动深度**：只管会话名称，不参与对话

商店：[pi.dev/packages/pi-autoname](https://pi.dev/packages/pi-autoname) · 仓库：[ssdiwu/pi-autoname](https://github.com/ssdiwu/pi-autoname) · 本机版本 `0.6.8`

pi 默认用首条消息或文件名做会话名，看名字想不起聊过什么，翻旧会话很难定位；每次手动起名又太麻烦。

pi-autoname 在首轮对话结束后调用一次 LLM，起一个“修 auth 模块竞态”这样能看懂的名字。之后定期在后台复查，话题明显变了就改名。

配置文件是 `~/.pi/agent/pi-autoname.json`，首次使用时自动生成，所有字段都可选。

**我的配置**（[`config/pi-autoname.json`](../config/pi-autoname.json)）：

```json
{
  "enabled": true,
  "model": "deepseek/deepseek-flash",
  "fallbackModels": ["openai-codex/gpt-6-luna"],
  "cooldownMinutes": 20,
  "debug": false,
  "respectManualName": true
}
```

逐项说明：

- `model: deepseek/deepseek-flash`、`fallbackModels: ["openai-codex/gpt-6-luna"]`：命名用 deepseek-flash，失败时回退到 gpt-6-luna，再失败就用当前会话模型。
- `respectManualName: true`：最关键的改动。默认情况下，手动起的名字只保留一个冷却周期，之后会被自动命名覆盖；开启后一直保留。
- `cooldownMinutes: 20`：从默认的 10 调到 20，后台评估次数减半，实际用下来足够。

### 参数

**常用参数**

| 参数 | 默认 | 说明 |
|------|------|------|
| `model` | 空（用会话模型） | 命名模型，格式 `provider/modelId`。主模型较贵时可另选轻量模型。 |
| `fallbackModels` | 不设 | 命名模型失败后依次尝试的备用模型，最后才用会话模型。所有模型尝试共用 30 秒，仍失败就在本地提取标题。 |
| `cooldownMinutes` | `10` | 多久评估一次是否改名（分钟，1–1440）。调大省后台调用，调小更快跟上话题变化。 |
| `respectManualName` | `false` | 怎么对待手动起的名字；不想让手动命名被改就开启。<br>· `false`：只保护一个冷却周期<br>· `true`：一直保留，直到手动执行 `/autoname` |

|------|------|------|
| `enabled` | `true` | 设为 `false` 会停止自动命名，手动 `/autoname` 也一并禁用。只想保住手动命名，应改用 `respectManualName`。 |
| `debug` | `false` | 输出调试日志（含会话 JSONL 诊断），排查问题时用，平时关闭。 |
