# 基础阶段：联网与命名

本阶段补齐 pi 最底层的两项能力：联网检索与会话管理（定位见 [01-理念与路线.md](01-理念与路线.md)）。两个插件各司其职，开箱即可工作，真正需要改动的配置很少。

本页内容：[前置：装 pi、配模型](#前置装-pi配模型) · [pi-web-access](#pi-web-access--联网能力)（联网能力）· [pi-autoname](#pi-autoname--会话命名)（会话命名）

## 前置：装 pi、配模型

```bash
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
pi --version   # 验证

pi
/login <供应商名>   # 如 /login deepseek，按提示粘贴 API key
```

凭证保存在 `~/.pi/agent/auth.json`，供应商与模型清单见 [ref-models.md](ref-models.md)。

## pi-web-access —— 联网能力

> **一句话**：为 pi 补齐联网搜索、网页 / PDF / 视频抓取与带引用的事实查证\
> **收益**：查资料、读外部文档、核对事实都无需离开 pi；可选 48 个搜索源，也能直接复用已有的 OpenAI 登录态\
> **代价**：部分搜索源按次计费或消耗套餐额度；走 fake-IP 代理时须手动放行地址池，否则抓取会被 SSRF 防护拦截\
> **适合**：几乎所有人（pi 本体不能联网）。**不必装**：完全离线、仅处理本地代码\
> **改动深度**：只新增联网工具，不改内置行为

商店：[pi.dev/packages/pi-web-access](https://pi.dev/packages/pi-web-access) · 仓库：[nicobailon/pi-web-access](https://github.com/nicobailon/pi-web-access) · 本机版本 `0.48.0`

pi 本体不带联网能力。pi-web-access 补齐了一整套联网工具，查资料、读外部文档、核对事实都靠它们完成：

- `web_search`：联网搜索，后端支持 48 个提供方（OpenAI、xAI 等）；
- `fetch_content`：抓取网页、PDF 与视频内容，支持拉取 GitHub 仓库；
- `source_check`：带引用的事实查证；
- `get_search_content`：取回此前缓存的搜索内容。

抓取请求默认受 SSRF 防护约束。本机走 fake-IP 代理时需放行代理地址池，做法见下文“我的配置”。

联网工具的挂载时机由 `toolActivation` 控制。默认的 `auto` 会按模型能力自动判断：

- 模型支持中途追加工具：新会话只挂一个 `web_enable`，待模型调用后，其余联网工具从下一次请求起生效。整个过程不重发会话，不影响前缀缓存。
- 模型不支持：从第一条请求起即挂载全套联网工具。

`dynamic` 固定先挂 `web_enable`，`eager` 固定从一开始就挂全套，两者都不区分模型能力。`none` 则不挂 `web_enable`，须配合 `toolExposure: "deferred"`，仅通过已启用的 `codemode` 或 `tool_search` 调用联网工具。动态激活需要 Pi 0.86.0 及以上版本。挂载方式在新会话发出第一条请求时按当时的模型确定，发出后切换模型或恢复会话均沿用当时记录的工具集。

配置文件位于 `~/.pi/agent/web-search.json`（不存在时回退到旧路径 `~/.pi/web-search.json`）。所有字段均可选，未写明时取内置默认值。

**我的配置**（[`config/web-search.json`](../config/web-search.json)）：

```json
{
  "provider": ["openai", "deepseek"],
  "deepseekApiKey": "!jq -r '.deepseek.key' ~/.pi/agent/auth.json",
  "openaiSearchModel": "gpt-6.2-astra",
  "xaiSearchModel": "grok-4.7",
  "xaiSearchTools": ["x_search"],
  "workflow": "none",
  "toolActivation": "auto",
  "ssrf": {
    "allowRanges": ["198.18.0.0/15"]
  },
  "fetchRouting": {
    "providers": [
      "http",
      "deepseek"
    ],
    "allowRemoteHostedProviders": true
  }
}
```

逐项说明：

- `provider: ["openai", "deepseek"]`：两个源并发查询并合并结果。OpenAI 复用已有订阅；DeepSeek 新上线的 Search / Fetch API 质量不错，一并纳入。DeepSeek 属于须点名的源，`auto` 不会自动选中。数组写法走的是多源聚合；若希望按顺序回退，应改用 `searchRouting.providers`。
- `deepseekApiKey: "!jq …"`：每次请求时执行命令，直接从 `auth.json` 读取 `/login deepseek` 存下的 key，不必重复维护一份凭证。DeepSeek 搜索按成功请求计费。
- `openaiSearchModel: gpt-6.2-astra`：固定 OpenAI 搜索模型。id 会原样传给 OpenAI 接口，鉴权默认优先走 openai-codex 登录态，网关专属的模型 id 同样可填。
- `xaiSearchModel: grok-4.7`：xAI 搜索所用模型。
- `xaiSearchTools: ["x_search"]`：xAI 仅启用 X 搜索。
- `workflow: none`：不做二次摘要，直接返回搜索原文。
- `toolActivation: auto`：按模型能力决定挂载方式，机制见上文。
- `ssrf.allowRanges` 中的 `198.18.0.0/15`：Surge 的 fake-IP 地址池。本机走系统代理，抓取时域名会解析到该网段，不放行会被 SSRF 防护拦截。
- `fetchRouting.providers: ["http", "deepseek"]`：直接 HTTP 抓取失败时回退到 DeepSeek Fetch。DeepSeek 不在默认抓取路由中，必须显式列出。
- `fetchRouting.allowRemoteHostedProviders: true`：DeepSeek Fetch 属于远程托管源，须开启此项才会启用；开启后目标 URL 会发给 DeepSeek。

### 参数

**常用参数**

| 参数 | 默认 | 说明 |
|------|------|------|
| `provider` | `auto` | 默认搜索源。<br>· 字符串：固定使用单个源<br>· 数组：并发查询多个源并合并，费用可能更高<br>· `auto`：按内置顺序选择可用源 |
| `toolActivation` | `auto` | 联网工具的挂载方式，一般保持 `auto`，修改后重启生效。<br>· `auto`：按模型能力自动判断<br>· `dynamic`：先只挂 `web_enable`，初始上下文更小，但可能触发一次缓存失效<br>· `eager`：从首条请求起挂全套<br>· `none`：不挂 `web_enable`，须配合 `toolExposure: "deferred"`，仅经 `codemode` 或 `tool_search` 调用 |
| `workflow` | `none` | 搜索结果的处理方式；需要人工把关选 `summary-review`，想省掉摘要调用选 `none`。<br>· `summary-review`：打开浏览器审核摘要草稿<br>· `auto-summary`：自动生成摘要<br>· `none`：直接返回原始结果 |
| `ssrf.allowRanges` | 不设 | 豁免 SSRF 防护的 CIDR 网段。使用 fake-IP 代理时只放行代理地址池，切勿为图省事放开整个内网。 |
| `openaiSearchModel` | 自动选择 | 固定 OpenAI 搜索模型的 ID，不再自动挑选。适合控制成本或使用网关专属模型；所选模型须支持对应端点的搜索能力。 |
| `xaiSearchModel` | 自动选择 | 固定 xAI 搜索模型，便于控费或应对旧模型下线，不影响主会话模型。 |
| `xaiSearchTools` | `["web_search"]` | xAI 搜索可用的工具集，仅在选用 xAI 时生效。<br>· `["x_search"]`：只搜 X<br>· `["web_search", "x_search"]`：两者同时启用 |

**路由与回退**

| 参数 | 默认 | 说明 |
|------|------|------|
| `searchRouting.providers` | 不设 | 按顺序尝试的备用源，逐个回退而非并发聚合，不接受 `auto`。顶层 `provider` / `searchProvider` 设为单个源时会覆盖此项；作为默认配置的 `provider` 数组全部失败且错误命中 `fallbackOn` 时，会继续回退到数组中尚未尝试的源。 |
| `searchRouting.fallbackOn` | 不设（设了须非空） | 决定哪些失败类型触发换源，其余错误直接返回。<br>· `transient`：临时故障<br>· `quota`：配额耗尽或限流<br>· `network`：网络错误<br>· `invalid-response`：无效响应<br>· `unsupported`：不支持的操作<br>· `empty`：请求成功但无结果<br>· `domain-miss`：缺少指定域名的结果<br>· `off-topic`：结果与查询无关，须配合 `searchRouting.offTopicModel` |
| `searchRouting.timeoutMs` | 不设 | 单次路由搜索的总时限（毫秒，1–600000），包含各源的可用性检查与凭证读取。超时即中止，不再尝试后续源。 |
| `searchRouting.offTopicModel` | 不设 | 判定结果是否跑题的分类模型（如 `cloudflare-workers-ai/@cf/cloudflare/clef`）。查询、回答与结果摘要都会发给它；仅在 Pi 中生效，MCP 模式下不可用。 |
| `fetchRouting.providers` | 不设 | 正文抓取失败时依次换用的源，如 `["http", "jina"]`。稳定或自托管的源宜放前面，列表越短，等待与外发越少。`parallel-mcp`、`deepseek`、`exa`、`tabstack`、`specstream` 不在默认顺序里，须显式列出。 |
| `fetchRouting.allowRemoteHostedProviders` | `false` | 允许第三方托管服务代抓网页。开启后目标 URL 会发给对方，由对方解析 DNS 并跟随重定向；涉及敏感目标时应保持关闭。 |

**模型**

| 参数 | 默认 | 说明 |
|------|------|------|
| `searchModel` | `gemini-3.6-flash` | 仅决定 Gemini 搜索所用模型，不影响网页、YouTube 与视频抽取。通常选用快速模型，搜索质量不足时再换。 |
| `summaryModel` | 不设 | 生成搜索摘要的模型，可附 `:low` 等思考后缀。想省费可选轻量模型，但须在 pi 的 `enabledModels` 范围内；写 `current` 或 `current:<档位>` 则复用当前会话模型。一旦指定就只用该模型，不可用时返回基于搜索结果拼出的普通摘要与失败原因，不自动换源。 |

**网络与鉴权**

| 参数 | 默认 | 说明 |
|------|------|------|
| `ssrf.trustEnvProxy` | `false` | 仅在代理负责 DNS 解析时开启，跳过代理目标的本地 DNS 预检。它不负责配置代理本身；localhost 与私网 IP 照常拦截，`NO_PROXY` 目标照常检查。 |
| `lockProxy` | 不设 | 设为 `true` 后，配置文件里的 `proxy` 成为 `web_search`、`source_check`、`fetch_content` 的唯一出口：工具调用若传入 `proxy: ""` 或其他代理，会在发包前直接报错。适合由代理统一注入真实 API key 的环境；未配 `proxy` 时所有调用都会失败。 |
| `authFetch` | 不设 | 为需要登录的站点配置命名 cookie 档案，如 `{"work": ["docs.company.com"]}`。调用时传入 `auth: "work"`，仅对名单内主机生效。 |
| `browserCookies` | 不设（自动发现） | 用 `{browser, profile}` 指定 Gemini Web 读取哪个浏览器和用户档案的 cookie。显式指定后不再探测无关浏览器，也能减少钥匙串授权弹窗。 |
| `allowBrowserCookies` | `false` | 允许读取 Chromium cookie，供 Gemini Web 与登录态抓取使用。确有需要再开，开启后可能弹出系统钥匙串授权。 |
| `allowHttpBaseUrls` | `false` | 允许 `braveBaseUrl` 这类网关地址在任意主机上走明文 `http://`。API key 与请求内容均不加密，仅在可信内网开启。 |

`authFetch` 档案也支持写成 `{hosts, chromeProfile, redirects: "same-origin", cache: "session" 或 "off"}`，前提是允许读取 cookie。这类请求只在本地走 HTTPS，拒绝跨源重定向，cookie 与登录后的正文都不会发往远端抽取服务。`browserCookies.browser` 支持 helium、chrome、brave、arc、chromium、edge；读取 cookie 也可以通过环境变量 `PI_ALLOW_BROWSER_COOKIES=1` 开启。

所有 `*ApiKey` 字段均支持三种写法：字面量、`$ENV`（读取环境变量）、`!命令`（每次执行命令获取凭据）。全大写字符串仍按字面量处理，读取环境变量必须带 `$` 前缀。顶层 `chromeProfile` 自 0.28.0 起已弃用，profile 名改写在 `browserCookies.profile`。

## pi-autoname —— 会话命名

> **一句话**：收到首组请求与回复后在后台调用模型起名，首个任务结束时校准一次，话题转向后再自动更新\
> **收益**：翻找旧会话时凭标题就能分辨主题，不必逐个点开\
> **代价**：每次命名多一次模型调用（可指定廉价模型），首个任务可能触发两次；默认手动起的名字只保护一个冷却周期，过期后会被覆盖\
> **适合**：会话多、常回查历史记录的人。**不必装**：会话极少，或习惯手动用 `/name` 命名\
> **改动深度**：只管会话名称与终端标题，不参与对话内容

商店：[pi.dev/packages/pi-autoname](https://pi.dev/packages/pi-autoname) · 仓库：[ssdiwu/pi-autoname](https://github.com/ssdiwu/pi-autoname) · 本机版本 `0.7.5`

pi 默认拿首条消息或文件名充当会话名，回头翻记录很难凭标题想起聊过什么；每次手动 `/name` 又太繁琐。

pi-autoname 在拿到第一组请求和回复后即于后台调用模型（不等工具跑完），起一个“修 auth 模块竞态”这样直观的标题。首个任务结束时会校准一次，此后按冷却周期在后台评估，话题明显转向时自动改名。

工作期间，TUI 的终端标题会显示加载动画（`π - ⠋ - 标题`）。动画只作用于终端标题，不改会话名，也不额外调用模型。

配置文件位于 `~/.pi/agent/pi-autoname.json`，首次使用时自动生成，所有字段均可选。

**我的配置**（[`config/pi-autoname.json`](../config/pi-autoname.json)）：

```json
{
  "enabled": true,
  "model": "deepseek/deepseek-flash",
  "fallbackModels": ["openai-codex/gpt-6-luna"],
  "cooldownMinutes": 20,
  "debug": false,
  "respectManualName": true
}
```

逐项说明：

- `model: deepseek/deepseek-flash`、`fallbackModels: ["openai-codex/gpt-6-luna"]`：主命名模型用 deepseek-flash，失败时回退到 gpt-6-luna，仍失败再落回当前会话模型。
- `respectManualName: true`：最关键的一项改动。默认情况下，手动起的名字只保护一个冷却周期，之后会被自动命名覆盖；开启后永久保留。
- `cooldownMinutes: 20`：从默认的 10 调到 20，后台评估频次减半，日常使用依然及时。

### 参数

**常用参数**

| 参数 | 默认 | 说明 |
|------|------|------|
| `model` | 空（用会话模型） | 命名模型，格式 `provider/modelId`，支持 `:low` 等思考后缀。主模型偏贵时可另选轻量模型。 |
| `fallbackModels` | 不设 | 主命名模型失败后依次尝试的备用模型，最后回退到会话模型。所有模型尝试共用 90 秒（单次上限 75 秒），仍失败则本地提取标题。 |
| `cooldownMinutes` | `10` | 两次改名评估的间隔（分钟，1–1440）。调大省后台调用，调小更快跟上话题变化。 |
| `respectManualName` | `false` | 如何对待手动起的名字；不想被自动改名覆盖时开启。<br>· `false`：仅保护一个冷却周期<br>· `true`：一直保留，直到手动执行 `/autoname` |

<details>
<summary><b>其余参数（5 项）</b></summary>

| 参数 | 默认 | 说明 |
|------|------|------|
| `enabled` | `true` | 设为 `false` 会同时停用自动命名和手动 `/autoname`。只想保住手动标题，应改用 `respectManualName`。 |
| `titleSpinner` | `true` | TUI 终端标题动画，与 AI 命名相互独立。想把终端标题留给 pi 或其他扩展时关闭，`/reload` 后生效。 |
| `language` | `auto` | AI 命名语言，填写 `zh-CN`、`en` 等 BCP 47 标签，优先级高于自动检测和 pi 的语言设置。 |
| `debug` | `false` | 输出调试日志（含会话 JSONL 诊断），排障时开启，平时保持关闭。 |
| `includeCustomMessages` | `false` | 是否将扩展注入的 `custom_message` 纳入命名提示。当扩展消息包含关键上下文时再开；包括界面隐藏的消息在内都会发给命名模型。<br>· `false`：忽略<br>· `true`：全部纳入<br>· 列表：仅纳入指定 `customType` 的消息 |

</details>
