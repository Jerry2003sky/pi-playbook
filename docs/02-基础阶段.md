# 基础阶段：联网与命名

本阶段的定位见 [01-理念与路线.md](01-理念与路线.md)：补 pi 本体最底层的两个缺口——联网能力和会话管理。两个插件都只有一个明确的体验收益，配置面很小。

本页内容：**pi-web-access**（联网能力）· **pi-autoname**（会话命名）

## 前置：装 pi、配模型

```bash
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
pi --version   # 验证

pi
/login <供应商名>   # 如 /login deepseek，按提示粘贴 API key
```

凭证落在 `~/.pi/agent/auth.json`。供应商与模型清单见 [07-models.md](07-models.md)。

## pi-web-access —— 联网能力

> 商店：[pi.dev/packages/pi-web-access](https://pi.dev/packages/pi-web-access) · 仓库：[nicobailon/pi-web-access](https://github.com/nicobailon/pi-web-access)

pi 本体没有联网。pi-web-access 把整套联网工具带进来：`web_search` 联网搜索、`fetch_content` 抓网页/PDF/看视频/拉 GitHub 仓库、`source_check` 带引用的查证、`get_search_content` 取回已存内容。搜索后端支持二十多个提供方，抓取带 SSRF 防护。

装它的理由很直接：没有它， pi 就查不了实时信息。该插件最大的亮点在于它能**调用OpenAI的搜索接口**，因而具备了强大的搜索能力，在我使用的各个agent中都是**首屈一指的**，这也是我一直使用pi的重要原因之一。

安装：

```bash
pi install npm:pi-web-access@0.27.0
```

配置写在 `~/.pi/web-search.json`，全字段可选，不写就按内置默认跑。

**我的配置**（[`config/web-search.json`](../config/web-search.json)）：

```json
{
  "provider": ["openai", "xai"],
  "openaiSearchModel": "gpt-5.6-sol",
  "xaiSearchModel": "grok-4.6",
  "xaiSearchTools": ["x_search"],
  "workflow": "none",
  "ssrf": {
    "allowRanges": ["198.18.0.0/15"]
  }
}
```

五个字段各对应一个决定：`provider: ["openai", "xai"]` 按顺序使用 OpenAI 和 xAI 搜索源，复用已有订阅；`xaiSearchTools: ["x_search"]` 指定 xAI 使用原生搜索工具；`openaiSearchModel: gpt-5.6-sol` 钉死 OpenAI 侧搜索模型，行为稳定；`xaiSearchModel: grok-4.6` 同样钉死 xAI 侧的搜索模型，临时指定 xai 源时也走固定模型；`workflow: none` 关闭结果总结，直接流式返回搜索原文；`198.18.0.0/15` 是 **Surge 的 fake-IP 池**——本机挂系统代理时所有抓取请求都会落在 fake-IP 上，不放行就被 SSRF 防护全部拦截。

**常用参数**

| 参数 | 作用 |
|------|------|
| `provider` | 钉死默认搜索源，不写走内置回退链 |
| `workflow` | 搜索结果的处理方式：`summary-review` 开浏览器策展界面，`auto-summary` 自动生成摘要，`none` 直接流式返回 |
| `ssrf.allowRanges` | 豁免 SSRF 防护的 CIDR 列表，挂 fake-IP 代理时必须放行 |
| `openaiSearchModel` | OpenAI 搜索使用的模型 |
| `xaiSearchModel` | xAI 搜索使用的模型 |

**参数详解**

提供方（`provider` 可取值；`auto` = 默认回退链，`all` = 并发打所有合格源，也可写单个提供方或显式数组；带 * 的是显式-only，`all` 路径不会带上）：

| 提供方 | 说明 |
|--------|------|
| `openai` | 复用 Codex 登录态，可指向兼容网关 |
| `exa` | 免 key 开箱 |
| `brave` | Brave Search API |
| `parallel` | 并行多源 |
| `parallel-mcp` * | Parallel 的 MCP 通道 |
| `tinyfish` | TinyFish 搜索 |
| `search1api` | 按积分计费 |
| `searchinfinity` | 火山引擎，每月免费额度 |
| `querit` | Querit 搜索 |
| `tavily` | 面向 AI 的搜索 API |
| `firecrawl` | 可自托管 |
| `jina` | Jina 搜索 |
| `serpdive` | 三档抓取深度 krill/mako/moby |
| `kagi` | 付费优质搜索 |
| `bocha` | Bocha 搜索 |
| `ollama` | 云搜索，免本地 daemon |
| `anysearch` * | AnySearch |
| `xai` * | Grok 推理内搜索，订阅鉴权 |
| `brightdata` * | 付费 SERP 代理 |
| `serpbase` * | 付费 SERP |
| `searxng` | 自托管元搜索，私有搜索首选 |
| `duckduckgo` * | 免 key |
| `perplexity` | Perplexity 搜索 |
| `gemini` | API grounded search 或浏览器 cookie 方式 |
| `kimi` * | Kimi 搜索，`/login kimi-coding` 鉴权 |
| `xcrawl` * | XCrawl 搜索 |
| `valyu` * | Valyu 搜索 |
| `serper` * | Google SERP API |

路由与回退：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `searchRouting.providers` | array | 显式有序回退链 |
| `searchRouting.fallbackOn` | `transient` / `quota` / `network` / `invalid-response` | 只对列出的失败类型继续下一个候选 |
| `fetchRouting.providers` | array | 抓取回退链 |
| `fetchRouting.allowRemoteHostedProviders` | bool，false | 是否允许远端托管提供方 |

工作流：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `workflow` | `summary-review` / `auto-summary` / `none` | 搜索结果处理方式，见上 |
| `curatorTimeoutSeconds` | number，20 | 策展器超时 |
| `curatorRemote` | bool，false | 远程访问策展器；开启时 token 走明文 HTTP |
| `autoOpenBrowser` | bool，true | 自动开浏览器；Docker/WSL/SSH 环境需要关 |
| `shortcuts.curate` / `shortcuts.activity` | string | 快捷键 |

模型：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `openaiSearchModel` | string | OpenAI 搜索模型 |
| `xaiSearchModel` | string | xAI 搜索模型 |
| `searchModel` | string，gemini-3.6-flash | Gemini 搜索模型 |
| `summaryModel` | string | 策展摘要模型，受 enabledModels 白名单限制 |
| `summaryGenerationDeadlineMs` | number，30000 | 摘要生成时限 |
| `youtube.preferredModel` / `video.preferredModel` | string | 视频理解模型 |

网络与鉴权：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `ssrf.allowRanges` | array | 豁免 SSRF 防护的 CIDR 列表，只加最窄的 fake-IP 池 |
| `ssrf.trustEnvProxy` | bool，false | 信任环境代理变量 |
| `authFetch` | string | fetch_content 的浏览器 cookie 鉴权 profile |
| `chromeProfile` | string | Chrome profile |
| `allowBrowserCookies` | bool，false | Gemini Web 用 |

所有 `*ApiKey` 字段支持三种写法：字面量、`$ENV` 读环境变量、`!命令` 每次取凭据。纯大写字符串会被当字面量，读环境变量必须带 `$` 前缀。

内容与开关：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `maxInlineContentChars` | number，30000 | 内联内容上限 |
| `githubClone` / `maxRepoSizeMB` | bool，true / number，350 | GitHub 克隆开关与大小上限 |
| `pdf` / `maxSizeMB` | bool，true / number，20 | PDF 抓取开关与大小上限 |
| `webSearch.enabled`、`tools.*`、`commands.*` | bool | 功能总开关 |
| `fetchContent.domainPolicy` | `{allow:[], deny:[]}` | 主机名黑白名单 |

## pi-autoname —— 会话命名

> 商店：[pi.dev/packages/pi-autoname](https://pi.dev/packages/pi-autoname) · 仓库：[ssdiwu/pi-autoname](https://github.com/ssdiwu/pi-autoname)

由于pi会话名称的本地规则（取首条消息、取文件名）产出的名字语义化程度低，跨会话检索时几乎没用，同时命名也只能手动，这对于会话管理很不方便。而pi-autoname 在首轮对话后用一个 LLM 调用给会话起语义化名字（比如“修 auth 模块竞态”），之后每隔一段时间静默评估一次，主题漂移了就改名。

安装：

```bash
pi install npm:pi-autoname@0.6.8
```

配置写在 `~/.pi/agent/pi-autoname.json`，首次使用自动生成，全字段可选。

**我的配置**（[`config/pi-autoname.json`](../config/pi-autoname.json)）：

```json
{
  "enabled": true,
  "model": "openai-codex/gpt-5.6-luna",
  "fallbackModels": ["deepseek/deepseek-v4-flash"],
  "cooldownMinutes": 20,
  "debug": false,
  "respectManualName": true
}
```

模型钉在 codex 的 gpt-5.6-luna 上——订阅内最便宜的一档，命名这种机械任务用不着主力模型；失败回退 deepseek-v4-flash，再失败落回会话模型。`respectManualName: true` 是这里最关键的改动：默认行为下手动名只享一个冷却窗口的宽限，之后就会被自动改名覆盖；我不希望自己起的名字被接管。`cooldownMinutes` 从 10 拉到 20，命名调用频率减半，够用。

**常用参数**

| 参数 | 作用 |
|------|------|
| `model` | 命名用的模型；留空则用当前会话模型 |
| `fallbackModels` | 主模型失败时依次尝试的模型 |
| `cooldownMinutes` | 重命名评估间隔 |
| `respectManualName` | 手动 `/name` 过的标题是否永保 |

**参数详解**

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `model` | string，空 | 命名模型；空 = 当前会话模型 |
| `fallbackModels` | array | 失败回退链，全部失败落回会话模型，再败退化为无 AI 的本地文本提取；AI 链共享 30 秒预算 |
| `enabled` | bool，true | 总开关 |
| `cooldownMinutes` | number，10 | 重命名评估间隔 |
| `respectManualName` | bool，false | 手动 `/name` 过的标题永保 |
| `debug` | bool，false | 调试输出 |
