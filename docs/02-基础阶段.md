# 基础阶段：联网与命名

本阶段补 pi 最底层的两个缺口：联网和会话管理（定位见 [01-理念与路线.md](01-理念与路线.md)）。两个插件各管一件事，配置项都很少。

本页内容：**pi-web-access**（联网能力）· **pi-autoname**（会话命名）

## 前置：装 pi、配模型

```bash
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
pi --version   # 验证

pi
/login <供应商名>   # 如 /login deepseek，按提示粘贴 API key
```

凭证保存在 `~/.pi/agent/auth.json`。供应商与模型清单见 [07-models.md](07-models.md)。

## pi-web-access —— 联网能力

> 商店：[pi.dev/packages/pi-web-access](https://pi.dev/packages/pi-web-access) · 仓库：[nicobailon/pi-web-access](https://github.com/nicobailon/pi-web-access)

pi 本体不能联网。pi-web-access 补上一整套联网工具：

- `web_search`：联网搜索，后端可选 36 个提供方（OpenAI、xAI 等）；
- `fetch_content`：抓网页、PDF、视频内容，拉取 GitHub 仓库；
- `source_check`：带引用的事实查证；
- `get_search_content`：取回之前存下的搜索内容。

抓取请求默认经过 SSRF 防护。后面的查证、读网页、查外部资料，都建立在这套工具之上。

联网工具何时挂载由 `toolActivation` 决定，默认 `auto`：

- 会话模型支持中途加工具时，新会话只先挂一个 `web_enable`，模型调用它之后联网工具才出现。激活时不重发会话，前缀缓存保持有效。
- 模型不支持中途加工具时，联网工具从第一条请求起就全部挂上。

`dynamic` 总是先挂 `web_enable`，`eager` 始终直接挂全套。动态激活需要 Pi 0.86.0 及以上；恢复的会话沿用当时记录的工具集。

安装：

```bash
pi install npm:pi-web-access@0.37.0
```

配置文件是 `~/.pi/agent/web-search.json`（不存在时回退到旧路径 `~/.pi/web-search.json`）。所有字段都可选，不写就用内置默认值。

**我的配置**（[`config/web-search.json`](../config/web-search.json)）：

```json
{
  "provider": ["openai"],
  "openaiSearchModel": "gpt-6-astra",
  "xaiSearchModel": "grok-4.7",
  "xaiSearchTools": ["x_search"],
  "workflow": "none",
  "toolActivation": "auto",
  "ssrf": {
    "allowRanges": ["198.18.0.0/15"]
  }
}
```

逐项说明：

- `provider: ["openai"]`：只用 OpenAI 搜索源，复用已有订阅。写成数组会走多源聚合逻辑，这里只列了一个；想要按顺序回退，改用 `searchRouting.providers`。
- `xaiSearchTools: ["x_search"]`：保留 xAI 的 X 搜索设置，显式选择 `provider: "xai"` 时生效。
- `openaiSearchModel: gpt-6-astra`：固定 OpenAI 侧的搜索模型。id 原样发给解析出的 OpenAI 鉴权（默认优先用 openai-codex 登录态），网关专属的模型 id 也可以填。
- `xaiSearchModel: grok-4.7`：显式选择 xAI 时使用的搜索模型。
- `workflow: none`：关闭结果总结，直接返回搜索原文。
- `toolActivation: auto`：模型声明能中途加工具、且无需重发整段对话作检查点时，新会话先只挂 `web_enable`，调用后联网工具在下一次模型请求中可用；否则从第一条请求起全部挂上，避免加工具时损失提示缓存。挂载方式建会话时按当时的模型定一次，之后换模型或续接会话都沿用已记录的工具集。
- `ssrf.allowRanges` 里的 `198.18.0.0/15`：放行 Surge 的 fake-IP 地址池。本机走系统代理时，抓取请求会解析到这个网段，不放行就会被 SSRF 防护拦下。

### 常用参数

| 参数 | 作用 |
|------|------|
| `provider` | 默认搜索源：字符串钉死单源，数组并发聚合多源，不写走内置回退链 |
| `toolActivation` | 联网工具的挂载方式：`auto` 按模型自行选择，`dynamic` 总是先挂 `web_enable`，`eager` 从不使用它 |
| `workflow` | 搜索结果的处理方式：`summary-review` 开浏览器策展界面，`auto-summary` 自动生成摘要，`none` 直接流式返回 |
| `ssrf.allowRanges` | 豁免 SSRF 防护的 CIDR 列表，挂 fake-IP 代理时必须放行 |
| `openaiSearchModel` | OpenAI 搜索使用的模型 |
| `xaiSearchModel` | xAI 搜索使用的模型 |
| `xaiSearchTools` | xAI 使用的搜索工具列表 |

### 参数详解

提供方。`auto` 按内置顺序选可用源；`all` 和提供方数组会并发聚合，可能增加费用；单个名称固定用该源。带 * 的不参与自动选择，须在 `provider` 或 `searchRouting.providers` 中点名。没有已有账号时可先试免 key 的源，需要稳定配额再配 API key。

路由与回退：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `searchRouting.providers` | array | 按顺序尝试备用源，不是并发聚合，也不接受 `auto`；要用这条路由，勿另设顶层 `provider` / `searchProvider`。 |
| `searchRouting.fallbackOn` | array，须非空 | 可选 `transient` 临时故障、`quota` 配额/限流、`network` 网络、`invalid-response` 无效响应、`unsupported` 不支持；仅这些失败才换源。 |
| `fetchRouting.providers` | array | 正文抓取失败时按序换源，如 `["http", "jina"]`；优先放稳定或自托管的源，少配可减少等待和外发。 |
| `fetchRouting.allowRemoteHostedProviders` | bool，false | 允许第三方托管服务代抓网页，会外发目标 URL，且对方自行解析 DNS、跟随重定向；敏感目标保留关闭。 |

工作流：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `workflow` | `summary-review` / `auto-summary` / `none`（默认） | `summary-review` 开浏览器审核摘要草稿；`auto-summary` 自动生成摘要；`none` 直接返回搜索结果。需人工筛选用前者，省调用用后者。 |
| `curatorTimeoutSeconds` | number，20 | 策展界面空闲多少秒后超时，上限 600；人工审核较慢时调高。远程访问且未显式设置时默认 60 秒。 |
| `curatorRemote` | bool 或 `{host, bind}`，未配置 | 开放策展器供远程浏览器访问；`true` 监听所有网卡，`{host, bind}` 可限制接口。仅在可信网络用，token 经明文 HTTP 传输。 |
| `autoOpenBrowser` | bool，true | 自动打开策展页面；本地通常开，SSH/容器设 `false` 后手动访问 URL。远程策展默认不打开，显式设 `true` 才尝试。 |
| `shortcuts.curate` / `shortcuts.activity` | string | 分别打开策展界面、活动监控；用 `ctrl+shift+s` 等 pi 按键格式，冲突时换键，重启生效。 |

模型：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `openaiSearchModel` | string | 指定 OpenAI 搜索模型 ID，跳过自动选择；要固定成本或使用网关专属模型时设置，模型须支持该端点的搜索。 |
| `xaiSearchModel` | string | 固定 xAI 搜索使用的模型；想控制费用或旧模型退役时调整，不影响主会话模型。 |
| `searchModel` | string，gemini-3.6-flash | 只选 Gemini 搜索模型，不影响网页、YouTube 或视频抽取；通常用快速模型，搜索质量不足再换。 |
| `summaryModel` | string | 搜索结果的摘要模型，可加 `:low` 等思考后缀；想省钱可选轻量模型，但须在 pi 的 `enabledModels` 范围内。 |
| `summaryGenerationDeadlineMs` | number，30000 | 单次摘要最多等多少毫秒，上限 600000；慢模型频繁超时可调高，想尽快失败可调低。 |
| `youtube.preferredModel` / `video.preferredModel` | string | 分别指定 YouTube 与本地视频理解的优先模型；不配用 Gemini 默认，需更强视觉理解时再换。 |

网络与鉴权：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `ssrf.allowRanges` | array | 允许访问指定 CIDR 网段；fake-IP 代理可只放行其地址池，不要为解决连接失败而放开整个内网。 |
| `ssrf.trustEnvProxy` | bool，false | 仅在信任代理代做 DNS 时开，可跳过代理目标的本地预检；不负责设置代理，localhost、私网 IP 仍拦截，NO_PROXY 目标仍检查。 |
| `authFetch` | object | 为需登录的网页配置命名 cookie 档案，如 `{"work": ["docs.company.com"]}`；调用时传 `auth: "work"`，只对名单内主机生效。 |
| `browserCookies` | object | 用 `{browser, profile}` 指定 Gemini Web 取 cookie 的浏览器和用户档案；留空自动发现，指定可减少无关浏览器或钥匙串探测。 |
| `allowBrowserCookies` | bool，false | 允许读取 Chromium cookie，供 Gemini Web 和登录态抓取使用；需要这些能力才开，可能触发钥匙串授权。 |

`authFetch` 也支持 `{hosts, chromeProfile, redirects: "same-origin", cache: "session" 或 "off"}`，需同时允许读取 cookie；它只走本地 HTTPS，拒绝跨源重定向，不把 cookie 或登录态正文交给远端抽取服务。`browserCookies.browser` 可选 helium/chrome/brave/arc/chromium/edge；也可用 `PI_ALLOW_BROWSER_COOKIES=1` 开启读取。

所有 `*ApiKey` 字段支持三种写法：字面量、`$ENV` 读环境变量、`!命令` 每次取凭据。纯大写字符串会被当字面量，读环境变量必须带 `$` 前缀。顶层 `chromeProfile` 在 0.28.0 已被拒绝，profile 名写进 `browserCookies.profile`。

内容与开关：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `maxInlineContentChars` | number，30000 | 每次直接返回给模型的内容上限（字符），也限制 `get_search_content` 切片；调低省上下文但需分段读取，范围 1000–200000。 |
| `githubClone` | object，`{enabled: true, maxRepoSizeMB: 350}` | `enabled` 控制仓库克隆特化，`maxRepoSizeMB` 限制大小（MB）；磁盘紧张时调低或关闭，不影响通用网页抓取。 |
| `githubPrIssue.enabled` | bool，true | 用 PR/issue 专用接口读取讨论、状态等结构化信息；接口不可用时可关，仍能按普通网页抓取。 |
| `pdf` | object，`{enabled: true, maxSizeMB: 20}` | `enabled` 开关 PDF 抽取，`maxSizeMB` 限制文件大小（MB，最高 50）；大文档频繁超限才调高，抽取方式另由 `pdf.provider` 决定。 |
| `fetch.defaultMode` / `fetch.allowedModes` | `readable`（默认） / 数组，三种模式全开 | `readable` 抽正文，`raw` 直取 HTTP 原文，`answer` 让模型作答并可能外发内容；前项设默认，后项限制可选模式，默认须在列表内。 |
| `webSearch.enabled`、`tools.*`、`commands.*` | bool | 前者默认关掉搜索和查证；后两项逐个控制工具、命令，并优先于总开关。无需模型使用的能力可关，注册变化需重启。 |
| `webSearch.allowedProviders` | array | 限制搜索可用的源，未列出的一律拒绝；适合控制费用或数据去向。不限制抓取源，也不会自动启用显式专用源。 |
| `toolActivation` | `auto`（默认） / `dynamic` / `eager` | `auto` 自动选挂载方式；`dynamic` 先只挂 `web_enable`，省初始上下文但可能丢缓存；`eager` 开局挂全套。通常留 `auto`，重启生效。 |
| `fetchContent.domainPolicy` | `{allow:[], deny:[]}` | 限制网页抓取主机，裸域名含子域，`deny` 优先；只抓指定站点时配 `allow`，拒绝个别站点配 `deny`，不豁免 SSRF 检查。 |

## pi-autoname —— 会话命名

> 商店：[pi.dev/packages/pi-autoname](https://pi.dev/packages/pi-autoname) · 仓库：[ssdiwu/pi-autoname](https://github.com/ssdiwu/pi-autoname)

pi 的会话名一般取首条消息或文件名，看名字很难想起会话内容，翻找旧会话时不好定位；每次手动起名又太麻烦。

pi-autoname 在首轮对话结束后调用一次 LLM，起一个“修 auth 模块竞态”这样能看懂的名字。之后它定期在后台评估，话题明显变了就更新名字。

安装：

```bash
pi install npm:pi-autoname@0.6.8
```

配置文件是 `~/.pi/agent/pi-autoname.json`，首次使用时自动生成，所有字段都可选。

**我的配置**（[`config/pi-autoname.json`](../config/pi-autoname.json)）：

```json
{
  "enabled": true,
  "model": "deepseek/deepseek-flash",
  "fallbackModels": ["openai-codex/gpt-6-luna"],
  "cooldownMinutes": 20,
  "debug": false,
  "respectManualName": true
}
```

命名用 `deepseek/deepseek-flash`，失败时回退到 `openai-codex/gpt-6-luna`，再失败就用当前会话模型。

最关键的改动是 `respectManualName: true`。默认情况下，手动起的名字只保留一个冷却周期，之后会被自动命名覆盖；开启后，手动名永久保留。`cooldownMinutes` 从 10 调到 20，命名调用次数减半，实际用下来足够。

### 常用参数

| 参数 | 作用 |
|------|------|
| `model` | 命名用的模型；留空则用当前会话模型 |
| `fallbackModels` | 主模型失败时依次尝试的模型 |
| `cooldownMinutes` | 重命名评估间隔 |
| `respectManualName` | 手动 `/name` 过的标题是否永保 |

### 参数详解

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `model` | string，空 | 命名模型，格式 `provider/modelId`；留空用会话模型，主模型较贵时可另选轻量模型。 |
| `fallbackModels` | array | 主模型失败后依次尝试的备用模型，最后尝试会话模型；所有 AI 尝试共享 30 秒，仍失败则本地提取标题。 |
| `enabled` | bool，true | `false` 停止自动命名，也禁用手动 `/autoname`；只想禁止覆盖手动名，应改用 `respectManualName`。 |
| `cooldownMinutes` | number，10 | 多久评估一次重命名（分钟，1–1440）；调大省后台调用，调小更快跟上话题变化。 |
| `respectManualName` | bool，false | `false` 只保护手动名称一个冷却周期；`true` 一直保留，直到手动 `/autoname`。希望自己命名后不再变动就开。 |
| `debug` | bool，false | 输出调试日志（含会话 JSONL 诊断），排障用，平时关。 |
