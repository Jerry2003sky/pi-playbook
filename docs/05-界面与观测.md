# 界面与观测

这一类负责终端显示、输入框样式和运行指标（定位见 [01-理念与路线.md](01-理念与路线.md)）：两个 UI 插件改善显示，一个速度仪表展示响应速度，另外还有本地配色主题和快捷键。它们和前三个阶段的插件互不依赖，随时可以装。

本页内容：**pi-claude-code-ui**（工具渲染美化）· **pi-claude-code-tui**（启动页头与输入框，本地定制）· **dark-classic**（本地配色主题）· **pi-token-speed**（速度仪表）· **keybindings.json**（快捷键）

## pi-claude-code-ui —— 工具渲染美化

> 商店：[pi.dev/packages/pi-claude-code-ui](https://pi.dev/packages/pi-claude-code-ui) · 仓库：[FammasMaz/pi-cc-tools](https://github.com/FammasMaz/pi-cc-tools)

pi 原生把工具输出平铺成原始文本，几十轮之后就很难扫读。pi-claude-code-ui 把工具调用渲染成 Claude Code 风格的结构化视图：分组行、Shiki 高亮的 diff、状态圆点、分支连接线、文件图标。read、search、bash、MCP 四类输出各有可调的显示模式。

它只改界面上的展示，模型收到的仍是原始结果。和所有扩展一样，它运行在 pi 进程内，安装前请先审查来源和源码。

安装：

```bash
pi install npm:pi-claude-code-ui@1.0.84
```

配置以平铺键的形式写在 `~/.pi/settings.json` 顶层。注意它和 `~/.pi/agent/settings.json` 是两个文件。会话内也可以用 `/cc-tools`、`/cc-theme`、`/cc-spinner` 交互修改，改动自动保存。

**我的配置**：全默认。默认效果已经合适，所以 `~/.pi/settings.json` 和项目 `.pi/settings.json` 都没有创建。

### 常用参数

| 参数 | 作用 |
|------|------|
| `toolBackground` | 工具块外观：`outlines` 上下横线 / `transparent` 无边框 / `default` pi 原生背景 |
| `previewLines` / `bashCollapsedLines` / `diffCollapsedLines` | 折叠状态下通用输出、bash 输出、diff 各显示几行 |
| `thinkingMode` | 思考块结束后收起（`live`）还是始终展开（`full`） |
| `groupToolCalls` | 相邻或并发的工具调用是否合并显示 |
| `themeAdaptive` | 颜色是否跟随 pi 主题 |

### 参数详解

以下按 1.0.84 源码核对。插件依次读取项目的 `.pi/settings.json` 和 `~/.pi/settings.json`，同名键以 **`~/.pi/settings.json` 为准**（和多数配置“项目覆盖全局”相反）。设置读取后缓存 5 秒，改文件后最多 5 秒生效，不用重启。

输出样式：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `toolBackground` | `outlines` / `transparent` / `default` / `border`，默认 `outlines` | 每个工具块的外观：<br>`outlines`：背景透明，上下各一条横线分隔<br>`transparent`：无背景、无横线，最紧凑<br>`default`：沿用 pi 原生的工具块背景色<br>`border`：旧名，等同 `outlines`<br>会话里 `/cc-tools outlines` 等命令切换 |
| `mcpOutputMode` | `hidden` / `summary` / `preview`，默认 `preview` | MCP 工具结果怎么显示：<br>`hidden`：完全不显示结果<br>`summary`：只显示一行状态（`N lines returned`，出错时显示错误首行），按 `Ctrl+O` 也不展开<br>`preview`：折叠时同样一行状态，按 `Ctrl+O` 展开看完整输出 |
| `readOutputMode` / `searchOutputMode` / `bashOutputMode` | — | README 仍列出（取值分别为 `hidden`/`summary`/`preview`、`hidden`/`count`/`preview`、`opencode`/`summary`/`preview`），但 1.0.84 源码只声明了类型，没有任何地方读取，**设置了也不起作用**。read、搜索、bash 的显示行数改用下面的行数参数控制 |
| `showTruncationHints` | — | 同上，只声明未读取，设置无效 |

行数与折叠：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `previewLines` | number，8 | 折叠状态下通用输出（read、搜索、MCP 等）预览几行 |
| `bashCollapsedLines` | number，10 | 折叠状态下 bash 输出显示几行 |
| `bashCommandPreviewLines` | number，8 | 多行 bash 脚本在运行中或失败后，显示多少行脚本原文；`0` 不显示。单行命令不受影响 |
| `diffCollapsedLines` | number，24 | edit/write 的 diff 超过这么多行就折叠 |
| `liveToolPreview` | bool，true | `true`：工具运行中在下方实时显示几行最新输出（bash 显示最后几行），直到下一个工具或文字出现<br>`false`：运行中只显示状态，跑完才出结果 |
| `liveToolPreviewLines` | number，5 | 实时预览显示几行 |
| `expandedPreviewMaxLines` | number，4000 | 按 `Ctrl+O` 展开后最多显示多少行，超出的提示已截断 |
| `extraExpandedPreviewMaxLines` | number，12000 | 按 `Ctrl+Shift+O` 进入“加强展开”模式后的行数上限 |
| `extraToolOutputExpanded` | bool，false | `true`：启动时就处于加强展开模式，展开上限用 `extraExpandedPreviewMaxLines`<br>`false`：用普通上限，需要时手动按 `Ctrl+Shift+O` |
| `thinkingMode` | `live` / `full`，默认 `live` | 思考内容怎么显示：<br>`live`：只有正在输出的思考块展开，结束后收成一行 `Thought for Xs`，`Ctrl+O` 可展开<br>`full`：思考块始终展开，和原生 pi 一样<br>会话里用 `/cc-tools thinking live` 或 `/cc-tools thinking full` 切换 |

行为与配色：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `groupToolCalls` | bool，true | `true`：相邻或并发的工具调用合并成一组；对同一目标的重复调用合成一行，不同工具各一行概要<br>`false`：每次调用单独一块。`/cc-tools group off` 会把已合并的也拆开 |
| `themeAdaptive` | bool，true | `true`：边框、暗色文字、diff 增删色、spinner 文字颜色从当前 pi 主题取，换主题自动跟随<br>`false`：固定使用 Claude Code 风格配色，不随主题变<br>会话里用 `/cc-theme on` 或 `/cc-theme off` 切换 |
| `toolBranchColorMode` | `fixed` / `theme`，默认 `fixed` | 工具行左侧分支线 `├ └ │` 的颜色：`fixed` 固定灰色，灰度由 `toolBranchRgbGray` 决定；`theme` 跟随主题的暗色文字颜色 |
| `toolBranchRgbGray` | number，72（0–255） | `fixed` 模式下分支线的灰度，0 黑、255 白 |
| `diffTheme` | string，未设置 | diff 的背景配色预设：`default`（原 pi-diff 配色）、`midnight`（淡色，适合纯黑背景）、`neon`（高对比）。未设置时背景色从主题推导，代码高亮主题按终端背景明暗自动选 `github-dark` 或 `github-light`；一旦设置（哪怕写的不是预设名）就不再自动切换明暗 |
| `diffColors` | object，`{}` | 逐项覆盖 diff 颜色，优先级最高。值为 `#RRGGBB`，可用键：`bgAdd`、`bgDel`（增删行背景）、`bgAddHighlight`、`bgDelHighlight`（行内变动词背景）、`bgGutterAdd`、`bgGutterDel`、`bgEmpty`、`fgAdd`、`fgDel`、`fgDim`、`fgLnum`、`fgRule`、`fgStripe`、`fgSafeMuted`；另有 `shikiTheme` 指定代码高亮主题名 |
| `spinnerVerbColor` / `spinnerStatusColor` | string，`borderAccent` / `muted` | 等待时 spinner 动词（如 `Working…`）和后面状态文字的颜色，填 pi 主题的颜色键名。用 `/cc-spinner verb <key>`、`/cc-spinner status <key>` 设置，`/cc-spinner preview` 列出可选键 |

## pi-claude-code-tui —— 启动页头与输入框（本地定制）

> 商店：[pi.dev/packages/pi-claude-code-tui](https://pi.dev/packages/pi-claude-code-tui) · 仓库：[Phoobobo/pi-claude-code-tui](https://github.com/Phoobobo/pi-claude-code-tui)（本仓库版本是本地定制，见下）

pi 默认的启动画面信息很少：一个横幅，下面就是输入框。pi-claude-code-tui 换上 Claude Code 风格的启动页头，显示动画 π 徽标、当前模型、思考档位、工作目录和常用命令提示；输入框也改成 Codex 风格的全封闭圆角边框（两侧带 │）。

安装（本地定制版，不走 npm 商店）：

```bash
cp -r plugins/pi-claude-code-tui ~/.pi/agent/extensions/
pi   # 重启生效；会话内 /use-claude-code-tui 手动应用，/use-default-tui 还原（选择持久化，见下）
```

上游版本没有配置文件，要定制只能改源码。本地版在上游 v0.1.13 基础上改了六处，每处都有源码注释（五处带 `LOCAL MODIFICATION` 标记，提示分割线那处是普通注释），并把界面选择保存到 `~/.pi/agent/pi-claude-code-tui.json`，由插件自己读写：

| 改动 | 效果 |
|------|------|
| 徽标单元格 `███` → `██` | 徽标整体更窄更轻 |
| 标题/徽标颜色从主题 accent 改为固定灰白 `#EEEEEE` | 页头观感稳定，不随主题切换变色 |
| 提示分割线从“最大 22 字符”改为拉满右栏宽度减 1 | 与左栏边距对齐 |
| 输入框从半开放边框（只有上下圆角边）改为全封闭圆角边框 | 两侧 │ 边线，新增 padOnly 辅助函数保证边框不截断编辑器行 |
| `/use-claude-code-tui` / `/use-default-tui` 的选择持久化到 `~/.pi/agent/pi-claude-code-tui.json` | 重启后保持所选界面；上游两个命令都是会话级，重启即回 |
| 移除输入框光标 restyle | 保留 pi 原生反色光标 |

当前界面选择（[`config/pi-claude-code-tui.json`](../config/pi-claude-code-tui.json)）：

```json
{
  "useDefault": false
}
```

`useDefault` 只有两个值：`false` 用本插件的 Claude Code 风格页头和全封闭输入框（等同执行过 `/use-claude-code-tui`）；`true` 用 pi 原生的启动画面和输入框（等同执行过 `/use-default-tui`），插件仍加载着，随时可以切回。这个文件由两个命令自动写入，一般不用手改。

完整的定制说明和上游信息见 [`plugins/pi-claude-code-tui/INSTALL.md`](../plugins/pi-claude-code-tui/INSTALL.md)。

## dark-classic —— 本地配色主题

pi 自带 `dark`、`light`、`system` 三个主题。本机用的是自定义主题 `dark-classic`：它复制了 pi 0.87.1 内置 `dark` 的配色，以后 pi 升级改了内置配色，这里仍保持原样。自定义主题放在 `~/.pi/agent/themes/`，文件名要和主题的 `name` 一致；pi 只对这个目录下的当前主题做热重载。

安装（副本见 [`config/themes/dark-classic.json`](../config/themes/dark-classic.json)）：

```bash
mkdir -p ~/.pi/agent/themes
cp config/themes/dark-classic.json ~/.pi/agent/themes/
```

在 `~/.pi/agent/settings.json` 里写 `"theme": "dark-classic"` 即可启用（见 [06-settings.md](06-settings.md)）。pi-claude-code-ui 开着 `themeAdaptive`，直接沿用这个主题的配色；pi-claude-code-tui 的页头固定为灰白色，不随主题变化。

## pi-token-speed —— 速度仪表

> 商店：[pi.dev/packages/pi-token-speed](https://pi.dev/packages/pi-token-speed) · 仓库：[gsanhueza/pi-token-speed](https://github.com/gsanhueza/pi-token-speed)

响应速度最影响使用体感，pi 却不显示它。pi-token-speed 在流式输出时，把 TPS（每秒 token 数）、TTFT（首 token 延迟）和统计数据实时显示在状态栏，按速度分四档着色。换模型、调思考档位、换网络节点，速度变化一眼可见。

安装：

```bash
pi install npm:pi-token-speed@0.10.2
```

配置写在 `~/.pi/agent/settings.json` 的 `tokenSpeed` 段（pi-claude-code-ui 用的是另一个文件 `~/.pi/settings.json`）。会话内可以用 `/tps` 菜单随时调整，非法值自动回退为默认值。

**我的配置**（settings.json 的 tokenSpeed 段）：

```json
{
  "display": "tps",
  "useProviderTokens": true,
  "slidingWindow": 1500,
  "countStrategy": "estimate",
  "endTpsBehavior": "average",
  "icon": "",
  "updateInterval": 100,
  "thresholds": {
    "slow": 0,
    "medium": 30,
    "fast": 60,
    "blazing": 90
  }
}
```

- 阈值 30/60/90 TPS，分别是中速、快速、极速三档的起点，比默认值（15/30/45）高一倍；
- `slidingWindow: 1500`：用 1.5 秒的滑动窗口让读数更平稳；
- `useProviderTokens: true`：优先用供应商返回的 token 数，拿不到时按 `countStrategy: estimate` 从文本估算；
- `icon: ""`：隐藏图标；
- `updateInterval: 100`：状态栏每 100ms 刷新一次，测速本身照常逐条计算。

新格式把阈值放在 `thresholds`、颜色放在 `colors` 下。旧的扁平键（如 `tpsMedium`、`colorFast`）仍然兼容，但启动时会警告；在 `/tps` 里保存任意一项设置，就会自动迁移到新格式。

### 常用参数

| 参数 | 作用 |
|------|------|
| `display` | 状态栏信息密度：`tps` / `ttft` / `stats` / `full` |
| `thresholds.medium` / `thresholds.fast` / `thresholds.blazing` | 三档分色阈值（左闭右开） |
| `slidingWindow` | 速度计算的滑动窗口毫秒数 |
| `useProviderTokens` | 用供应商计费 token 数 |
| `countStrategy` | 计数方式：`direct` 每 delta 记 1 / `estimate` 按文本近似 |
| `endTpsBehavior` | 流结束时显示 `average` 全程平均 / `last` 收尾瞬时 |
| `icon` | 状态栏 TPS 前的图标，`/tps` 菜单可选 `⚡` / `🔥` / `💨` / `🚀` / 无 |

### 参数详解

显示：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `display` | `tps` / `ttft` / `stats` / `full`，默认 `tps` | 状态栏显示哪些信息：<br>`tps`：只显示速度，如 `⚡ TPS: 25.0 tok/s`<br>`ttft`：速度加首 token 延迟，如 `(TTFT: 450 ms)`，适合比较供应商或网络节点的响应快慢<br>`stats`：速度加本次 token 数和耗时，如 `(150 tok in 6.0s)`<br>`full`：以上全部 |
| `icon` | string，`⚡` | 状态栏 `TPS` 前的图标，`/tps` 菜单可选 `⚡`、`🔥`、`💨`、`🚀` 或无，也可在配置里写任意字符；`""` 只显示 `TPS: …` |
| `updateInterval` | number，0 | 状态栏刷新间隔（毫秒）。`0` 每收到一段输出就刷新；数字闪烁时设 50–200。只影响显示频率，测速照常逐段计算 |

档位阈值与颜色（档位左闭右开，最后一档向上开放；阈值必须严格递增）：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `thresholds.slow` | number，0 | 慢速档起点，通常保留 0 |
| `thresholds.medium` | number，15 | TPS 达到这个值显示为中速 |
| `thresholds.fast` | number，30 | 达到这个值显示为快速 |
| `thresholds.blazing` | number，45 | 达到这个值显示为极速 |
| `colors.slow` / `colors.medium` / `colors.fast` / `colors.blazing` | string，`#ff4444` / `#ffaa00` / `#00ff88` / `#44ddff` | 四档对应的文字颜色，写 `#RRGGBB` |

测量方式：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `slidingWindow` | number，1000（100–30000 毫秒） | 计算实时速度时看最近多长时间内的 token。窗口大读数平稳但反应慢，小则反应快但跳动大。输出慢的模型（每秒不到 5 个）建议 5000 以上；供应商攒一批再一次性吐出时，插件会把停顿时间算进去，避免显示虚高的瞬时速度 |
| `useProviderTokens` | bool，false | token 数从哪来：<br>`false`：用插件自己的计数（方式见 `countStrategy`）<br>`true`：优先用供应商报告的 token 数，更准；供应商没报告时退回 `countStrategy`<br>无论哪种，流结束时都会用最终的权威 token 数校正总量 |
| `countStrategy` | `direct` / `estimate`，默认 `direct` | 插件自己计数的方式：<br>`direct`：每收到一段流式输出（delta）记 1 个 token，最快但不精确，供应商每段塞很多字时会偏低<br>`estimate`：按每段文字的内容估算 token 数，读数更接近实际<br>只统计正文、思考和 `edit`/`write` 工具调用的输出；其他工具执行期间计时暂停 |
| `endTpsBehavior` | `average` / `last`，默认 `average` | 输出结束后状态栏停在哪个数：<br>`average`：全程平均速度（总 token ÷ 总时长），和 `stats` 显示的数据一致<br>`last`：结束前最后一个滑动窗口的速度，看模型收尾时有多快 |

按供应商覆盖：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `providerOverrides` | object，`{}` | 按供应商 id（如 `anthropic`、`openai-codex`）单独设置，结构和上面相同，可只写部分键，没写的沿用基础配置；`thresholds`/`colors` 按档位合并。显示类的键切换供应商后立即生效，测量类的键从下一次输出开始生效。`/tps overrides` 可交互编辑，当前未设置 |

非法值在会话开始时自动改回默认值，状态栏会提示改了哪些。

## keybindings.json —— 快捷键

pi 的快捷键配置在 `~/.pi/agent/keybindings.json`。这里只改了“复制消息”一个动作（[`config/keybindings.json`](../config/keybindings.json)）：

```json
{
  "app.message.copy": ["super+c"]
}
```

`super+c` 在 macOS 上就是 Command+C，替换掉这个动作默认的 Ctrl+X。具体行为：

- 普通会话里，复制最后一条助手消息；`/tree` 里，复制选中的消息。
- 全屏模式下，`fullscreenCopyOnSelect` 默认为 true：选中文字即自动复制，Command+C 复制最后一条助手消息。设为 `false` 后（本配置就是这样，见 [06-settings.md](06-settings.md)），有选区时 Command+C 复制选区。

终端要能单独上报 Super 修饰键，一般靠 Kitty 键盘协议。如果按键被终端截走，可以改用 `/copy` 复制最后一条助手消息。改完后运行 `/reload`，用 `/hotkeys` 确认绑定，再按 Command+C 检查剪贴板。
