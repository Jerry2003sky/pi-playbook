# 界面与观测

这一类插件横跨所有阶段（定位见 [01-理念与路线.md](01-理念与路线.md)）：不改变 pi 的行为，只改变观感和感知。两个 UI 插件管“好不好看”，一个速度仪表管“快不快看得见”。它们和前面三个能力阶段的插件没有依赖关系，什么时候装都行。

本页内容：**pi-claude-code-ui**（工具渲染美化）· **pi-claude-code-tui**（启动页头与输入框，本地定制）· **pi-token-speed**（速度仪表）· **keybindings.json**（快捷键）

## pi-claude-code-ui —— 工具渲染美化

> 商店：[pi.dev/packages/pi-claude-code-ui](https://pi.dev/packages/pi-claude-code-ui) · 仓库：[FammasMaz/pi-cc-tools](https://github.com/FammasMaz/pi-cc-tools)

pi 原生把工具输出平铺成原始文本，几十轮会话之后很难扫读。pi-claude-code-ui 把工具调用渲染成 Claude Code 风格的结构化视图：分组行、Shiki 高亮 diff、状态圆点、分支连接线、文件图标。read、search、bash、MCP 四类输出各有显示模式可调。

它不改变任何模型行为，纯界面层，零风险。

安装：

```bash
pi install npm:pi-claude-code-ui@1.0.83
```

配置写在 `~/.pi/settings.json` 顶层（注意和 `~/.pi/agent/settings.json` 是两个文件），平铺键；会话内 `/cc-tools`、`/cc-theme`、`/cc-spinner` 可交互改并自动持久化。

**我的配置**：全默认。`~/.pi/settings.json` 和项目 `.pi/settings.json` 都不存在——默认值已经合口味，没有为它创建配置文件。

**常用参数**

| 参数 | 作用 |
|------|------|
| `toolBackground` | 工具行背景样式：`default` / `transparent` / `outlines` / `border` |
| `readOutputMode` | read 结果显示程度：`hidden` / `summary` / `preview` |
| `bashOutputMode` | bash 输出样式：`opencode` 紧凑式/`summary` / `preview` |
| `groupToolCalls` | 并发工具调用是否分组显示 |
| `themeAdaptive` | 颜色是否跟随 pi 主题 |

**参数详解**

输出模式：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `toolBackground` | `default` / `transparent` / `outlines` / `border` | 工具行背景样式，默认 `outlines`；`border` 是 `outlines` 的别名 |
| `readOutputMode` | `hidden` / `summary` / `preview` | read 结果显示程度 |
| `searchOutputMode` | `hidden` / `count` / `preview` | 搜索结果显示程度 |
| `bashOutputMode` | `opencode` / `summary` / `preview` | bash 输出样式 |
| `mcpOutputMode` | `hidden` / `summary` / `preview` | MCP 输出显示程度 |

行数与折叠：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `previewLines` | number，8 | 折叠预览行数 |
| `expandedPreviewMaxLines` | number，4000 | Ctrl+O 展开上限 |
| `extraExpandedPreviewMaxLines` | number，12000 | Ctrl+Shift+O 展开上限 |
| `extraToolOutputExpanded` | bool，false | 额外工具输出默认展开 |
| `thinkingMode` | `live` / `full`，`live` | 思考块展开方式：`live` 只展开流式中的，结束后收起；`full` 始终展开 |
| `bashCollapsedLines` | number，10 | bash 折叠行数 |
| `bashCommandPreviewLines` | number，8 | bash 运行时/失败后展示的脚本行数，`0` 关闭 |
| `liveToolPreviewLines` | number，5 | 实时预览行数 |
| `diffCollapsedLines` | number，24 | diff 折叠行数 |

行为与主题：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `groupToolCalls` | bool，true | 并发工具调用分组显示 |
| `liveToolPreview` | bool，true | 工具运行中显示少量实时输出 |
| `themeAdaptive` | bool，true | 颜色跟随 pi 主题 |
| `diffTheme` | string，`github-dark` | diff 配色主题 |
| `diffColors` | object，{} | 增删色手工覆盖，优先级最高 |
| `showTruncationHints` | bool，false | 截断提示 |

## pi-claude-code-tui —— 启动页头与输入框（本地定制）

> 商店：[pi.dev/packages/pi-claude-code-tui](https://pi.dev/packages/pi-claude-code-tui) · 仓库：[Phoobobo/pi-claude-code-tui](https://github.com/Phoobobo/pi-claude-code-tui)（本仓库版本是本地定制，见下）

pi 默认启动画面的信息量很少：一个横幅，然后就是输入框。pi-claude-code-tui 把 Claude Code 风格启动页头带进来：动画 π 徽标、当前模型、思考档位、工作目录、常用命令提示，输入框改成 Codex 风格全封闭圆角边框（带 │ 侧边）。

安装（本地定制版，不走 npm 商店）：

```bash
cp -r plugins/pi-claude-code-tui ~/.pi/agent/extensions/
pi   # 重启生效；会话内 /use-claude-code-tui 手动应用，/use-default-tui 还原（选择持久化，见下）
```

这个插件上游没有配置文件，定制靠改源码；本地版另把界面选择持久化到 `~/.pi/agent/pi-claude-code-tui.json`（插件自己读写）。我本地的版本基于上游 v0.1.13 改了六处，每处都用 `LOCAL MODIFICATION` 注释标在源码里：

| 改动 | 效果 |
|------|------|
| 徽标单元格 `███` → `██` | 徽标整体更窄更轻 |
| 标题/徽标颜色从主题 accent 改为固定灰白 `#EEEEEE` | 页头观感稳定，不随主题切换变色 |
| 提示分割线从“最大 22 字符”改为拉满右栏宽度减 1 | 与左栏边距对齐 |
| 输入框从半开放边框（只有上下圆角边）改为全封闭圆角边框 | 两侧 │ 边线，新增 padOnly 辅助函数保证边框不截断编辑器行 |
| `/use-claude-code-tui` / `/use-default-tui` 的选择持久化到 `~/.pi/agent/pi-claude-code-tui.json` | 重启后保持所选界面；上游两个命令都是会话级，重启即回 |
| 移除输入框光标 restyle | 保留 pi 原生反色光标 |

当前界面选择（[`config/pi-claude-code-tui.json`](../config/pi-claude-code-tui.json)）：

```json
{
  "useDefault": false
}
```

完整的定制说明和上游信息见 [`plugins/pi-claude-code-tui/INSTALL.md`](../plugins/pi-claude-code-tui/INSTALL.md)。

## pi-token-speed —— 速度仪表

> 商店：[pi.dev/packages/pi-token-speed](https://pi.dev/packages/pi-token-speed) · 仓库：[gsanhueza/pi-token-speed](https://github.com/gsanhueza/pi-token-speed)

模型响应速度是最影响体感的指标，pi 原生不显示。pi-token-speed 在流式输出时于状态栏实时显示 TPS（token/秒）、TTFT（首 token 时延）和统计，按速度分四档着色。换模型、调思考档位、换网络节点，效果都直接可见——它是运行状态的仪表盘。

安装：

```bash
pi install npm:pi-token-speed@0.10.1
```

配置写在 `settings.json` 的 `tokenSpeed` 段；会话内 `/tps` 菜单可运行时调；非法值自动回退默认。

**我的配置**（settings.json 的 tokenSpeed 段）：

```json
{
  "display": "tps",
  "useProviderTokens": true,
  "slidingWindow": 1500,
  "countStrategy": "estimate",
  "endTpsBehavior": "average",
  "icon": "",
  "updateInterval": 100,
  "thresholds": {
    "slow": 0,
    "medium": 30,
    "fast": 60,
    "blazing": 90
  }
}
```

阈值设为 30/60/90 TPS，对应中速、快速、极速三档的起点；`slidingWindow` 用 1500ms，平滑读数。`useProviderTokens: true` 优先采用供应商计数，缺少计数时用 `countStrategy: estimate` 按文本估算。`icon: ""` 隐藏图标；`updateInterval: 100` 将状态栏刷新间隔设为 100ms，测速计算照常进行。

当前格式把阈值放进 `thresholds`、颜色放进 `colors`。旧扁平键（如 `tpsMedium`、`colorFast`）仍兼容，启动时会告警；在 `/tps` 保存任一设置后会自动迁移为嵌套格式。

**常用参数**

| 参数 | 作用 |
|------|------|
| `display` | 状态栏信息密度：`tps` / `ttft` / `stats` / `full` |
| `thresholds.medium` / `thresholds.fast` / `thresholds.blazing` | 三档分色阈值（左闭右开） |
| `slidingWindow` | 速度计算的滑动窗口毫秒数 |
| `useProviderTokens` | 用供应商计费 token 数 |
| `countStrategy` | 计数方式：`direct` 每 delta 记 1 / `estimate` 按文本近似 |
| `endTpsBehavior` | 流结束时显示 `average` 全程平均 / `last` 收尾瞬时 |
| `icon` | 状态栏 TPS 前的图标，`/tps` 菜单可选 `⚡` / `🔥` / `💨` / `🚀` / 无 |

**参数详解**

档位阈值（左闭右开，最后一档向上开放；阈值须严格递增）：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `thresholds.slow` | number，0 | 最低阈值，通常保留 0 |
| `thresholds.medium` | number，15 | 中速档起点 |
| `thresholds.fast` | number，30 | 快速档起点 |
| `thresholds.blazing` | number，45 | 极速档起点 |

档位颜色：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `colors.slow` | string，#ff4444 | 慢速档颜色 |
| `colors.medium` | string，#ffaa00 | 中速档颜色 |
| `colors.fast` | string，#00ff88 | 快速档颜色 |
| `colors.blazing` | string，#44ddff | 极速档颜色 |

窗口与计数：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `slidingWindow` | number，1000（100–30000ms） | 滑动窗口毫秒数 |
| `countStrategy` | `direct` / `estimate` | 计数方式 |
| `useProviderTokens` | bool，false | 用供应商计费 token 数 |
| `endTpsBehavior` | `average` / `last` | 流结束时的显示 |

显示：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `display` | `tps` / `ttft` / `stats` / `full` | 状态栏信息密度 |
| `icon` | string，`⚡` | 状态栏 TPS 前的图标；置空则只显示 `TPS: …` |
| `updateInterval` | number，0 | 状态栏刷新间隔毫秒，`0` = 每个 delta 都刷新 |
| `providerOverrides` | object，{} | 按供应商 id 覆盖设置；`thresholds` / `colors` 按档位合并，省略值沿用基础配置；`/tps overrides` 可编辑，当前未设置 |

## keybindings.json —— 快捷键

pi 原生快捷键配置写在 `~/.pi/agent/keybindings.json`。当前只覆盖消息复制动作（[`config/keybindings.json`](../config/keybindings.json)）：

```json
{
  "app.message.copy": ["super+c"]
}
```

`super+c` 在 macOS 上对应 Command+C，覆盖该动作默认的 Ctrl+X：普通会话里复制最后一条助手消息，`/tree` 里复制选中消息；全屏模式关闭 `fullscreenCopyOnSelect` 时，有选区就复制选区。终端需要支持独立上报 Super 修饰键，通常通过 Kitty 键盘协议；若按键被终端拦截，可使用 `/copy` 复制最后一条助手消息。修改后运行 `/reload`，用 `/hotkeys` 核对绑定，再按 Command+C 验证剪贴板内容。
