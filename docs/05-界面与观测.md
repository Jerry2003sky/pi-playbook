## pi-claude-code-ui —— 工具渲染美化

> **一句话**：把工具调用渲染为 Claude Code 风格的结构化视图——分组行、高亮 diff、状态圆点、分支连接线\
> **收益**：对话跑满几十轮后，工具输出依然清爽好扫读\
> **代价**：与所有扩展一样运行在 pi 进程内，安装前须审查来源；默认跟随终端配色，每次启动都会把 pi 主题切回 `system`，想固定其他主题须手动关闭；read、search 的模式开关在 1.0.107 未生效\
> **适合**：嫌原生工具输出平铺难扫读的人。**不必装**：习惯直接看原始文本输出\
> **改动深度**：只改界面呈现，模型收到的仍是原始结果；`bashIntent: model` 为唯一例外，自 1.0.112 起为默认值

商店：[pi.dev/packages/pi-claude-code-ui](https://pi.dev/packages/pi-claude-code-ui) · 仓库：[FammasMaz/pi-cc-tools](https://github.com/FammasMaz/pi-cc-tools) · 本机版本 `1.0.114`

pi 原生把工具输出平铺成原始文本，跑上几十轮后很难一眼理清做了什么。pi-claude-code-ui 将工具调用重排成 Claude Code 风格的结构化视图：分组行、Shiki 语法高亮 diff、状态圆点、分支连接线和文件图标一应俱全。bash 与 MCP 可切换输出模式（read、search 的模式开关在当前版本未生效，见下表）；只改文件的 bash 命令（如 `sed -i`、heredoc 写文件）同样会渲染成 diff，pi-subagents 的 `Agent` 行与 Agents 面板也会沿用同一套视觉风格。

它只改界面呈现，发回模型的仍是原始工具结果。唯一的例外是 `bashIntent: model`——它会给 bash 工具多加一个字段，并往模型指令里添一行。自 1.0.112 起这是默认值，若希望 bash 行仍直接显示原命令，设 `"bashIntent": "off"` 即可。同所有扩展一样，它运行在 pi 进程内，装前务必审视来源与源码。

配置以平铺键的形式写在 `~/.pi/agent/settings.json` 顶层，与 pi 本体设置共用同一文件。1.0.110 之前读的是 `~/.pi/settings.json`，从旧版升级时记得把原来的键迁过来，否则会按默认值生效。会话内也可用 `/cc-tools`、`/cc-theme`、`/cc-spinner` 交互修改，改动自动落盘。

**我的配置**（`settings.json` 顶层的两个键，完整文件见 [`config/settings.json`](../config/settings.json)）：

```json
{
  "groupToolCalls": false,
  "terminalTheme": false
}
```

- `groupToolCalls: false`：不折叠合并相邻或并发的工具调用，保持每次调用独立成行。
- `terminalTheme: false`：开启时，每次 `/reload` 或重启都会把主题切回 `system`，无法固定其他主题。关掉后才能稳定使用 `settings.json` 指定的 `dark-classic`。其余参数全默认，未创建项目级 `.pi/settings.json`。

## pi-claude-code-tui —— 启动页头与输入框（本地定制）

> **一句话**：换上 Claude Code 风格启动页头（动画 π 徽标、当前模型、思考档位、工作目录），输入框改为全封闭圆角边框\
> **收益**：启动瞬间就能确认当前模型与思考档位，界面整体更利落\
> **代价**：本地定制版不走商店，上游更新须手动合并；不提供配置文件，改样式只能动源码\
> **适合**：偏好 Claude Code 视觉风格的人。**不必装**：习惯 pi 原生界面\
> **改动深度**：只改启动页头与输入框外观，`/use-default-tui` 可随时还原

商店：[pi.dev/packages/pi-claude-code-tui](https://pi.dev/packages/pi-claude-code-tui) · 仓库：[Phoobobo/pi-claude-code-tui](https://github.com/Phoobobo/pi-claude-code-tui) · 本机版本：本地定制（基于上游 v0.1.13）

pi 默认启动画面比较简素：一道横幅下面紧接输入框。pi-claude-code-tui 将其换为 Claude Code 风格的启动页头，集中呈现动画 π 徽标、当前模型、思考档位、工作目录和常用命令提示；输入框同步改为 Codex 风格的全封闭圆角边框（两侧带 `│`）。

安装（本地定制版，不走 npm 商店）：

```bash
cp -r plugins/pi-claude-code-tui ~/.pi/agent/extensions/
pi   # 重启生效；会话内 /use-claude-code-tui 手动应用，/use-default-tui 还原（选择持久化，见下）
```

上游版没有配置文件，想定制只能改源码。本地版在 v0.1.13 基础上改了六处，均附有源码注释（五处带 `LOCAL MODIFICATION` 标记，提示分割线一处为普通注释），并由插件自行将界面选择持久化到 `~/.pi/agent/pi-claude-code-tui.json`：

| 改动 | 效果 |
|------|------|
| 徽标单元格 `███` → `██` | 徽标整体更窄、更轻盈 |
| 标题与徽标颜色由主题 accent 改为固定灰白 `#EEEEEE` | 页头观感稳定，不随主题切换跳色 |
| 提示分割线从“最大 22 字符”改为拉满右栏宽度减 1 | 与左栏边距严格对齐 |
| 输入框由半开放边框（仅上下圆角边）改为全封闭圆角边框 | 补齐两侧 `│` 边线，新增 `padOnly` 辅助函数避免截断编辑器行 |
| `/use-claude-code-tui` / `/use-default-tui` 选择持久化到 `~/.pi/agent/pi-claude-code-tui.json` | 重启后保持所选界面；上游两命令均为会话级，重启即还原 |
| 移除输入框光标 restyle | 保留 pi 原生反色光标 |

留存的界面选择（[`config/pi-claude-code-tui.json`](../config/pi-claude-code-tui.json)）：

```json
{
  "useDefault": true
}
```

`useDefault: true` 表示启用 pi 原生界面，需要定制外观时运行 `/use-claude-code-tui` 即可切回。本机目前未安装该插件，源码与这份状态文件留在仓库备用。

完整定制说明与上游信息见 [`plugins/pi-claude-code-tui/INSTALL.md`](../plugins/pi-claude-code-tui/INSTALL.md)。

## dark-classic —— 本地配色主题

pi 内置 `dark`、`light`、`system` 三套主题。本机使用的是自定义主题 `dark-classic`：它保留了 pi 0.87.1 内置 `dark` 的配色，避免后续 pi 升级改动内置配色时影响观感；其中思考档位的七个颜色（`thinkingOff` 到 `thinkingMax`）已同步为 pi 1.3.0 内置 `dark` 的取值。自定义主题须放在 `~/.pi/agent/themes/`，文件名与主题 `name` 保持一致；pi 只对该目录下当前激活的主题做热重载。

安装（副本见 [`config/themes/dark-classic.json`](../config/themes/dark-classic.json)）：

```bash
mkdir -p ~/.pi/agent/themes
cp config/themes/dark-classic.json ~/.pi/agent/themes/
```

在 `~/.pi/agent/settings.json` 中写入 `"theme": "dark-classic"` 即可生效（见 [ref-settings.md](ref-settings.md)）。pi-claude-code-ui 开启 `themeAdaptive` 后会直接沿用这套配色；pi-claude-code-tui 的页头则固定为灰白色，不受主题影响。

## pi-token-speed —— 速度仪表

> **一句话**：流式输出期间，在状态栏实时展示 TPS（每秒 token 数）与首 token 延迟，按速度分四档着色\
> **收益**：换模型、调思考档位、切网络节点后，吞吐与延迟变化立刻可见\
> **代价**：基本没有，仅占用状态栏一小段宽度\
> **适合**：常切换模型或网络节点、关心响应速度的人。**不必装**：不在意生成速度\
> **改动深度**：仅在状态栏展示读数

商店：[pi.dev/packages/pi-token-speed](https://pi.dev/packages/pi-token-speed) · 仓库：[gsanhueza/pi-token-speed](https://github.com/gsanhueza/pi-token-speed) · 本机版本 `0.13.1`

生成速度最直接影响交互体感，pi 原生却没有任何读数。pi-token-speed 在流式输出过程中，将 TPS（每秒 token 数）、TTFT（首 token 延迟）与统计信息实时呈现在状态栏，并按速度四档着色。换模型、改思考档位或切代理节点后，快慢立判。

配置写在 `~/.pi/agent/settings.json` 的 `tokenSpeed` 段（pi-claude-code-ui 的键同样写在该文件顶层）。会话中可随时用 `/tps` 菜单调整，非法值自动回退默认。

**我的配置**（`settings.json` 的 `tokenSpeed` 段）：

```json
{
  "display": "tps",
  "useProviderTokens": true,
  "slidingWindow": 1000,
  "countStrategy": "estimate",
  "endTpsBehavior": "average",
  "icon": "",
  "updateInterval": 100,
  "thresholds": {
    "slow": 0,
    "medium": 30,
    "fast": 60,
    "blazing": 90
  }
}
```

逐项说明：

- `thresholds` 中的 `medium: 30`、`fast: 60`、`blazing: 90`：中速、快速、极速三档起点均比默认值（15 / 30 / 45）提高一倍。
- `slidingWindow: 1000`：滑动窗口 1 秒，与默认值一致。
- `useProviderTokens: true`：优先采用供应商上报的 token 计数，拿不到时按 `countStrategy: estimate` 从文本估算。
- `icon: ""`：隐藏图标，让状态栏更紧凑。
- `updateInterval: 100`：状态栏每 100ms 刷新一次，内部测速仍逐条计算。

新格式将阈值归入 `thresholds`、颜色归入 `colors`。旧扁平键（如 `tpsMedium`、`colorFast`）虽仍兼容，但启动时会发警告；在 `/tps` 菜单中保存任意一项即可自动迁移至新格式。

### 参数

档位区间左闭右开，最高一档向上开放；四档阈值须严格递增。

**常用参数**

| 参数 | 默认 | 说明 |
|------|------|------|
| `display` | `tps` | 状态栏展示的内容；排查首字慢或总耗时时选 `ttft` 或 `full`。<br>· `tps`：仅显示速度<br>· `ttft`：增加首 token 延迟<br>· `stats`：增加总 token 数与耗时<br>· `full`：全部显示 |
| `thresholds.medium` | `15` | 进入中速档的 TPS 起点。调高后更多读数会落入慢速档，可按个人可接受的底线速度设定。 |
| `thresholds.fast` | `30` | 进入快速档的 TPS 起点，须高于中速阈值。模型普遍较快、颜色长期停在同一档时可调高。 |
| `thresholds.blazing` | `45` | 极速档起点，须高于快速阈值。设在明显高于日常均速的水平，才容易区分真正的高吞吐。 |
| `slidingWindow` | `1000`（范围 100–30000） | 计算实时速度所用的时间窗口（毫秒）。窗口大读数更平稳但滞后，窗口小更能反映突发与卡顿。 |
| `useProviderTokens` | `false` | 开启后优先采信供应商上报的 token 数，缺失时回退至 `countStrategy`。供应商计数准确时开；想用统一本地口径横向对比时关。 |
| `countStrategy` | `direct` | 本地 token 计数口径。<br>· `direct`：每个流片段计 1 token，开销低但受服务端分块策略影响<br>· `estimate`：按文本长度估算，更便于跨接口比较 |
| `endTpsBehavior` | `average` | 流结束后定格显示的速度。<br>· `average`：全程平均速度，适合横向比较模型<br>· `last`：最后一个窗口的速度，适合观察尾段表现 |
| `icon` | `⚡` | TPS 前置图标，支持任意字符；设为空字符串即隐藏，适合窄终端。 |

<details>
<summary><b>其余参数（11 项）</b></summary>

**档位颜色**（写在 `colors` 对象里）

| 参数 | 默认 | 说明 |
|------|------|------|
| `slow` | `#ff4444` | 慢速档颜色，十六进制格式，默认红色，可按终端底色微调。 |
| `medium` | `#ffaa00` | 中速档颜色，十六进制格式，默认橙色。 |
| `fast` | `#00ff88` | 快速档颜色，十六进制格式，默认绿色。 |
| `blazing` | `#44ddff` | 极速档颜色，十六进制格式，默认青色，建议与快速档拉开区分度。 |

**阈值与显示**

| 参数 | 默认 | 说明 |
|------|------|------|
| `thresholds.slow` | `0` | 慢速档下界（TPS），通常保持 `0`。阈值只影响着色，不改变测速本身。 |
| `prefix` | `TPS` | 读数前的文字标签，设为 `""` 可隐藏，适合窄终端。 |
| `updateInterval` | `0` | 状态栏刷新节流间隔（毫秒），`0` 表示每个流片段均刷新。适当调大可减轻重绘开销，内部测速仍逐片段累计。 |
| `formatDuration` | `false` | 将统计耗时换算为更易读的单位，例如把 `92.3s` 显示为 `1m 32.3s`。 |
| `displayColors` | `{}` | 读数后缀的十六进制配色，键为 `count`、`elapsed`、`ttft`。 |
| `suffixTheme` | `""` | 未在 `displayColors` 中指定颜色的后缀文字所用的主题样式，不影响已着色部分。<br>· `""`：终端默认前景色<br>· `dim`：主题 dim 色<br>· `muted`：主题 muted 色 |
| `providerOverrides` | `{}` | 按供应商 ID 覆盖局部参数，适合不同渠道速度分布或计数口径有差异的场景。`thresholds` / `colors` / `displayColors` 逐项合并，未写明的项沿用基础配置。 |

</details>

`providerOverrides` 的键是供应商 ID（如 `openai-codex`），不是模型名，可用 `/tps overrides` 交互编辑。显示类参数修改后立即生效；窗口与计数类参数则从下一次流式响应起生效，避免中途切换口径污染当前测速。

## keybindings.json —— 快捷键

pi 的快捷键配置位于 `~/.pi/agent/keybindings.json`。本机只改动了“复制消息”一项动作（[`config/keybindings.json`](../config/keybindings.json)）：

```json
{
  "app.message.copy": ["super+c"]
}
```

`super+c` 在 macOS 上即 <kbd>Cmd</kbd>+<kbd>C</kbd>，替换掉该动作默认的 <kbd>Ctrl</kbd>+<kbd>X</kbd>。具体表现如下：

- 普通会话中复制最后一条助手消息，`/tree` 视图中复制当前选中的消息。
- 全屏模式下，`fullscreenCopyOnSelect` 默认为 `true`（选中即自动复制，<kbd>Cmd</kbd>+<kbd>C</kbd> 仍复制最后一条助手消息）；将其设为 `false` 后（本机配置即如此，见 [ref-settings.md](ref-settings.md)），有选区时按 <kbd>Cmd</kbd>+<kbd>C</kbd> 会优先复制选区。

终端须支持单独上报 Super 修饰键（通常依赖 Kitty 键盘协议）。若按键被终端截获，可改用 `/copy` 复制最后一条助手消息。改完后执行 `/reload`，先用 `/hotkeys` 确认绑定，再按 <kbd>Cmd</kbd>+<kbd>C</kbd> 验证剪贴板内容。
