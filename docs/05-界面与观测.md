# 界面与观测

这一类负责终端显示、输入框样式和运行指标（定位见 [01-理念与路线.md](01-理念与路线.md)）：两个 UI 插件改善显示，一个速度仪表展示响应速度，另外还有本地配色主题和快捷键。它们和前三个阶段的插件互不依赖，随时可以装。

本页内容：**pi-claude-code-ui**（工具渲染美化）· **pi-claude-code-tui**（启动页头与输入框，本地定制）· **dark-classic**（本地配色主题）· **pi-token-speed**（速度仪表）· **keybindings.json**（快捷键）

## pi-claude-code-ui —— 工具渲染美化

> 商店：[pi.dev/packages/pi-claude-code-ui](https://pi.dev/packages/pi-claude-code-ui) · 仓库：[FammasMaz/pi-cc-tools](https://github.com/FammasMaz/pi-cc-tools)

pi 原生把工具输出平铺成原始文本，几十轮之后就很难扫读。pi-claude-code-ui 把工具调用渲染成 Claude Code 风格的结构化视图：分组行、Shiki 高亮的 diff、状态圆点、分支连接线、文件图标。read、search、bash、MCP 四类输出各有可调的显示模式。

它只改界面上的展示，模型收到的仍是原始结果。和所有扩展一样，它运行在 pi 进程内，安装前请先审查来源和源码。

安装：

```bash
pi install npm:pi-claude-code-ui@1.0.84
```

配置以平铺键的形式写在 `~/.pi/settings.json` 顶层。注意它和 `~/.pi/agent/settings.json` 是两个文件。会话内也可以用 `/cc-tools`、`/cc-theme`、`/cc-spinner` 交互修改，改动自动保存。

**我的配置**：全默认。默认效果已经合适，所以 `~/.pi/settings.json` 和项目 `.pi/settings.json` 都没有创建。

### 常用参数

| 参数 | 作用 |
|------|------|
| `toolBackground` | 工具行的边框/背景样式 |
| `groupToolCalls` | 连续或并发的工具调用是否合并成一组显示 |
| `thinkingMode` | 思考块结束后是否收起 |
| `previewLines` / `bashCollapsedLines` / `diffCollapsedLines` | 折叠状态下各类输出显示多少行 |
| `themeAdaptive` | 颜色是否跟随 pi 主题 |

### 参数详解

插件依次读项目的 `.pi/settings.json` 和 `~/.pi/settings.json`，同名键以 **`~/.pi/settings.json` 为准**（与多数配置“项目覆盖全局”相反）。设置有 5 秒缓存，改文件后最多 5 秒生效，不用重启；`/cc-tools`、`/cc-theme`、`/cc-spinner` 的改动写进 `~/.pi/settings.json`。

以下按 1.0.84 源码核对。

输出样式：

| 参数 | 默认 | 取值与效果 |
|------|------|-----------|
| `toolBackground` | `outlines` | `"outlines"`：每个工具块上下加一条横线分隔，背景透明<br>`"transparent"`：无边框、无背景，最紧凑<br>`"default"`：用 pi 自带的工具块背景色<br>`"border"`：旧名字，等同 `outlines` |
| `mcpOutputMode` | `preview` | MCP 工具结果的显示方式：<br>`"hidden"`：完全不显示结果<br>`"summary"`：只显示一行状态（`N lines returned` 或错误首行），`Ctrl+O` 也不展开<br>`"preview"`：折叠时显示状态行，`Ctrl+O` 展开看完整输出 |
| `readOutputMode` / `searchOutputMode` / `bashOutputMode` | — | README 里列着（取值分别是 `hidden`/`summary`/`preview`、`hidden`/`count`/`preview`、`opencode`/`summary`/`preview`），但 1.0.84 源码里只声明了类型，没有任何地方读取，**设置了也不起作用** |
| `showTruncationHints` | — | 同上，只声明未读取，设置无效 |

行数与折叠：

| 参数 | 默认 | 取值与效果 |
|------|------|-----------|
| `previewLines` | `8` | 折叠状态下预览显示的行数（read、搜索、MCP 等通用输出） |
| `bashCollapsedLines` | `10` | bash 输出预览显示的行数 |
| `bashCommandPreviewLines` | `8` | 多行 bash 脚本在运行中或失败后显示多少行脚本内容，`0` = 不显示；单行命令不受影响 |
| `diffCollapsedLines` | `24` | edit / write 的 diff 超过这么多行就折叠 |
| `liveToolPreview` | `true` | `true`：工具运行中在下方实时显示几行最新输出<br>`false`：运行中只显示状态，跑完才出结果 |
| `liveToolPreviewLines` | `5` | 实时预览的行数 |
| `expandedPreviewMaxLines` | `4000` | 按 `Ctrl+O` 展开后最多显示的行数 |
| `extraExpandedPreviewMaxLines` | `12000` | 按 `Ctrl+Shift+O` 进入加强展开模式后的行数上限 |
| `extraToolOutputExpanded` | `false` | `true`：启动时就处于 `Ctrl+Shift+O` 加强展开模式，展开上限用 `extraExpandedPreviewMaxLines`<br>`false`：启动时用普通上限，需要时手动按 `Ctrl+Shift+O` |
| `thinkingMode` | `live` | `"live"`：只有正在输出的思考块展开，结束后收成一行 `Thought for Xs`，`Ctrl+O` 可展开<br>`"full"`：思考块始终展开，和原生 pi 一样 |

行为与配色：

| 参数 | 默认 | 取值与效果 |
|------|------|-----------|
| `groupToolCalls` | `true` | `true`：相邻或并发的工具调用合并显示；同一目标的重复调用合成一行，不同工具每种一行概要<br>`false`：每次调用单独一块。`/cc-tools group off` 会把已合并的也拆开 |
| `themeAdaptive` | `true` | `true`：边框、暗色文字、diff 增删色、spinner 文字颜色从当前 pi 主题取，切换主题自动跟随<br>`false`：固定使用 Claude Code 风格的配色，不随主题变 |
| `toolBranchColorMode` | `fixed` | 工具行左侧分支线 `├ └ │` 的颜色：<br>`"fixed"`：固定灰度，不随主题变，灰度由 `toolBranchRgbGray` 决定<br>`"theme"`：跟随主题的暗色文字颜色<br>`/cc-tools branch` 可切换 |
| `toolBranchRgbGray` | `72` | `fixed` 模式下分支线的灰度，0（黑）–255（白） |
| `diffTheme` | 未设置 | diff 背景色预设：`"default"`（原 pi-diff 配色）、`"midnight"`（适合纯黑背景的淡色）、`"neon"`（高对比）。未设置时背景色从主题推导，语法高亮主题按终端背景明暗自动选 `github-dark` 或 `github-light`；也可用环境变量 `DIFF_THEME` 指定 Shiki 高亮主题 |
| `diffColors` | `{}` | 手工覆盖 diff 颜色，优先级最高。可用键：`bgAdd`、`bgDel`、`bgAddHighlight`、`bgDelHighlight`、`bgGutterAdd`、`bgGutterDel`、`bgEmpty`、`fgAdd`、`fgDel`、`fgDim`、`fgLnum`、`fgRule`、`fgStripe`、`fgSafeMuted`（值为 `#RRGGBB`），以及 `shikiTheme`（语法高亮主题名） |
| `spinnerVerbColor` / `spinnerStatusColor` | `borderAccent` / `muted` | spinner 动词（如 `Working…`）和状态后缀的颜色，填 pi 主题的颜色键名；用 `/cc-spinner verb <key>` 等命令设置，`/cc-spinner preview` 看可选键 |

## pi-claude-code-tui —— 启动页头与输入框（本地定制）

> 商店：[pi.dev/packages/pi-claude-code-tui](https://pi.dev/packages/pi-claude-code-tui) · 仓库：[Phoobobo/pi-claude-code-tui](https://github.com/Phoobobo/pi-claude-code-tui)（本仓库版本是本地定制，见下）

pi 默认的启动画面信息很少：一个横幅，下面就是输入框。pi-claude-code-tui 换上 Claude Code 风格的启动页头，显示动画 π 徽标、当前模型、思考档位、工作目录和常用命令提示；输入框也改成 Codex 风格的全封闭圆角边框（两侧带 │）。

安装（本地定制版，不走 npm 商店）：

```bash
cp -r plugins/pi-claude-code-tui ~/.pi/agent/extensions/
pi   # 重启生效；会话内 /use-claude-code-tui 手动应用，/use-default-tui 还原（选择持久化，见下）
```

上游版本没有配置文件，要定制只能改源码。本地版在上游 v0.1.13 基础上改了六处，每处都有源码注释（五处带 `LOCAL MODIFICATION` 标记，提示分割线那处是普通注释），并把界面选择保存到 `~/.pi/agent/pi-claude-code-tui.json`，由插件自己读写：

| 改动 | 效果 |
|------|------|
| 徽标单元格 `███` → `██` | 徽标整体更窄更轻 |
| 标题/徽标颜色从主题 accent 改为固定灰白 `#EEEEEE` | 页头观感稳定，不随主题切换变色 |
| 提示分割线从“最大 22 字符”改为拉满右栏宽度减 1 | 与左栏边距对齐 |
| 输入框从半开放边框（只有上下圆角边）改为全封闭圆角边框 | 两侧 │ 边线，新增 padOnly 辅助函数保证边框不截断编辑器行 |
| `/use-claude-code-tui` / `/use-default-tui` 的选择持久化到 `~/.pi/agent/pi-claude-code-tui.json` | 重启后保持所选界面；上游两个命令都是会话级，重启即回 |
| 移除输入框光标 restyle | 保留 pi 原生反色光标 |

当前界面选择（[`config/pi-claude-code-tui.json`](../config/pi-claude-code-tui.json)）：

```json
{
  "useDefault": true
}
```

`useDefault` 取值：`true` 表示用 pi 原生的启动页和输入框（等同执行过 `/use-default-tui`）；`false` 表示用本插件的 Claude Code 风格页头和全封闭输入框（等同执行过 `/use-claude-code-tui`）。本机目前是 `true`，插件仍然装着，随时可以用 `/use-claude-code-tui` 切回。

完整的定制说明和上游信息见 [`plugins/pi-claude-code-tui/INSTALL.md`](../plugins/pi-claude-code-tui/INSTALL.md)。

## dark-classic —— 本地配色主题

pi 自带 `dark`、`light`、`system` 三个主题。本机用的是自定义主题 `dark-classic`：它复制了 pi 0.87.1 内置 `dark` 的配色，以后 pi 升级改了内置配色，这里仍保持原样。自定义主题放在 `~/.pi/agent/themes/`，文件名要和主题的 `name` 一致；pi 只对这个目录下的当前主题做热重载。

安装（副本见 [`config/themes/dark-classic.json`](../config/themes/dark-classic.json)）：

```bash
mkdir -p ~/.pi/agent/themes
cp config/themes/dark-classic.json ~/.pi/agent/themes/
```

在 `~/.pi/agent/settings.json` 里写 `"theme": "dark-classic"` 即可启用（见 [06-settings.md](06-settings.md)）。pi-claude-code-ui 开着 `themeAdaptive`，直接沿用这个主题的配色；pi-claude-code-tui 的页头固定为灰白色，不随主题变化。

## pi-token-speed —— 速度仪表

> 商店：[pi.dev/packages/pi-token-speed](https://pi.dev/packages/pi-token-speed) · 仓库：[gsanhueza/pi-token-speed](https://github.com/gsanhueza/pi-token-speed)

响应速度最影响使用体感，pi 却不显示它。pi-token-speed 在流式输出时，把 TPS（每秒 token 数）、TTFT（首 token 延迟）和统计数据实时显示在状态栏，按速度分四档着色。换模型、调思考档位、换网络节点，速度变化一眼可见。

安装：

```bash
pi install npm:pi-token-speed@0.10.2
```

配置写在 `~/.pi/agent/settings.json` 的 `tokenSpeed` 段（pi-claude-code-ui 用的是另一个文件 `~/.pi/settings.json`）。会话内可以用 `/tps` 菜单随时调整，非法值自动回退为默认值。

**我的配置**（settings.json 的 tokenSpeed 段）：

```json
{
  "display": "tps",
  "useProviderTokens": true,
  "slidingWindow": 1500,
  "countStrategy": "estimate",
  "endTpsBehavior": "average",
  "icon": "",
  "updateInterval": 100,
  "thresholds": {
    "slow": 0,
    "medium": 30,
    "fast": 60,
    "blazing": 90
  }
}
```

- 阈值 30/60/90 TPS，分别是中速、快速、极速三档的起点，比默认值（15/30/45）高一倍；
- `slidingWindow: 1500`：用 1.5 秒的滑动窗口让读数更平稳；
- `useProviderTokens: true`：优先用供应商返回的 token 数，拿不到时按 `countStrategy: estimate` 从文本估算；
- `icon: ""`：隐藏图标；
- `updateInterval: 100`：状态栏每 100ms 刷新一次，测速本身照常逐条计算。

新格式把阈值放在 `thresholds`、颜色放在 `colors` 下。旧的扁平键（如 `tpsMedium`、`colorFast`）仍然兼容，但启动时会警告；在 `/tps` 里保存任意一项设置，就会自动迁移到新格式。

### 常用参数

| 参数 | 作用 |
|------|------|
| `display` | 状态栏显示哪些信息 |
| `thresholds.medium` / `thresholds.fast` / `thresholds.blazing` | 三档分色阈值 |
| `slidingWindow` | 速度计算的滑动窗口毫秒数 |
| `useProviderTokens` / `countStrategy` | token 怎么计数 |
| `endTpsBehavior` | 流结束后显示平均速度还是收尾速度 |
| `icon` | 状态栏 TPS 前的图标 |

### 参数详解

配置写在 `~/.pi/agent/settings.json` 的 `tokenSpeed` 段，全部可选。非法值在会话开始时自动改回默认值并在状态栏提示。

显示：

| 参数 | 默认 | 取值与效果 |
|------|------|-----------|
| `display` | `tps` | `"tps"`：只显示速度，如 `⚡ TPS: 25.0 tok/s`<br>`"ttft"`：速度加首 token 延迟，如 `… (TTFT: 450 ms)`<br>`"stats"`：速度加累计 token 数和耗时，如 `… (150 tok in 6.0s)`<br>`"full"`：以上全部，如 `… (150 tok in 6.0s · TTFT: 450 ms)` |
| `icon` | `"⚡"` | TPS 前的图标，任意字符串；`""` 不显示图标。`/tps` 菜单可选 `⚡` / `🔥` / `💨` / `🚀` / 无 |
| `updateInterval` | `0` | 状态栏刷新间隔（毫秒），`0` = 每收到一段输出就刷新。数字闪烁时调大，如 100；只影响显示，速度照常逐段计算 |

计数与计算：

| 参数 | 默认 | 取值与效果 |
|------|------|-----------|
| `useProviderTokens` | `false` | `true`：优先用供应商返回的 token 数，供应商不返回时退回 `countStrategy`<br>`false`：始终用插件自己计数（按 `countStrategy`）<br>无论哪种，流结束时有准确总数都会用它校正最终平均值 |
| `countStrategy` | `direct` | 插件自己计数时的方法：<br>`"direct"`：每收到一段流式输出记 1 个 token。快，但供应商一段里带多个 token 时会低估<br>`"estimate"`：按每段文本内容估算 token 数。供应商分段很碎或很粗时读数更接近真实速度 |
| `slidingWindow` | `1000` | 用最近多少毫秒内的 token 算速度，范围 100–30000。越大读数越平稳、反应越慢；越小越灵敏、越跳。慢模型（低于 5 tok/s）建议 5000–15000 |
| `endTpsBehavior` | `average` | 流结束后状态栏停在哪个数：<br>`"average"`：全程平均速度（总 token ÷ 总时间），与 `stats` 显示的一致<br>`"last"`：停止那一刻的滑动窗口速度，反映收尾时有多快 |

只统计文本、思考和 edit / write 工具参数的输出；其他工具执行期间计时暂停，不拉低速度。

档位阈值与颜色（按 `>=` 判断：速度大于等于某档阈值就用该档颜色；阈值须严格递增）：

| 参数 | 默认 | 取值与效果 |
|------|------|-----------|
| `thresholds.slow` | `0` | 最低档起点，通常保持 0 |
| `thresholds.medium` | `15` | 达到这个速度显示中速档颜色 |
| `thresholds.fast` | `30` | 达到这个速度显示快速档颜色 |
| `thresholds.blazing` | `45` | 达到这个速度显示极速档颜色 |
| `colors.slow` / `colors.medium` / `colors.fast` / `colors.blazing` | `#ff4444` / `#ffaa00` / `#00ff88` / `#44ddff` | 四档颜色，`#RRGGBB` |

按供应商覆盖：

| 参数 | 默认 | 取值与效果 |
|------|------|-----------|
| `providerOverrides` | `{}` | 按供应商 id 写一份局部配置，如 `{"anthropic": {"thresholds": {"fast": 60}}}`，当前模型属于该供应商时生效。可只写部分键，没写的沿用基础配置；`thresholds` / `colors` 按档位合并。显示类的键切换供应商后立即生效，计数类的键（`slidingWindow`、`useProviderTokens`、`countStrategy`、`endTpsBehavior`）从下一次流开始生效。`/tps overrides` 可交互编辑，本机未设置 |

## keybindings.json —— 快捷键

pi 的快捷键配置在 `~/.pi/agent/keybindings.json`。这里只改了“复制消息”一个动作（[`config/keybindings.json`](../config/keybindings.json)）：

```json
{
  "app.message.copy": ["super+c"]
}
```

`super+c` 在 macOS 上就是 Command+C，替换掉这个动作默认的 Ctrl+X。具体行为：

- 普通会话里，复制最后一条助手消息；`/tree` 里，复制选中的消息。
- 全屏模式下，`fullscreenCopyOnSelect` 默认为 true：选中文字即自动复制，Command+C 复制最后一条助手消息。设为 `false` 后（本配置就是这样，见 [06-settings.md](06-settings.md)），有选区时 Command+C 复制选区。

终端要能单独上报 Super 修饰键，一般靠 Kitty 键盘协议。如果按键被终端截走，可以改用 `/copy` 复制最后一条助手消息。改完后运行 `/reload`，用 `/hotkeys` 确认绑定，再按 Command+C 检查剪贴板。
