# 界面与观测

这一类负责终端显示、输入框样式和运行指标（定位见 [01-理念与路线.md](01-理念与路线.md)）：两个 UI 插件改善显示，一个速度仪表展示响应速度，另外还有本地配色主题和快捷键。它们和前三个阶段的插件互不依赖，随时可以装。

## pi-claude-code-ui —— 工具渲染美化

> **一句话**：把工具调用渲染成 Claude Code 风格的结构化视图：分组行、高亮 diff、状态圆点、分支连接线\
> **收益**：几十轮之后，工具输出依然好扫读\
> **代价**：和所有扩展一样运行在 pi 进程内，装前要审查来源；read、search 的模式开关在 1.0.86 不生效\
> **适合**：觉得原生工具输出难读的人。**不必装**：习惯看原始文本输出\
> **改动深度**：只改界面上的展示，模型收到的仍是原始结果

商店：[pi.dev/packages/pi-claude-code-ui](https://pi.dev/packages/pi-claude-code-ui) · 仓库：[FammasMaz/pi-cc-tools](https://github.com/FammasMaz/pi-cc-tools) · 本机版本 `1.0.86`

pi 原生把工具输出平铺成原始文本，几十轮之后就很难扫读。pi-claude-code-ui 把工具调用渲染成 Claude Code 风格的结构化视图：分组行、Shiki 高亮的 diff、状态圆点、分支连接线、文件图标。bash、MCP 可切换显示模式；read、search 的模式开关在当前版本未生效，见下表。

它只改界面上的展示，模型收到的仍是原始结果。和所有扩展一样，它运行在 pi 进程内，安装前请先审查来源和源码。

配置以平铺键的形式写在 `~/.pi/settings.json` 顶层。注意它和 `~/.pi/agent/settings.json` 是两个文件。会话内也可以用 `/cc-tools`、`/cc-theme`、`/cc-spinner` 交互修改，改动自动保存。

**我的配置**：全默认。默认效果已经合适，所以 `~/.pi/settings.json` 和项目 `.pi/settings.json` 都没有创建。

### 参数

**常用参数**

| 参数 | 默认 | 说明 |
|------|------|------|
| `toolBackground` | `outlines` | `default` 用 pi 底色，`transparent` 去底色，`outlines` 加上下边线且透明；`border` 同 `outlines`。默认边线适合区分密集输出。 |
| `previewLines` | `8` | 通用正文预览最多显示几行；调大便于扫读，调小省屏幕。当前 read/search 展开后也受此值限制。 |
| `bashOutputMode` | `opencode` | `opencode` 折叠看状态、展开看输出；`summary` 始终只看状态；`preview` 折叠也看部分输出。需要盯日志时选后者。 |
| `groupToolCalls` | `true` | 合并相邻或并发工具调用，重复目标压成一行；更易扫读，想逐次检查调用顺序时关闭。 |
| `themeAdaptive` | `true` | 开启后边框、状态文字、diff 等跟随 pi 主题；关闭保留固定 Claude 风格配色，手工颜色覆盖仍优先。 |

<details>
<summary><b>其余参数（15 项）</b></summary>

**输出模式**

| 参数 | 默认 | 说明 |
|------|------|------|
| `readOutputMode` | 未读取 | 原意是隐藏结果 / 只看摘要 / 预览正文；1.0.86 未读取此项，改值无效，实际折叠看行数、展开看正文。 |
| `searchOutputMode` | 未读取 | 原意是隐藏结果 / 只看数量 / 预览匹配项；1.0.86 未读取此项，实际折叠看数量、展开看匹配项。 |
| `mcpOutputMode` | `preview` | `hidden` 隐藏结果，`summary` 仅状态或行数，`preview` 可展开正文预览；MCP 结果很长时优先用后两者。 |

**行数与折叠**

| 参数 | 默认 | 说明 |
|------|------|------|
| `expandedPreviewMaxLines` | `4000` | 支持完整展开的视图在 <kbd>Ctrl</kbd>+<kbd>O</kbd> 下最多显示几行；调大可看更多长输出，但会增加渲染量。 |
| `extraExpandedPreviewMaxLines` | `12000` | <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>O</kbd> 进入额外详情模式后的行数上限；偶尔查大段输出时用，不必同时提高普通展开上限。 |
| `extraToolOutputExpanded` | `false` | 启动时就开启额外详情模式，使用更高的展开上限；通常保留关闭，需要时按 <kbd>Ctrl</kbd>+<kbd>Shift</kbd>+<kbd>O</kbd> 切换。 |
| `thinkingMode` | `live` | `live` 仅流式思考时展开，结束即收起；`full` 始终展开。只关心结论选前者，要回看推理选后者。 |
| `bashCollapsedLines` | `10` | bash 正文预览的行数上限，主要配合 `preview` 模式；调大多看日志，`0` 不显示正文预览。 |
| `bashCommandPreviewLines` | `8` | 运行中或失败后显示多少行脚本源文，不是命令输出；`0` 关闭折叠态脚本预览，展开仍可查看。 |
| `liveToolPreviewLines` | `5` | 工具运行时显示的预览行数，bash 取末尾几行；要看进度可调大，仅在 `liveToolPreview` 开启时有用。 |
| `diffCollapsedLines` | `24` | 折叠状态最多展示多少行 diff；小改动可调大直接看完，大改动多时调小避免刷屏。 |

**行为与主题**

| 参数 | 默认 | 说明 |
|------|------|------|
| `liveToolPreview` | `true` | 工具未结束就显示少量输出，方便看长命令进度；关闭可减少运行中的界面更新，不影响工具执行。 |
| `diffTheme` | 不设 | diff 配色预设：`default` 原始配色、`midnight` 适合黑底、`neon` 对比更强；留空随 pi 主题适配。 |
| `diffColors` | `{}` | 按字段覆盖 diff 颜色，如 `fgAdd` / `fgDel` 改增删文字色，值用十六进制颜色；只覆盖不满意的项，优先级高于预设。 |
| `showTruncationHints` | 未读取 | 1.0.86 只声明了此键，未读取；不能用它隐藏截断提示，是否提示由各渲染器决定。 |

</details>

以 1.0.86 的 `extensions/index.ts` 为准，表中标注“未读取”的键无需配置。行数设置只改变界面预览，不改变模型收到的工具结果；各渲染器使用的上限不同，提高 <kbd>Ctrl</kbd>+<kbd>O</kbd> 上限不一定能展开全文。

## pi-claude-code-tui —— 启动页头与输入框（本地定制）

> **一句话**：换上 Claude Code 风格的启动页头（动画 π 徽标、当前模型、思考档位、工作目录），输入框改成全封闭圆角边框\
> **收益**：启动时一眼看清当前模型和思考档位\
> **代价**：本地定制版不走商店，上游更新要手动合并；没有配置文件，想定制只能改源码\
> **适合**：喜欢 Claude Code 外观的人。**不必装**：习惯 pi 原生界面\
> **改动深度**：只改启动页头和输入框外观，`/use-default-tui` 随时还原

商店：[pi.dev/packages/pi-claude-code-tui](https://pi.dev/packages/pi-claude-code-tui) · 仓库：[Phoobobo/pi-claude-code-tui](https://github.com/Phoobobo/pi-claude-code-tui) · 本机版本：本地定制（基于上游 v0.1.13）

pi 默认的启动画面信息很少：一个横幅，下面就是输入框。pi-claude-code-tui 换上 Claude Code 风格的启动页头，显示动画 π 徽标、当前模型、思考档位、工作目录和常用命令提示；输入框也改成 Codex 风格的全封闭圆角边框（两侧带 │）。

安装（本地定制版，不走 npm 商店）：

```bash
cp -r plugins/pi-claude-code-tui ~/.pi/agent/extensions/
pi   # 重启生效；会话内 /use-claude-code-tui 手动应用，/use-default-tui 还原（选择持久化，见下）
```

上游版本没有配置文件，要定制只能改源码。本地版在上游 v0.1.13 基础上改了六处，每处都有源码注释（五处带 `LOCAL MODIFICATION` 标记，提示分割线那处是普通注释），并把界面选择保存到 `~/.pi/agent/pi-claude-code-tui.json`，由插件自己读写：

| 改动 | 效果 |
|------|------|
| 徽标单元格 `███` → `██` | 徽标整体更窄更轻 |
| 标题/徽标颜色从主题 accent 改为固定灰白 `#EEEEEE` | 页头观感稳定，不随主题切换变色 |
| 提示分割线从“最大 22 字符”改为拉满右栏宽度减 1 | 与左栏边距对齐 |
| 输入框从半开放边框（只有上下圆角边）改为全封闭圆角边框 | 两侧 │ 边线，新增 padOnly 辅助函数保证边框不截断编辑器行 |
| `/use-claude-code-tui` / `/use-default-tui` 的选择持久化到 `~/.pi/agent/pi-claude-code-tui.json` | 重启后保持所选界面；上游两个命令都是会话级，重启即回 |
| 移除输入框光标 restyle | 保留 pi 原生反色光标 |

当前界面选择（[`config/pi-claude-code-tui.json`](../config/pi-claude-code-tui.json)）：

```json
{
  "useDefault": true
}
```

`useDefault: true` 表示当前用 pi 原生界面，定制外观由 `/use-claude-code-tui` 重新启用。

完整的定制说明和上游信息见 [`plugins/pi-claude-code-tui/INSTALL.md`](../plugins/pi-claude-code-tui/INSTALL.md)。

## dark-classic —— 本地配色主题

pi 自带 `dark`、`light`、`system` 三个主题。本机用的是自定义主题 `dark-classic`：它复制了 pi 0.87.1 内置 `dark` 的配色，以后 pi 升级改了内置配色，这里仍保持原样。自定义主题放在 `~/.pi/agent/themes/`，文件名要和主题的 `name` 一致；pi 只对这个目录下的当前主题做热重载。

安装（副本见 [`config/themes/dark-classic.json`](../config/themes/dark-classic.json)）：

```bash
mkdir -p ~/.pi/agent/themes
cp config/themes/dark-classic.json ~/.pi/agent/themes/
```

在 `~/.pi/agent/settings.json` 里写 `"theme": "dark-classic"` 即可启用（见 [ref-settings.md](ref-settings.md)）。pi-claude-code-ui 开着 `themeAdaptive`，直接沿用这个主题的配色；pi-claude-code-tui 的页头固定为灰白色，不随主题变化。

## pi-token-speed —— 速度仪表

> **一句话**：流式输出时，在状态栏实时显示 TPS（每秒 token 数）、首 token 延迟等读数，按速度分四档着色\
> **收益**：换模型、调思考档位、换网络节点后，速度变化一眼可见\
> **代价**：基本没有，状态栏多占一块位置\
> **适合**：常换模型或网络节点、在意响应速度的人。**不必装**：不关心速度\
> **改动深度**：只在状态栏显示读数

商店：[pi.dev/packages/pi-token-speed](https://pi.dev/packages/pi-token-speed) · 仓库：[gsanhueza/pi-token-speed](https://github.com/gsanhueza/pi-token-speed) · 本机版本 `0.11.0`

响应速度最影响使用体感，pi 却不显示它。pi-token-speed 在流式输出时，把 TPS（每秒 token 数）、TTFT（首 token 延迟）和统计数据实时显示在状态栏，按速度分四档着色。换模型、调思考档位、换网络节点，速度变化一眼可见。

配置写在 `~/.pi/agent/settings.json` 的 `tokenSpeed` 段（pi-claude-code-ui 用的是另一个文件 `~/.pi/settings.json`）。会话内可以用 `/tps` 菜单随时调整，非法值自动回退为默认值。

**我的配置**（settings.json 的 tokenSpeed 段）：

```json
{
  "display": "tps",
  "useProviderTokens": true,
  "slidingWindow": 1500,
  "countStrategy": "estimate",
  "endTpsBehavior": "average",
  "icon": "",
  "updateInterval": 100,
  "thresholds": {
    "slow": 0,
    "medium": 30,
    "fast": 60,
    "blazing": 90
  }
}
```

- 阈值 30/60/90 TPS，分别是中速、快速、极速三档的起点，比默认值（15/30/45）高一倍；
- `slidingWindow: 1500`：用 1.5 秒的滑动窗口让读数更平稳；
- `useProviderTokens: true`：优先用供应商返回的 token 数，拿不到时按 `countStrategy: estimate` 从文本估算；
- `icon: ""`：隐藏图标；
- `updateInterval: 100`：状态栏每 100ms 刷新一次，测速本身照常逐条计算。

新格式把阈值放在 `thresholds`、颜色放在 `colors` 下。旧的扁平键（如 `tpsMedium`、`colorFast`）仍然兼容，但启动时会警告；在 `/tps` 里保存任意一项设置，就会自动迁移到新格式。

### 参数

档位阈值左闭右开，最后一档向上开放；阈值须严格递增。

**常用参数**

| 参数 | 默认 | 说明 |
|------|------|------|
| `display` | `tps` | `tps` 只显示速度；`ttft` 加首 token 等待；`stats` 加总 token 和耗时；`full` 全显示。排查响应慢选 `ttft` 或 `full`。 |
| `thresholds.medium` | `15` | 达到多少 TPS 算中速；调高会让更多读数仍归慢速，按你能接受的最低速度设置。 |
| `thresholds.fast` | `30` | 达到多少 TPS 算快速，必须高于中速阈值；模型普遍很快、颜色总是一档时可调高。 |
| `thresholds.blazing` | `45` | 极速档起点，必须高于快速阈值；设为明显超出日常速度的水平，方便识别真正的高吞吐。 |
| `slidingWindow` | `1000`（范围 100–30000） | 用最近多少毫秒的数据算实时速度；调大读数平稳但反应慢，调小更容易看到突发和停顿。 |
| `useProviderTokens` | `false` | 开启后优先采用供应商上报的 token 数，缺失则回退到 `countStrategy`；供应商计数可靠时开，想统一用本地算法时关。 |
| `countStrategy` | `direct` | `direct` 每个流片段记 1 token，快但受分块方式影响；`estimate` 按文本估算，通常更便于比较不同接口。 |
| `endTpsBehavior` | `average` | 流结束后，`average` 显示全程平均速度，适合比较模型；`last` 保留最后窗口的速度，适合观察收尾表现。 |
| `icon` | `⚡` | TPS 前缀图标，可填任意字符；空字符串隐藏，适合窄终端。 |

<details>
<summary><b>其余参数（7 项）</b></summary>

**档位阈值**

| 参数 | 默认 | 说明 |
|------|------|------|
| `thresholds.slow` | `0` | 慢速档下界，单位 TPS；通常保留 `0`，与其余阈值一起只影响分色，不影响测速。 |

**档位颜色**

| 参数 | 默认 | 说明 |
|------|------|------|
| `colors.slow` | `#ff4444` | 慢速档颜色，十六进制格式；默认红色，可按终端背景调整。 |
| `colors.medium` | `#ffaa00` | 中速档颜色，十六进制格式；默认橙色。 |
| `colors.fast` | `#00ff88` | 快速档颜色，十六进制格式；默认绿色。 |
| `colors.blazing` | `#44ddff` | 极速档颜色，十六进制格式；默认青色，宜与快速档区分。 |

**显示**

| 参数 | 默认 | 说明 |
|------|------|------|
| `updateInterval` | `0` | 状态栏刷新间隔（毫秒），`0` 每个流片段都刷新；调大减少重绘开销，测速仍逐片段计算。 |
| `providerOverrides` | `{}` | 按供应商 ID 单独覆盖参数，适合不同渠道的速度分档或计数差异；`thresholds` / `colors` 逐项合并，未写项继承基础值。 |

</details>

`providerOverrides` 的键要用供应商 ID（如 `openai-codex`），不是模型名；可用 `/tps overrides` 编辑。显示参数立即生效，窗口和计数参数从下一次流式响应开始生效，避免中途改变测速口径。

## keybindings.json —— 快捷键

pi 的快捷键配置在 `~/.pi/agent/keybindings.json`。这里只改了“复制消息”一个动作（[`config/keybindings.json`](../config/keybindings.json)）：

```json
{
  "app.message.copy": ["super+c"]
}
```

`super+c` 在 macOS 上就是 <kbd>Cmd</kbd>+<kbd>C</kbd>，替换掉这个动作默认的 <kbd>Ctrl</kbd>+<kbd>X</kbd>。具体行为：

- 普通会话里，复制最后一条助手消息；`/tree` 里，复制选中的消息。
- 全屏模式下，`fullscreenCopyOnSelect` 默认为 true：选中文字即自动复制，<kbd>Cmd</kbd>+<kbd>C</kbd> 复制最后一条助手消息。设为 `false` 后（本配置就是这样，见 [ref-settings.md](ref-settings.md)），有选区时 <kbd>Cmd</kbd>+<kbd>C</kbd> 复制选区。

终端要能单独上报 Super 修饰键，一般靠 Kitty 键盘协议。如果按键被终端截走，可以改用 `/copy` 复制最后一条助手消息。改完后运行 `/reload`，用 `/hotkeys` 确认绑定，再按 <kbd>Cmd</kbd>+<kbd>C</kbd> 检查剪贴板。
