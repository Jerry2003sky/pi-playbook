# 进阶阶段：效率与交互

本阶段解决体验与效率问题（定位见 [01-理念与路线.md](01-理念与路线.md)）：搜索慢，效率问题不可见，模型拿不准时瞎猜。四个插件相互独立，各治各的病，没有依赖顺序。

本页内容：**@ff-labs/pi-fff**（搜索增强）· **pi-context-view**（上下文观察）· **pi-cache-graph**（缓存监控）· **@juicesharp/rpiv-ask-user-question**（结构化提问）

## @ff-labs/pi-fff —— 搜索增强

> 商店：[pi.dev/packages/@ff-labs/pi-fff](https://pi.dev/packages/@ff-labs/pi-fff) · 仓库：[dmtrKovalenko/fff](https://github.com/dmtrKovalenko/fff)

内置的 find/grep 每次全盘扫、结果按字母序排。大型仓库里一条命令等十几秒，命中的文件还排在几十条结果后面。

fff 把搜索换成 Rust 原生引擎：`fffind` 模糊文件名搜索加 frecency 排序（访问越频繁的文件排越前），`ffgrep` 内容搜索带光标分页，`fff-multi-grep` 多模式 OR 搜索。索引在会话启动时后台构建，git 感知，本地运行不上传文件。用一段时间后 frecency 生效，搜索经常一次命中。

安装：

```bash
pi install npm:@ff-labs/pi-fff@0.10.5
```

它没有 settings.json 配置段，参数全走 CLI 标志或环境变量，优先序 CLI > 环境变量 > 默认。

> **⚠️ 云盘目录警告，装 fff 前先处理。** fff 启动时会在后台给家目录建索引（`--fff-enable-home-scan` 默认开），索引器遍历家目录里的每个文件。如果家目录里有 Dropbox/OneDrive 这类云盘，“仅在线”文件（本地只有占位符）会被索引逐个触发真实下载——整个云盘被拖回本地，流量、磁盘、时间全部浪费，索引文件还可能被同步回云端。踩一次就是一次全盘下载。
>
> 排除方式：fff 的索引器遵循 `.gitignore` 和 `.ignore` 文件（gitignore 语法，扫描时逐目录读取）。在家目录放一个 `~/.ignore`，把云盘路径写进去，索引器就会跳过：
>
> ```gitignore
> # ~/.ignore —— 云盘目录，按实际路径写
> /Library/CloudStorage/
> /Dropbox
> /OneDrive
> ```
>
> `.ignore` 是给 fff 这类本地工具看的忽略文件，不影响 git；写 `.gitignore` 也有效，但会同时作用于 git 仓库，一般不混用。

**我的配置**：fff 全默认。`~/.ignore` 的实际内容：

```gitignore
/Library/
/Pictures/
/Applications/
/Library/CloudStorage/
```

云盘路径 `/Library/CloudStorage/` 在列，家目录索引会跳过它；`/Library`、`/Pictures`、`/Applications` 是顺手排掉的三个大目录。配套地，我在全局 AGENTS.md 里写了搜索纪律：优先用 fff 工具、fallback 条件写明（见 [09-agents-md.md](09-agents-md.md)）。

**常用参数**

| 参数 | 作用 |
|------|------|
| `FFF_ENABLE_HOME_SCAN` | 是否允许索引整个家目录；家目录有大树（内核源码、构建产物）时关掉，否则启动后后台索引要跑很久 |

**参数详解**

模式：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `--fff-mode` | `tools-and-ui` / `tools-only` / `override` | 注册方式：工具+补全 / 只加工具 / 替换内置 find/grep；改完重启生效 |

数据：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `--fff-frecency-db` / `FFF_FRECENCY_DB` | string，`~/.pi/agent/fff/` | frecency 数据文件位置 |
| `--fff-history-db` / `FFF_HISTORY_DB` | string，`~/.pi/agent/fff/` | 历史数据文件位置 |

这个默认目录存的是个人使用数据（访问频率、搜索历史），入库时注意 gitignore。

扫描：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `--fff-enable-root-scan` | bool，false | 是否允许从 `/` 建索引 |
| `--fff-enable-home-scan` | bool，true | 从 `$HOME` 启动时是否索引家目录 |

## pi-context-view —— 上下文观察

> 商店：[pi.dev/packages/pi-context-view](https://pi.dev/packages/pi-context-view) · 仓库：[dimk90/pi-context-view](https://github.com/dimk90/pi-context-view)

上下文是怎么被吃掉的，平时不可见：哪类工具输出最占地方、哪些扩展悄悄注入了指令、系统提示有多大，都没有一个直观的视图。

pi-context-view 提供两个命令：`/context usage` 按工具/技能/消息分类显示上下文占用，可放大到 1M 窗口细目；`/context injections` 列出会话启动时注入的隐藏内容（系统提示、工具定义、扩展塞进来的指令）。它对模型上下文零注入——不添加任何指令，纯界面层，装上没有副作用。

安装：

```bash
pi install npm:pi-context-view@0.4.2
```

无配置参数，开箱即用。命令族：`/context`、`/context usage`、`/context injections`。

**我的配置**：全默认。跑长会话时用 `/context usage` 看各分类占用变化，剪枝前后的差异一目了然。

## pi-cache-graph —— 缓存观测

> 商店：[pi.dev/packages/pi-cache-graph](https://pi.dev/packages/pi-cache-graph) · 仓库：[championswimmer/pi-cache-graph](https://github.com/championswimmer/pi-cache-graph)

提示缓存是模型成本的大头：命中部分按折扣计费，前缀稳定就能省钱。但缓存命中率平时不可见，剪枝参数怎么影响缓存更是黑盒。

pi-cache-graph 提供三个命令：`/cache graph` 看缓存命中率随轮次变化的曲线（数字键切视图），`/cache stats` 看逐消息 token/缓存明细，`/cache export` 导出 CSV。命中率的定义是 cacheRead / (input + cacheRead + cacheWrite)。

安装：

```bash
pi install npm:pi-cache-graph@1.0.2
```

无配置参数。`/cache export` 的 CSV 落在项目根目录。

**我的配置**：全默认。它与剪枝是配套关系：剪枝把历史工具输出摘要化会改变前缀内容，直接影响缓存命中。用 `/cache graph` 能直观看到命中率随轮次的变化——这也是 [01-理念与路线.md](01-理念与路线.md) 里“运行状态要可见”的体现。

## @juicesharp/rpiv-ask-user-question —— 结构化提问

> 商店：[pi.dev/packages/@juicesharp/rpiv-ask-user-question](https://pi.dev/packages/@juicesharp/rpiv-ask-user-question) · 仓库：[juicesharp/rpiv-mono](https://github.com/juicesharp/rpiv-mono)

模型遇到需求不明的情况，两个选择都不好：瞎猜，方向可能整个做错；停下来用自然语言问，用户要打一大段字，来回几轮才问清楚。

这个插件给模型一个 `ask_user_question` 工具：弹结构化问卷，一次最多 4 题、每题 2–4 个带说明的选项，选项可以带 markdown 预览。用户点选后，选择以结构化数据交回模型。模型能提供高质量候选答案，用户点一下就行。非交互环境（无 TTY）会自动移除这个工具，脚本场景不会卡死。RPC/ACP 宿主（VS Code、Zed）下走原生对话框。

安装：

```bash
pi install npm:@juicesharp/rpiv-ask-user-question@2.6.2
```

配置写在 `~/.config/rpiv-ask-user-question/config.json`，只读，非法值静默回退默认。

**我的配置**：全默认（配置文件不存在）。

**常用参数**

| 参数 | 作用 |
|------|------|
| `collapseKey` | 折叠/展开问卷的按键（默认 `ctrl+]`） |
| `guidance.promptSnippet` | 模型看到的工具一行简介，控制提问积极程度 |
| `guidance.promptGuidelines` | 给模型的提问准则 |

**参数详解**

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `collapseKey` | string，`ctrl+]` | 折叠/展开按键；`"off"` 禁用 |
| `guidance.description` | string | 整体替换工具描述 |
| `guidance.promptSnippet` | string | 工具一行简介 |
| `guidance.promptGuidelines` | string | 提问准则（默认四条） |

工具行为约束（非配置，是硬限制）：单次 ≤ 4 题、每题 2–4 选项、选项 label ≤ 60 字符；`Other`、`Type something.` 等是保留标签，不能自己写。
