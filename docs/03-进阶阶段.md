# 进阶阶段：效率与交互

本阶段解决体验与效率问题（定位见 [01-理念与路线.md](01-理念与路线.md)）：搜索慢，消耗看不见，模型拿不准时乱猜。四个插件各管一摊，互不依赖，安装顺序随意。

本页内容：**@ff-labs/pi-fff**（搜索增强）· **pi-context-view**（上下文观察）· **pi-cache-graph**（缓存监控）· **@juicesharp/rpiv-ask-user-question**（结构化提问）

## @ff-labs/pi-fff —— 搜索增强

> 商店：[pi.dev/packages/@ff-labs/pi-fff](https://pi.dev/packages/@ff-labs/pi-fff) · 仓库：[dmtrKovalenko/fff](https://github.com/dmtrKovalenko/fff)

内置 find/grep 每次都全盘扫描，结果按字母序排列。大仓库里一条命令要等十几秒，想要的文件还常常排在几十条结果之后。

fff 把搜索换成 Rust 原生引擎，支持 frecency 排序（常用、最近用过的文件排在前面）、游标分页和多模式 OR 搜索。索引在会话启动时于后台构建，能识别 git，全程在本地运行，不上传文件。用上一段时间，frecency 积累起来，搜索经常一次命中。

它有三种注册方式：`tools-and-ui`、`tools-only`、`override`。我用 `override`：内置 `grep`/`find` 的名字和参数保持原样，底层实现整体换成 FFF，frecency 和分页自动生效。另有可选的 `multi_grep` 工具，提供 Aho-Corasick 多模式 OR 搜索，需要启动前设置 `PI_FFF_MULTIGREP=1`；本机保持默认关闭。

安装：

```bash
pi install npm:@ff-labs/pi-fff@0.11.0
```

配置文件是 `~/.pi/agent/pi-fff.json`，自带 JSON Schema，编辑器里有补全和校验。也可以用命令行标志或环境变量配置，优先级：命令行 > 环境变量 > pi-fff.json > 默认值。

> **⚠️ 装 fff 之前，先处理云盘目录。** 从家目录启动 pi 时，fff 默认会在后台索引整个家目录（`--fff-enable-home-scan` 默认开启）。云盘里“仅在线”的文件在本地只是占位符，一旦被索引读取内容，就可能触发下载，白白消耗流量、磁盘和时间。所以要先写好忽略规则，再让它扫描家目录。注意：`warnOnHomeDirScan` 只管提示，是否扫描由 `enableHomeDirScanning` 决定。
>
> 排除方法：fff 的索引器遵守 `.gitignore` 和 `.ignore`（gitignore 语法，扫描时逐级读取）。在家目录放一个 `~/.ignore`，写上云盘路径，索引器就会跳过：
>
> ```gitignore
> # ~/.ignore —— 云盘目录，按实际路径写
> /Library/CloudStorage/
> /Dropbox
> /OneDrive
> ```
>
> `.ignore` 专供 fff、rg 这类本地工具读取，git 不认它。写进 `.gitignore` 同样有效，但会连带影响 git，一般分开放。

**我的配置**：`pi-fff.json` 只设了覆盖模式和家目录扫描提示，其余用默认值：

```json
{
  "$schema": "https://raw.githubusercontent.com/dmtrKovalenko/fff/main/packages/pi-fff/pi-fff.schema.json",
  "mode": "override",
  "warnOnHomeDirScan": false
}
```

`mode: override` 直接替换内置 `grep`/`find` 的实现，工具名和参数沿用内置版本。会话内可以用 `/fff-mode` 切换，切完要 `/reload` 才会重新注册工具。`warnOnHomeDirScan: false` 关掉家目录索引的启动提示：云盘已经在 `.ignore` 里排除，这条提示没有新信息，索引照常进行。`~/.ignore` 的实际内容：

```gitignore
/Library/
/Pictures/
/Applications/
/Library/CloudStorage
/Dropbox
/OneDrive
```

三条云盘规则（`/Library/CloudStorage`、`/Dropbox`、`/OneDrive`）覆盖了全局 AGENTS.md 列出的四个云盘路径，CloudStorage 下的两个由父目录规则一并覆盖。`/Library`、`/Pictures`、`/Applications` 也一起排除。

全局 AGENTS.md 的搜索纪律也按 override 模式重写了：内置 find/grep 就是 FFF，用它还是用 bash 由模型自己权衡；bash 里优先 fd/rg，并注意语法差异；另外记下一个隐藏路径的盲区。详见 [09-agents-md.md](09-agents-md.md)。

### 常用参数

| 参数 | 作用 |
|------|------|
| `FFF_ENABLE_HOME_SCAN` | 是否允许索引整个家目录；家目录里有大目录树（内核源码、构建产物）时建议关掉，否则启动后的后台索引会跑很久 |

### 参数详解

模式：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `--fff-mode` | `tools-and-ui` / `tools-only` / `override` | 注册方式：工具+补全 / 只加工具 / 替换内置 find/grep；改完重启生效 |

数据：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `--fff-frecency-db` / `FFF_FRECENCY_DB` | string，`~/.pi/agent/fff/` | frecency 数据文件位置 |
| `--fff-history-db` / `FFF_HISTORY_DB` | string，`~/.pi/agent/fff/` | 历史数据文件位置 |

不显式配置路径时，优先使用已有的 fff.nvim 数据库（`~/.cache/nvim/fff_nvim`、`~/.local/share/nvim/fff_queries`），找不到才用 `~/.pi/agent/fff/`。这样在 Neovim 里积累的 frecency 可以直接复用。这些目录存的是个人使用数据（访问频率、搜索历史），纳入版本管理时记得加进 gitignore。

扫描：

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `--fff-enable-root-scan` | bool，false | 是否允许从 `/` 建索引 |
| `--fff-enable-home-scan` | bool，true | 从 `$HOME` 启动时是否索引家目录 |
| `--fff-warn-home-scan` | bool，true | 索引家目录时弹警告通知；保留索引但嫌吵可关 |
| `--fff-follow-symlinks` | bool，true | 是否穿过目录符号链接索引（worktree、stow 布局靠链接触达文件）；想只走真实树可关 |

以上标志在 `pi-fff.json` 中的对应键名：`fff-mode`→`mode`、`fff-frecency-db`→`frecencyDbPath`、`fff-history-db`→`historyDbPath`、`fff-enable-root-scan`→`enableFsRootScanning`、`fff-enable-home-scan`→`enableHomeDirScanning`、`fff-warn-home-scan`→`warnOnHomeDirScan`、`fff-follow-symlinks`→`followSymlinks`。

## pi-context-view —— 上下文观察

> 商店：[pi.dev/packages/pi-context-view](https://pi.dev/packages/pi-context-view) · 仓库：[dimk90/pi-context-view](https://github.com/dimk90/pi-context-view)

上下文被什么占掉了，平时看不到：哪类工具输出最占地方，哪些扩展悄悄注入了指令，系统提示有多大，都没有直观的视图。

pi-context-view 补上了这块：

- `/context usage`：按工具、技能、消息分类显示上下文占用，可以放大查看 1M 窗口的细目；
- `/context injections`：列出会话启动时注入的隐藏内容，包括系统提示、工具定义和扩展塞进来的指令。

它只工作在界面层，不往模型上下文里加任何东西，装上零副作用。

安装：

```bash
pi install npm:pi-context-view@0.6.0
```

不配置就能用。`/context config` 会生成全局配置文件 `~/.pi/agent/extensions/pi-context-view.json`，可调配色和占用图尺寸。全部命令：`/context`、`/context usage`、`/context injections`、`/context config`。

**我的配置**：全默认。长会话里用 `/context usage` 观察各类占用的变化，剪枝前后的差别一眼就能看出来。

## pi-cache-graph —— 缓存观测

> 商店：[pi.dev/packages/pi-cache-graph](https://pi.dev/packages/pi-cache-graph) · 仓库：[championswimmer/pi-cache-graph](https://github.com/championswimmer/pi-cache-graph)

提示缓存直接决定模型成本：命中的部分按折扣计费，前缀越稳定越省钱。可平时看不到命中率，剪枝参数怎么影响缓存更是无从得知。

pi-cache-graph 提供三个命令：

- `/cache graph`：命中率随轮次变化的曲线，数字键切换视图；
- `/cache stats`：逐条消息的 token 与缓存明细；
- `/cache export`：导出 CSV。

命中率 = cacheRead / (input + cacheRead + cacheWrite)。

安装：

```bash
pi install npm:pi-cache-graph@1.0.2
```

没有配置参数。`/cache export` 导出的 CSV 放在项目根目录。

**我的配置**：全默认。它和剪枝要搭配着用：剪枝把历史工具输出换成摘要，会改动前缀，直接影响缓存命中。调剪枝参数时，用 `/cache graph` 盯着命中率曲线，就能看到效果——这正是 [01-理念与路线.md](01-理念与路线.md) 里“让运行状态看得见”的落地。

## @juicesharp/rpiv-ask-user-question —— 结构化提问

> 商店：[pi.dev/packages/@juicesharp/rpiv-ask-user-question](https://pi.dev/packages/@juicesharp/rpiv-ask-user-question) · 仓库：[juicesharp/rpiv-mono](https://github.com/juicesharp/rpiv-mono)

需求不明确时，模型的两条路都不理想：自己猜，可能整个方向做错；用自然语言问，用户得打一大段字，来回好几轮才说清楚。

这个插件给模型一个 `ask_user_question` 工具，用来弹出结构化问卷：一次最多 4 题，每题 2–4 个带说明的选项，选项还能附 markdown 预览。模型负责给出靠谱的候选项，用户点选即可，结果以结构化数据交回模型。

非交互环境（无 TTY）下，这个工具会被自动移除，脚本运行不会卡住；在 VS Code、Zed 这类 RPC/ACP 宿主里，问卷以原生对话框呈现。

安装：

```bash
pi install npm:@juicesharp/rpiv-ask-user-question@2.11.0
```

配置文件是 `~/.config/rpiv-ask-user-question/config.json`（若存在 `$XDG_CONFIG_HOME/rpiv-ask-user-question/config.json` 则优先读它），插件只读不写。非法值回退为默认值，JSON 解析失败时在 stderr 打印警告。

**我的配置**：全默认（配置文件不存在）。

### 常用参数

| 参数 | 作用 |
|------|------|
| `collapseKey` | 折叠/展开问卷的按键（默认 `ctrl+]`） |
| `guidance.promptSnippet` | 模型看到的工具一行简介，控制提问积极程度 |
| `guidance.promptGuidelines` | 给模型的提问准则 |

### 参数详解

| 参数 | 类型/默认 | 说明 |
|------|-----------|------|
| `collapseKey` | string，`ctrl+]` | 折叠/展开按键；`"off"` 禁用 |
| `guidance.description` | string | 整体替换工具描述 |
| `guidance.promptSnippet` | string | 工具一行简介 |
| `guidance.promptGuidelines` | string 列表 | 提问准则（默认四条） |

另有几条写死的限制，无法配置：单次最多 4 题，每题 2–4 个选项，选项 label 不超过 60 字符；`Other`、`Type something.` 等是保留标签，模型不能使用。
