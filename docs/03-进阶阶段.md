# 进阶阶段：效率与交互

## @ff-labs/pi-fff —— 搜索增强

> **一句话**：用 Rust 引擎替换内置的 find/grep，结果按“常用 + 最近用过”排序\
> **收益**：大仓库里不用再等全盘扫描；用一段时间后，搜索经常一次命中\
> **代价**：会话启动后在后台建索引；从家目录启动会索引整个家目录，要先排除云盘目录，否则可能触发下载\
> **适合**：常在大仓库里搜代码的人。**不必装**：项目都很小，内置搜索已经够用\
> **改动深度**：`override` 模式替换内置 grep/find 的实现，工具名和参数不变；另外两种模式只新增工具，不动内置

商店：[pi.dev/packages/@ff-labs/pi-fff](https://pi.dev/packages/@ff-labs/pi-fff) · 仓库：[dmtrKovalenko/fff](https://github.com/dmtrKovalenko/fff) · 本机版本 `0.11.0`

内置 find/grep 每次都全盘扫描，结果按字母序排列。大仓库里一条命令要等十几秒，想要的文件还常常排在几十条结果之后。

fff 把搜索换成 Rust 原生引擎，支持 frecency 排序（常用、最近用过的文件排在前面）、游标分页和多模式 OR 搜索。会话启动时在后台建索引，能识别 git，全程在本地运行，不上传文件。用上一段时间，frecency 积累起来，搜索经常一次命中。

它有三种注册方式：`tools-and-ui`、`tools-only`、`override`。我用 `override`：内置 `grep`/`find` 的名字和参数保持原样，底层实现整体换成 FFF，frecency 和分页自动生效。另有可选的 `multi_grep` 工具，提供 Aho-Corasick 多模式 OR 搜索，需要启动前设置 `PI_FFF_MULTIGREP=1`；本机保持默认关闭。

配置文件是 `~/.pi/agent/pi-fff.json`，自带 JSON Schema，编辑器里有补全和校验。也可以用命令行标志或环境变量配置，优先级：命令行 > 环境变量 > pi-fff.json > 默认值。下文只列 JSON 键名，命令行和环境变量的写法见[插件 README](https://github.com/dmtrKovalenko/fff/tree/main/packages/pi-fff)。

> [!WARNING]
> **装 fff 之前，先处理云盘目录。** 从家目录启动 pi 时，fff 默认会在后台索引整个家目录（`enableHomeDirScanning` 默认开启）。云盘里“仅在线”的文件在本地只是占位符，一旦被索引读取内容，就可能触发下载，白白消耗流量、磁盘和时间。所以要先写好忽略规则，再让它扫描家目录。注意：`warnOnHomeDirScan` 只管提示，是否扫描由 `enableHomeDirScanning` 决定。
>
> 排除方法：fff 的索引器遵守 `.gitignore` 和 `.ignore`（gitignore 语法，扫描时逐级读取）。在家目录放一个 `~/.ignore`，写上云盘路径，索引器就会跳过：
>
> ```gitignore
> # ~/.ignore —— 云盘目录，按实际路径写
> /Library/CloudStorage/
> /Dropbox
> /OneDrive
> ```
>
> `.ignore` 专供 fff、rg 这类本地工具读取，git 不认它。写进 `.gitignore` 同样有效，但会连带影响 git，一般分开放。

**我的配置**：`pi-fff.json` 只设了覆盖模式和家目录扫描提示，其余用默认值：

```json
{
  "$schema": "https://raw.githubusercontent.com/dmtrKovalenko/fff/main/packages/pi-fff/pi-fff.schema.json",
  "mode": "override",
  "warnOnHomeDirScan": false
}
```

逐项说明：

- `mode: override`：直接替换内置 `grep`/`find` 的实现，工具名和参数沿用内置版本。会话内可以用 `/fff-mode` 切换，切完要 `/reload` 才会重新注册工具。
- `warnOnHomeDirScan: false`：关掉家目录索引的启动提示。云盘已经在 `.ignore` 里排除，这条提示没有新信息，索引照常进行。

`~/.ignore` 的实际内容：

```gitignore
/Library/
/Pictures/
/Applications/
/Library/CloudStorage
/Dropbox
/OneDrive
```

其中三条是云盘规则（`/Library/CloudStorage`、`/Dropbox`、`/OneDrive`），覆盖了全局 AGENTS.md 列出的四个云盘路径：CloudStorage 下的两个由父目录规则一并覆盖。其余三条排除 `/Library`、`/Pictures`、`/Applications`。

全局 AGENTS.md 的搜索纪律也按 override 模式重写了：内置 find/grep 就是 FFF，用它还是用 bash，由模型自己权衡。用 bash 时优先 fd/rg，并注意它们和 find/grep 的语法差异。另外还记下了一个隐藏路径的盲区。详见 [07-全局指令.md](07-全局指令.md)。

### 参数

**常用参数**

| 键（pi-fff.json） | 默认 | 说明 |
|------|------|------|
| `mode` | `tools-and-ui` | FFF 的注册方式；切入或切出 `override` 后，要 `/reload` 或重启才生效。<br>· `tools-and-ui`：新增 FFF 工具并接管 `@` 补全<br>· `tools-only`：只新增工具，保留原有补全<br>· `override`：替换内置 find/grep，适合不想改变工具名的情况 |
| `enableHomeDirScanning` | `true` | 从家目录启动时是否索引家目录。家目录里有内核源码、构建产物这类大目录树时可以关掉，免得后台索引跑很久。但关掉后，从家目录启动的会话会整体停用 FFF 搜索，退回内置 grep/find。 |
| `warnOnHomeDirScan` | `true` | 索引家目录时弹出警告。只管提示，不改变索引行为，嫌打扰可以关掉。 |

可选的 `multi_grep` 工具不走配置文件，只认环境变量 `PI_FFF_MULTIGREP=1`。

## pi-context-view —— 上下文观察

> **一句话**：按类别显示上下文被什么占掉，并列出最近一次请求里注入的隐藏内容\
> **收益**：哪类工具输出最占地方、扩展塞了哪些指令，一眼看清；剪枝前后的变化也看得出来\
> **代价**：基本没有。只工作在界面层，不往模型上下文里加任何东西\
> **适合**：常跑长会话、装了不少扩展、在调剪枝的人。**不必装**：会话都很短，不关心上下文构成\
> **改动深度**：只新增 `/context` 系列命令，不改 pi 的任何行为

商店：[pi.dev/packages/pi-context-view](https://pi.dev/packages/pi-context-view) · 仓库：[dimk90/pi-context-view](https://github.com/dimk90/pi-context-view) · 本机版本 `0.7.2`

上下文被什么占掉了，平时看不到：哪类工具输出最占地方，哪些扩展悄悄注入了指令，系统提示有多大，都没有直观的视图。

pi-context-view 补上了这块：

- `/context usage`：按工具、技能、消息分类显示上下文占用，可以放大查看 1M 窗口的细目；
- `/context injections`：列出最近一次请求里注入的隐藏内容，包括系统提示、工具定义和扩展塞进来的指令，扩展只在发给模型的请求里做的改动也能看到。

它只工作在界面层，不往模型上下文里加任何东西，装上零副作用。

不配置就能用。`/context config` 会生成全局配置文件 `~/.pi/agent/extensions/pi-context-view.json`，可调配色和占用图尺寸。全部命令：`/context`、`/context usage`、`/context injections`、`/context config`。

**我的配置**：全默认。长会话里用 `/context usage` 观察各类占用的变化，剪枝前后的差别一眼就能看出来。

## pi-cache-graph —— 缓存观测

> **一句话**：把提示缓存命中率画成随轮次变化的曲线，并给出逐条消息的明细\
> **收益**：缓存命中率看得见了，调剪枝参数时能直接看到它对成本的影响\
> **代价**：没有配置项，基本无负担；`/cache export` 会把 CSV 写到项目根目录\
> **适合**：用了剪枝插件、或在意 API 成本的人。**不必装**：不用剪枝，也不关心缓存命中\
> **改动深度**：只新增 `/cache` 系列命令，不改 pi 的任何行为

商店：[pi.dev/packages/pi-cache-graph](https://pi.dev/packages/pi-cache-graph) · 仓库：[championswimmer/pi-cache-graph](https://github.com/championswimmer/pi-cache-graph) · 本机版本 `1.0.2`

提示缓存直接决定模型成本：命中的部分按折扣计费，前缀越稳定越省钱。可平时看不到命中率，剪枝参数怎么影响缓存更是无从得知。

pi-cache-graph 提供三个命令：

- `/cache graph`：命中率随轮次变化的曲线，数字键切换视图；
- `/cache stats`：逐条消息的 token 与缓存明细；
- `/cache export`：导出 CSV。

命中率 = cacheRead / (input + cacheRead + cacheWrite)。

没有配置参数。`/cache export` 导出的 CSV 放在项目根目录。

**我的配置**：全默认。它和剪枝要搭配着用：剪枝把历史工具输出换成摘要，会改动前缀，直接影响缓存命中。调剪枝参数时，用 `/cache graph` 盯着命中率曲线，就能看到效果——这正是 [01-理念与路线.md](01-理念与路线.md) 里“让运行状态看得见”的落地。

## @juicesharp/rpiv-ask-user-question —— 结构化提问

> **一句话**：给模型一个弹出问卷的工具，需求不明确时让你点选，而不是让它瞎猜或让你打一大段字\
> **收益**：方向性的问题一次问清，少做错、少来回\
> **代价**：工具说明会进入模型上下文；模型问得太勤或太少时，要通过 `guidance.*` 调整\
> **适合**：常给出模糊需求、希望模型先确认再动手的人。**不必装**：主要在脚本等非交互环境里跑 pi（那里这个工具会被自动移除）\
> **改动深度**：只新增一个 `ask_user_question` 工具，不替换内置行为

商店：[pi.dev/packages/@juicesharp/rpiv-ask-user-question](https://pi.dev/packages/@juicesharp/rpiv-ask-user-question) · 仓库：[juicesharp/rpiv-mono](https://github.com/juicesharp/rpiv-mono) · 本机版本 `2.13.9`

需求不明确时，模型的两条路都不理想：自己猜，可能整个方向做错；用自然语言问，用户得打一大段字，来回好几轮才说清楚。

这个插件给模型一个 `ask_user_question` 工具，用来弹出结构化问卷：一次最多 4 题，每题 2–4 个带说明的选项，选项还能附 markdown 预览。模型负责给出靠谱的候选项，用户点选即可，结果以结构化数据交回模型。

非交互环境（无 TTY）下，这个工具会被自动移除，脚本运行不会卡住；在 VS Code、Zed 这类 RPC/ACP 宿主里，问卷以原生对话框呈现。

配置文件是 `~/.config/rpiv-ask-user-question/config.json`（若存在 `$XDG_CONFIG_HOME/rpiv-ask-user-question/config.json` 则优先读它），插件只读不写。非法值回退为默认值，JSON 解析失败时在 stderr 打印警告。

**我的配置**：全默认（配置文件不存在）。

### 参数

**常用参数**

| 参数 | 默认 | 说明 |
|------|------|------|
| `collapseKey` | `ctrl+]` | 折叠或展开问卷的快捷键。设为 `"off"` 只禁用快捷键，问卷照常可用。键盘布局按不出 <kbd>Ctrl</kbd>+<kbd>]</kbd> 时，可改成 `alt+o` 等组合。 |
| `guidance.promptSnippet` | 内置简介 | 系统提示里的一行工具简介，决定模型提问的积极程度，例如可以写“仅在关键需求不明确时提问”。 |
| `guidance.promptGuidelines` | 内置 4 条 | 提问准则列表，写了就整体替换默认准则，例如集中提问、推荐项放在首位。准则要写成具体的行为规则；空值或非法值会回退到默认。 |

`guidance.*` 改的是模型看到的提示，不是强制规则。它在工具注册时读取，改完要重启 Pi。自定义列表会整体替换默认准则，仍需要的默认要求得自己写回去。

另有几条写死的限制，无法配置：单次最多 4 题，每题 2–4 个选项，选项 label 不超过 60 字符。`Other`、`Type something.` 等是保留标签，模型不能使用。

| `guidance.description` | 内置说明 | 整体替换模型看到的工具说明，不与默认说明合并。只想调整提问习惯时，优先改上面两项。 |

## @narumitw/pi-btw —— 旁路提问

> **一句话**：用 `/btw` 开一条临时的旁路线程，带着主会话的上下文提问，问答默认不写进主会话\
> **收益**：主任务进行中也能插问细节，主会话的上下文和历史不受干扰；有用的答案再手动带回主输入框\
> **代价**：每次旁路提问多一次模型调用，选中的会话上下文（最多保留最近 40,000 字符）会发给所用模型；旁路线程只存在内存里，`/new`、`/resume`、`/reload` 或重启后就没了\
> **适合**：常在长任务中途冒出小问题的人。**不必装**：习惯一次只做一件事，或不介意在主会话里直接问\
> **改动深度**：只新增 `/btw` 命令和独立的旁路工作区，不改主会话的上下文和模型

商店：[pi.dev/packages/@narumitw/pi-btw](https://pi.dev/packages/@narumitw/pi-btw) · 仓库：[narumiruna/pi-extensions](https://github.com/narumiruna/pi-extensions) · 本机版本 `0.61.2`

在主会话里插问一个旁支问题，问答会一直留在上下文里，既占地方，也可能把模型带偏。新开一个会话来问，又拿不到当前的上下文。

pi-btw 用旁路线程解决这个问题：

- `/btw <问题>`：立即开一条旁路线程，以主会话当前分支为上下文作答，不切换主会话的分支；
- `/btw`：先打开管理界面，选择上下文、续接旧线程或修改设置。

旁路线程里可以追问、排队引导、搜索记录。问答默认不进主会话。需要时按 <kbd>Ctrl</kbd>+<kbd>R</kbd>，把最新回答、一段问答或整条线程带回主输入框。带回只填入输入框，不会自动发送；覆盖已有草稿前会先确认。

旁路工作区有全屏、旁路在左、旁路在右三种布局。分栏时，另一侧是 pi 原生的主会话视图，实时更新。拖动分隔线可以调整比例，旁路占 20%–80%，松开后自动保存。终端窄于 80 列时只显示旁路线程。

`/btw` 只支持 TUI 模式。旁路默认用当前会话的模型和思考档位，也可以在 `/btw` → Settings 里单独指定，不影响主会话。

配置文件是 `~/.pi/agent/pi-btw.json`，第一次在设置界面修改、记住档位或拖动分隔线时才创建。每次执行 `/btw` 都会重新读取，改完不用 `/reload`。

**我的配置**（[`config/pi-btw.json`](../config/pi-btw.json)）：

```json
{
  "fullscreenCopyOnSelect": false,
  "layout": "right-pane",
  "sidePaneRatio": 0.3813
}
```

- `layout: right-pane`：旁路线程放在右侧，左侧保留主会话视图。
- `sidePaneRatio: 0.3813`：旁路约占 38% 的宽度，是拖动分隔线后自动保存的值。
- `fullscreenCopyOnSelect: false`：旁路工作区里选中文字不自动复制，改用 pi 的复制快捷键。pi-btw 不继承 pi 本体的同名设置（settings.json 里同样设为 `false`），所以要在这里单独关。

### 参数

**常用参数**

| 参数 | 默认 | 说明 |
|------|------|------|
| `layout` | `fullscreen` | 旁路工作区的布局，下次打开或续接时生效。<br>· `fullscreen`：全屏<br>· `left-pane`：旁路在左，右侧显示主会话<br>· `right-pane`：旁路在右，左侧显示主会话 |
| `sidePaneRatio` | `0.5` | 分栏时旁路所占的宽度比例，限制在 0.2–0.8。一般直接拖动分隔线，松开后自动写入。 |
| `fullscreenCopyOnSelect` | `true` | 旁路工作区里选中即复制。想保留选区、用快捷键手动复制时关闭。 |

| `model` | 不设（用当前会话模型） | 旁路专用的模型，格式 `provider/model-id`。模型不存在或没有凭证时，警告并回退到会话模型；只影响 `/btw`。 |
| `thinkingLevel` | 不设（跟随主会话） | 旁路线程的起始思考档位。不设时，每条新线程从主会话当前的档位开始；设了就固定从这一档开始，超出模型能力的档位会被收窄。 |
| `rememberThinkingLevelChanges` | `true` | 固定档位时，旁路里用快捷键调的档位是否写回配置，作为下次的起始档位。跟随主会话时，快捷键的调整只在当前线程生效。 |

**快捷键**（写在 `keybindings` 对象里）

| 参数 | 默认 | 说明 |
|------|------|------|
| `exit` | `ctrl+c` | 取消并离开旁路工作区。改了别的键，<kbd>Ctrl</kbd>+<kbd>C</kbd> 仍然可以强制取消。 |
| `cycleThinkingLevel` | 跟随 pi 的 `app.thinking.cycle` | 在旁路里循环切换思考档位。 |
| `bringToMain` | `ctrl+r` | 回答完成后，打开“带回主会话”的选择界面。 |

</details>

快捷键也可以在 `/btw` → Settings 里修改，保存后下次打开旁路时生效。新快捷键不能占用普通输入键，也不能和 pi-btw 自己或 pi 的编辑、选择、搜索、滚动按键冲突。

## @dietrichgebert/ponytail —— 精简改动

> **一句话**：每轮往系统提示里加一套“懒惰的资深开发者”规则，让模型先找现成方案，只写完成任务所需的最少代码\
> **收益**：少出没人要的抽象、配置项和新依赖，diff 更短、更好审；改动波及的调用方、测试和配置仍然要求改全\
> **代价**：规则每次请求都占一段系统提示；模型会主动跳过它认为没必要的部分，真正需要的功能要说清楚\
> **适合**：觉得模型写的代码偏繁、爱过度设计的人。**不必装**：更想要完整、可扩展的实现，不希望模型主动删减\
> **改动深度**：通过扩展往系统提示里加一段规则，另外新增 6 个技能和 `/ponytail` 系列命令；不替换内置工具

商店：[pi.dev/packages/@dietrichgebert/ponytail](https://pi.dev/packages/@dietrichgebert/ponytail) · 仓库：[DietrichGebert/ponytail](https://github.com/DietrichGebert/ponytail) · 本机版本 `5.3.2`

模型写代码容易越写越多：顺手加的抽象、没人要的配置项、为几行功能引入的新依赖。每次都在提示里叮嘱一遍又太麻烦。

ponytail 把这套要求做成常驻规则。每轮开始前，它的扩展把当前档位的规则加进系统提示。规则的核心是一个先后顺序：先问这件事要不要做，再依次找代码库里现成的实现、标准库、已装的依赖，最后才写新代码。改动波及的调用方、测试、配置必须改全；信任边界的校验、防止数据丢失的错误处理、安全和无障碍都不能省。回复末尾用一两行说明跳过了什么、有什么风险。

本机用 git 方式安装，`settings.json` 的 `packages` 里写作 `git:github.com/DietrichGebert/ponytail`，版本号取自仓库里的 `package.json`。

档位有三个，按会话记录：

- `lite`：照要求做，只用一行指出更小的方案，由用户选择；
- `full`：完整规则，默认档位；
- `ultra`：动手前还会质疑需求，对没必要的部分提出反对。

整条输入只写 “stop ponytail” 或 “normal mode” 时，当前会话关闭 ponytail。全部命令：

- `/ponytail [lite|full|ultra|off]`：切换当前会话的档位；不带参数时开启，已开启则显示当前档位
- `/ponytail status`：显示当前档位和默认档位
- `/ponytail default <档位>`：修改默认档位，写入配置文件
- `/ponytail-review`：审查一次改动的逻辑、安全、负载、测试和性能，以及每一行是否必要
- `/ponytail-audit`：对整个仓库做一次质量审计，只出报告，不改代码
- `/ponytail-debt`：列出代码里所有 `shortcut:` 注释，形成一份技术债清单
- `/ponytail-gain`：显示插件基准测试测得的节省量
- `/ponytail-help`：速查档位、技能和命令

后五个命令分别转给同名技能执行。

配置文件是 `~/.config/ponytail/config.json`（设了 `XDG_CONFIG_HOME` 时改读其下的 `ponytail/config.json`），不在 `~/.pi/agent/` 下，所以 `config/` 没有收录副本。

**我的配置**（`~/.config/ponytail/config.json`）：

```json
{
  "hideStatus": true
}
```

- `hideStatus: true`：隐藏状态栏上的 ponytail 指示，规则照常生效。

### 参数

**常用参数**

| 参数 | 默认 | 说明 |
|------|------|------|
| `defaultMode` | `full` | 新会话的默认档位，也可以用 `/ponytail default <档位>` 修改。<br>· `off`：默认关闭<br>· `lite`：只提示更小的方案<br>· `full`：完整规则<br>· `ultra`：连需求一起质疑 |
| `hideStatus` | `false` | 隐藏状态栏指示，规则照常生效。状态栏位置紧张时开启。 |
| `quietStartup` | `false` | 不再弹出启动时的 “Ponytail loaded” 提示，规则照常生效。 |

三项都可以用环境变量 `PONYTAIL_DEFAULT_MODE`、`PONYTAIL_HIDE_STATUS`、`PONYTAIL_QUIET_STARTUP` 覆盖，环境变量优先于配置文件。
