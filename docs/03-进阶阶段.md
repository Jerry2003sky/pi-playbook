## @ff-labs/pi-fff —— 搜索增强

> **一句话**：用 Rust 引擎替换内置 find / grep，结果按“常用度 + 近期访问”排序\
> **收益**：大仓库里告别全盘扫描等待；积累一段时间后，搜索经常一次命中目标\
> **代价**：会话启动后会在后台建索引；从家目录启动会扫描整个家目录，须提前排除云盘目录，否则可能触发下载\
> **适合**：常在大仓库里检索代码的人。**不必装**：项目体量很小，内置搜索已经顺手\
> **改动深度**：`override` 模式直接替换内置 grep / find 的底层实现，工具名和参数不变；另外两种模式只新增工具，不动内置

商店：[pi.dev/packages/@ff-labs/pi-fff](https://pi.dev/packages/@ff-labs/pi-fff) · 仓库：[dmtrKovalenko/fff](https://github.com/dmtrKovalenko/fff) · 本机版本 `0.11.0`

内置 find / grep 每次都全盘扫描，结果按字母序排布。遇到大仓库，一条命令常要等十几秒，目标文件还往往埋在几十条无关结果后面。

fff 把搜索换成 Rust 原生引擎，支持 frecency 排序（常用、近期访问过的文件靠前）、游标分页与多模式 OR 搜索。它在会话启动时于后台建索引，能识别 git 规则，全程本地运行，不上传任何文件。用上一段时间后，frecency 数据积累起来，搜索往往一次直达。

插件提供三种注册方式：`tools-and-ui`、`tools-only`、`override`。本机选用 `override`：内置 `grep` / `find` 的名称与参数原封不动，底层整体换为 FFF，frecency 排序与分页自动生效。另有可选的 `multi_grep` 工具，提供 Aho-Corasick 多模式 OR 搜索，需启动前设 `PI_FFF_MULTIGREP=1`；本机保持默认关闭。

配置文件位于 `~/.pi/agent/pi-fff.json`，自带 JSON Schema，编辑器可提供补全和校验。也支持通过命令行标志或环境变量覆盖，优先级为：命令行 > 环境变量 > pi-fff.json > 默认值。下文仅列 JSON 键名，命令行与环境变量写法见[插件 README](https://github.com/dmtrKovalenko/fff/tree/main/packages/pi-fff)。

> [!WARNING]
> **装 fff 之前，务必先排除云盘目录。** 从家目录启动 pi 时，fff 默认会在后台索引整个家目录（`enableHomeDirScanning` 默认开启）。云盘里“仅在线”的文件在本地只是占位符，一旦被索引器读取内容就可能触发下载，白白耗费流量、磁盘和时间。务必先写好忽略规则，再允许它扫描家目录。注意：`warnOnHomeDirScan` 只控制提示，是否扫描由 `enableHomeDirScanning` 决定。
>
> 排除方法：fff 的索引器遵守 `.gitignore` 与 `.ignore`（gitignore 语法，扫描时逐级读取）。在家目录放置 `~/.ignore` 并写入云盘路径，索引器就会跳过：
>
> ```gitignore
> # ~/.ignore —— 云盘目录，按实际路径写
> /Library/CloudStorage/
> /Dropbox
> /OneDrive
> ```
>
> `.ignore` 专供 fff、rg 这类本地搜索工具读取，git 不会识别它。写进 `.gitignore` 同样有效，但会连带影响 git 行为，通常建议分开放。

**我的配置**：`pi-fff.json` 只设了覆盖模式与家目录扫描提示，其余保持默认：

```json
{
  "$schema": "https://raw.githubusercontent.com/dmtrKovalenko/fff/main/packages/pi-fff/pi-fff.schema.json",
  "mode": "override",
  "warnOnHomeDirScan": false
}
```

逐项说明：

- `mode: override`：直接替换内置 `grep` / `find` 的底层实现，工具名和参数沿用原生版本。会话内可用 `/fff-mode` 切换，切完须执行 `/reload` 重新注册工具。
- `warnOnHomeDirScan: false`：关闭家目录扫描启动提示。云盘目录已在 `.ignore` 中排除，提示并无新信息，索引照常运行。

`~/.ignore` 的实际内容：

```gitignore
/Library/
/Pictures/
/Applications/
/Library/CloudStorage
/Dropbox
/OneDrive
```

其中三条是云盘规则（`/Library/CloudStorage`、`/Dropbox`、`/OneDrive`），覆盖了全局 AGENTS.md 列出的四个云盘路径（CloudStorage 下的两个由父目录规则一并覆盖）；其余三条排除 `/Library`、`/Pictures`、`/Applications`。

全局 AGENTS.md 的搜索纪律也围绕 `override` 模式做了调整：内置 find / grep 本身即 FFF，检索时优先调用它们，而非 shell 命令；走 bash 时优先用 `fd` / `rg`，并留意它们与 find / grep 的语法差异，同时补充了隐藏路径的检索盲区，详见 [07-全局指令.md](07-全局指令.md)。

### 参数

**常用参数**

| 键（pi-fff.json） | 默认 | 说明 |
|------|------|------|
| `mode` | `tools-and-ui` | FFF 的注册方式；切入或切出 `override` 后须 `/reload` 或重启才生效。<br>· `tools-and-ui`：新增 FFF 工具并接管 `@` 补全<br>· `tools-only`：只新增工具，保留原有补全<br>· `override`：替换内置 find / grep，适合不想改变工具名的场景 |
| `enableHomeDirScanning` | `true` | 从家目录启动时是否索引家目录。若家目录内存有内核源码、大型构建产物等目录树，可将其关闭以免后台索引耗时过长；但关闭后，从家目录启动的会话会整体停用 FFF，退回内置 grep / find。 |
| `warnOnHomeDirScan` | `true` | 索引家目录时弹出警告。只控制提示，不改变索引行为，嫌打扰可关闭。 |

可选的 `multi_grep` 工具不走配置文件，仅认环境变量 `PI_FFF_MULTIGREP=1`。

<details>
<summary><b>其余参数（4 项）</b></summary>

| 键（pi-fff.json） | 默认 | 说明 |
|------|------|------|
| `frecencyDbPath` | 见下文 | 访问频率与近期访问记录的数据库路径，用于结果排序。想复用 Neovim 中的使用习惯，可指向同一份数据库。 |
| `historyDbPath` | 见下文 | “查询 → 所选文件”历史的数据库路径，用于优化重复查询的排序。仅在需要与其他 FFF 工具共享历史时修改。 |

| `followSymlinks` | `true` | 沿目录符号链接继续索引，适合 stow 这类软链布局，循环链接会自动截断。关闭可避开链接指向的大型目录，但目标内的文件也随之无法搜到。 |

两个数据库路径未显式配置时，会优先复用已有的 fff.nvim 数据库（`~/.cache/nvim/fff_nvim`、`~/.local/share/nvim/fff_queries`），找不到才落到 `~/.pi/agent/fff/`。这样在 Neovim 中积累的 frecency 可以直接沿用。这些目录存放个人使用数据（访问频率与搜索历史），若纳入版本管理，记得加入 gitignore。

## pi-context-view —— 上下文观察

> **一句话**：分类展示上下文被哪些内容占满，并列出最近一次请求注入的隐藏指令\
> **收益**：哪类工具输出最吃窗口、哪些扩展悄悄塞了指令，打开视图即一目了然\
> **代价**：基本没有。只工作在界面层，不往模型上下文里注入任何内容\
> **适合**：常跑长会话、装了不少扩展、在意窗口占用的人。**不必装**：会话都很短，不关心上下文构成\
> **改动深度**：只新增 `/context` 系列命令，不改 pi 的任何行为

商店：[pi.dev/packages/pi-context-view](https://pi.dev/packages/pi-context-view) · 仓库：[dimk90/pi-context-view](https://github.com/dimk90/pi-context-view) · 本机版本 `0.8.4`

平时很难看清上下文究竟被什么吃掉：哪类工具输出占了大头、哪些扩展悄悄注入了指令、系统提示本身有多长，原生界面都看不到。

pi-context-view 补上了这块观测视图：

- `/context usage`：按工具、技能、消息分类展示上下文占用，支持放大查看 1M 窗口的细目；
- `/context injections`：列出最近一次请求注入的全部隐藏内容，包括系统提示、工具定义和扩展写入的指令，哪怕是扩展仅在发包瞬间做的改动也能看到。

视图中按 `/` 可筛选搜索 Injections 与预览，按 `c` 复制高亮行或展开的预览。Usage 视图里按 `p` 可切换类别百分比的基准：按整个上下文窗口占比，或按已用上下文占比。

插件只工作在界面层，不向模型上下文注入任何内容，几乎没有使用负担。

无需配置即可使用。执行 `/context config` 会生成全局配置文件 `~/.pi/agent/extensions/pi-context-view.json`，可调配色和占用图尺寸。在首轮对话前打开视图可能会触发一次静默探测——它不发模型请求，只留下不进入后续上下文的空白条目；若想关闭，设 `autoProbing: false`。全部命令：`/context`、`/context usage`、`/context injections`、`/context config`。

**我的配置**：全默认。长会话中主要用 `/context usage` 观察各类占用的变化趋势。

## pi-cache-graph —— 缓存观测

> **一句话**：将提示缓存命中率绘成随轮次变化的曲线，并提供逐条消息的明细\
> **收益**：命中率走势直观可见，上下文改动对缓存成本的影响能直接对照\
> **代价**：无配置项，基本无负担；`/cache export` 会将 CSV 写入项目根目录\
> **适合**：常跑长会话、在意 API 成本的人。**不必装**：不关心缓存命中\
> **改动深度**：只新增 `/cache` 系列命令，不改 pi 的任何行为

商店：[pi.dev/packages/pi-cache-graph](https://pi.dev/packages/pi-cache-graph) · 仓库：[championswimmer/pi-cache-graph](https://github.com/championswimmer/pi-cache-graph) · 本机版本 `1.2.1`

提示缓存直接左右调用成本：命中的前缀按折扣计费，前缀越稳越省钱。但平时看不到命中率，上下文改动究竟把缓存打断到什么程度也无从查证。

pi-cache-graph 提供三个命令：

- `/cache graph`：展示命中率随轮次变化的曲线，按数字键切换视图；
- `/cache stats`：列出逐条消息的 token 与缓存读写明细；
- `/cache export`：将记录导出为 CSV。

命中率的计算口径为 `cacheRead / (input + cacheRead + cacheWrite)`。

插件没有配置参数，`/cache export` 导出的 CSV 默认落在项目根目录。

**我的配置**：全默认。它是上下文观测链路的一环：靠前的内容一旦改动，前缀就会失效，直接拉低命中率。用 `/cache graph` 盯住曲线，就能直观验证上下文管理策略的实际效果——这也是 [01-理念与路线.md](01-理念与路线.md) 中“让运行状态看得见”的具体落地。

## @juicesharp/rpiv-ask-user-question —— 结构化提问

> **一句话**：为模型提供一个弹出式问卷工具，需求不明确时点选确认，避免盲猜或反复打字拉扯\
> **收益**：方向性分歧一次问清，少走弯路、少来回\
> **代价**：工具说明会占一段上下文；模型问得过勤或过少时，须通过 `guidance.*` 调教\
> **适合**：常给模糊需求、希望模型先确认方向再动手的人。**不必装**：主要在脚本等非交互环境里跑 pi（该环境下工具会自动移除）\
> **改动深度**：只新增 `ask_user_question` 工具，不替换内置行为

商店：[pi.dev/packages/@juicesharp/rpiv-ask-user-question](https://pi.dev/packages/@juicesharp/rpiv-ask-user-question) · 仓库：[juicesharp/rpiv-mono](https://github.com/juicesharp/rpiv-mono) · 本机版本 `2.15.0`

需求尚不清晰时，模型通常面临两难：直接按猜测动手，很可能整个方向跑偏；用自然语言反问，又往往要打一大段字、来回几轮才能对齐。

这个插件给模型提供 `ask_user_question` 工具，用于弹出结构化问卷：单次最多 4 题，每题 2–4 个带说明的选项，选项还支持附带 markdown 预览。模型负责拟好候选项，点选或按 <kbd>1</kbd>–<kbd>9</kbd> 选定后，结果以结构化数据交回模型。

在无 TTY 的非交互环境下，工具会自动移除，不会卡住脚本执行；在 VS Code、Zed 等 RPC / ACP 宿主中，问卷则以原生对话框呈现。

配置文件位于 `~/.config/rpiv-ask-user-question/config.json`（若存在 `$XDG_CONFIG_HOME/rpiv-ask-user-question/config.json` 则优先读取），插件只读不写。非法值回退默认，JSON 解析失败时在 stderr 打印警告。

**我的配置**：全默认（未创建配置文件）。

### 参数

**常用参数**

| 参数 | 默认 | 说明 |
|------|------|------|
| `collapseKey` | `ctrl+]` | 折叠或展开问卷的快捷键。设为 `"off"` 仅禁用快捷键，问卷照常可用。键盘布局不方便按 <kbd>Ctrl</kbd>+<kbd>]</kbd> 时，可改为 `alt+o` 等组合。 |
| `guidance.promptSnippet` | 内置简介 | 写入系统提示的一行工具简介，直接影响模型提问的积极程度，例如可写“仅在关键需求不明确时提问”。 |
| `guidance.promptGuidelines` | 内置 4 条 | 提问准则列表，配置后会整体替换默认准则（如集中提问、推荐项居首）。宜写成具体的行为规则；空值或非法值会回退默认。 |

`guidance.*` 调整的是发给模型的提示词，并非硬性约束。它在工具注册时读取，修改后须重启 Pi。由于自定义列表会整体替换默认准则，仍需保留的默认要求须手动写回。

另有几项写死的上限，无法通过配置修改：单次最多 4 题，每题 2–4 个选项，选项 label 不超过 60 字符；`Other`、`Type something.` 等属于保留标签，模型不可占用。

<details>
<summary><b>其余参数（2 项）</b></summary>

| 参数 | 默认 | 说明 |
|------|------|------|
| `notesKey` | `n` | 打开备注编辑器的按键，支持任意单个字符（含 `т` 等非拉丁字符）或 `ctrl+n` 类组合键。 |
| `guidance.description` | 内置说明 | 整体替换模型看到的工具描述，不与默认描述合并。仅需调整提问习惯时，优先改上面两项。 |

## @narumitw/pi-btw —— 旁路提问

> **一句话**：用 `/btw` 拉起一条临时旁路线程，带着主会话上下文插问，问答默认不写入主会话\
> **收益**：长任务中途随时核对细节，不污染主会话上下文与历史；有价值的结论再手动带回主输入框\
> **代价**：每次旁路提问多一次模型调用，所选会话上下文（最多取最近 40,000 字符）会发给所用模型；旁路线程只驻留内存，`/new`、`/resume`、`/reload` 或重启后清空\
> **适合**：常在长任务中途冒出旁支问题的人。**不必装**：习惯单线推进，或不介意直接在主会话里插问\
> **改动深度**：只新增 `/btw` 命令与独立旁路工作区，不改主会话上下文和模型

商店：[pi.dev/packages/@narumitw/pi-btw](https://pi.dev/packages/@narumitw/pi-btw) · 仓库：[narumiruna/pi-extensions](https://github.com/narumiruna/pi-extensions) · 本机版本 `0.63.9`

在主会话中途插问旁支细节，问答会一直滞留在上下文里，既占窗口，也容易把主线带偏；另开新会话来问，又拿不到当前上下文。

pi-btw 用临时旁路线程解开这个矛盾：

- `/btw <问题>`：直接拉起一条旁路线程，基于主会话当前分支作答，不切换主会话分支；
- `/btw`：打开管理界面，选择参考上下文、续接已有旁路线程或调整设置。

旁路线程内支持追问、排队引导与记录搜索，问答默认不写进主会话。若答案有用，按 <kbd>Ctrl</kbd>+<kbd>R</kbd> 可将最新回复、某段问答或整条线程带回主输入框——只填入不自动发送，覆盖已有草稿前会先确认。

主会话的新进展不会自动同步进旁路线程。输入问题时按 Import main updates（默认 <kbd>F9</kbd>）可预览并确认导入，导入会相应增加上下文长度与费用。

旁路工作区支持全屏、旁路居左、旁路居右三种布局。分栏时另一侧实时呈现 pi 原生主会话视图，拖动分隔线即可调整旁路占比（20%–80%），松手自动保存；焦点切回主会话侧后可照常提交和引导，无需关闭旁路。终端宽度不足 80 列时自动折叠为只显示旁路线程。

`/btw` 仅支持 TUI 模式。旁路默认沿用当前会话的模型与思考档位，也可在 `/btw` → Settings 中单独指定，不影响主会话。

配置文件位于 `~/.pi/agent/pi-btw.json`，首次在设置页修改选项、记住档位或拖动分隔线时才会创建。每次调用 `/btw` 都会重新读取，改完无需 `/reload`。

**我的配置**（[`config/pi-btw.json`](../config/pi-btw.json)）：

```json
{
  "fullscreenCopyOnSelect": false,
  "layout": "right-pane",
  "sidePaneRatio": 0.3813
}
```

- `layout: right-pane`：旁路线程置于右侧，左侧保留主会话视图。
- `sidePaneRatio: 0.3813`：旁路约占 38% 宽度，由拖动分隔线后自动写入。
- `fullscreenCopyOnSelect: false`：旁路工作区内选中文字不自动复制，改用 pi 的复制快捷键。pi-btw 不继承 pi 本体的同名设置（`settings.json` 中同样设为 `false`），因此须在这里单独关闭。

## @dietrichgebert/ponytail —— 精简改动

> **一句话**：每轮向系统提示注入一套“懒惰的资深开发者”规则，促使模型先找现成方案，只写完成任务所需的最小代码\
> **收益**：少出多余抽象、无人要的配置项与新依赖，diff 更短更好审；改动波及的调用方、测试与配置依然要求改全\
> **代价**：规则每轮都占一段系统提示；模型会主动跳过它判定为非必要的部分，真正需要的功能须讲明\
> **适合**：觉得模型写代码偏繁、爱过度设计的人。**不必装**：偏好一步到位的完整可扩展实现，不希望模型主动做减法\
> **改动深度**：通过扩展向系统提示注入规则，另增 6 个技能与 `/ponytail` 系列命令；不替换内置工具

商店：[pi.dev/packages/@dietrichgebert/ponytail](https://pi.dev/packages/@dietrichgebert/ponytail) · 仓库：[DietrichGebert/ponytail](https://github.com/DietrichGebert/ponytail) · 本机版本 `5.3.3`

模型写代码容易顺手膨胀：多余的抽象层、没人要的配置项、为几行逻辑引入的新依赖。每次都在提示词里反复叮嘱既繁琐又容易漏。

ponytail 把这套约束做成了常驻规则。每轮开始前，扩展将当前档位的规则写入系统提示，按固定优先级引导模型决策：先判断这件事该不该做，再依次排查代码库现有实现、标准库和已装依赖，确实没有才写新代码。与此同时，受改动波及的调用方、测试和配置必须改全，信任边界校验、防数据丢失的错误处理、安全与无障碍也不得省略。回复末尾还会用一两行交代跳过了什么以及潜在风险。

本机以 git 方式安装，`settings.json` 的 `packages` 中写作 `git:github.com/DietrichGebert/ponytail`，版本号取自仓库 `package.json`。

规则分三档，按会话记录：

- `lite`：按要求照常实现，仅用一行指出更轻量的替代方案，交由用户定夺；
- `full`：完整规则，默认档位；
- `ultra`：动手前会先质疑需求本身，对非必要部分直接提出反对。

单条消息只输入 “stop ponytail” 或 “normal mode” 时，当前会话关闭 ponytail。全部命令：

- `/ponytail [lite|full|ultra|off]`：切换当前会话档位；不带参数时开启，已开启则显示当前档位
- `/ponytail status`：查看当前档位与默认档位
- `/ponytail default <档位>`：修改默认档位并写回配置文件
- `/ponytail-review`：审查一次改动的逻辑、安全、负载、测试与性能，逐行检视必要性
- `/ponytail-audit`：对整个仓库做质量审计，只出报告，不改代码
- `/ponytail-debt`：汇总代码中的 `shortcut:` 注释，生成技术债清单
- `/ponytail-gain`：展示插件基准测试测得的精简收益
- `/ponytail-help`：速查档位、技能与命令

后五个命令分别转交同名技能执行。

配置文件位于 `~/.config/ponytail/config.json`（设置了 `XDG_CONFIG_HOME` 时改读其下的 `ponytail/config.json`），不在 `~/.pi/agent/` 下，因此 `config/` 未收录副本。

**我的配置**（`~/.config/ponytail/config.json`）：

```json
{
  "hideStatus": true
}
```

- `hideStatus: true`：隐藏状态栏上的 ponytail 指示，规则照常生效。

### 参数

**常用参数**

| 参数 | 默认 | 说明 |
|------|------|------|
| `defaultMode` | `full` | 新会话的默认档位，也可通过 `/ponytail default <档位>` 修改。<br>· `off`：默认关闭<br>· `lite`：仅提示更轻量的方案<br>· `full`：完整规则<br>· `ultra`：连同需求一起质疑 |
| `hideStatus` | `false` | 隐藏状态栏指示，规则照常生效。状态栏空间紧张时开启。 |
| `quietStartup` | `false` | 隐藏启动时的 “Ponytail loaded” 提示，规则照常生效。 |

三项均可通过环境变量 `PONYTAIL_DEFAULT_MODE`、`PONYTAIL_HIDE_STATUS`、`PONYTAIL_QUIET_STARTUP` 覆盖，环境变量优先级高于配置文件。

## pi-quote-blocks —— 引用回复

> **一句话**：把回复中选中的片段转为引用块，草稿里用 `[Qn]` 占位，发送时自动展开为 Markdown 引用\
> **收益**：针对长回复里的多处细节分别回应，省去手动复制粘贴和排引用格式的麻烦\
> **代价**：直接读取选区依赖 pi 渲染器内部接口，仅在插件核对过的 pi 版本（1.0.3、1.4.0）上启用，其余版本改读剪贴板；默认占用 <kbd>Alt</kbd>+<kbd>Q</kbd>、<kbd>Alt</kbd>+<kbd>E</kbd>、<kbd>Alt</kbd>+<kbd>H</kbd> 三个快捷键\
> **适合**：常需逐段回应长回复的人。**不必装**：日常回复较短，用不到引用\
> **改动深度**：新增 `/quote`、`/quotes` 命令、三个快捷键及输入框上方卡片；发送时把标记展开成引用，模型收到的是展开后的完整文本

商店：[pi.dev/packages/pi-quote-blocks](https://pi.dev/packages/pi-quote-blocks) · 仓库：[codelllc09/pi-quote-blocks](https://github.com/codelllc09/pi-quote-blocks) · 本机版本 `0.2.2`

要针对长回复里的某几段分别回应，以往要么手动复制原文再排引用格式，要么费力用文字指代“上面第三段”。

pi-quote-blocks 将流程拆成三层：

- 选中的文本转为引用块，以卡片形式停靠在输入框上方；
- 草稿中只需插入 `[Qn]` 短标记，标记所在位置即最终引用出现的位置；
- 发送时标记自动展开为 Markdown 引用（`> …`），草稿里未提及的块直接丢弃。

删去草稿里的 `[Qn]` 标记，对应卡片随之移除；每批编号均从 Q1 重新起算。操作方式：

- 在对话区拖选后按 <kbd>Alt</kbd>+<kbd>Q</kbd>：创建引用块并在光标处插入 `[Qn]`；无选区时改读系统剪贴板
- `/quote [n]`：引用倒数第 n 条助手回复，默认取最后一条
- <kbd>Alt</kbd>+<kbd>E</kbd> 或 `/quotes`：打开块管理器，支持预览、编辑、删除引用块或重新插入标记
- <kbd>Alt</kbd>+<kbd>H</kbd>：折叠或展开卡片
- `/quotes <子命令>`：支持 `clear`、`fold`、`unfold`、`edit Qn`、`remove Qn`、`preview`

直接读取选区依赖 pi 渲染器的内部接口，插件仅在核对过的 pi 版本（1.0.3、1.4.0）上启用。其余版本及非全屏模式下，<kbd>Alt</kbd>+<kbd>Q</kbd> 只读取系统剪贴板。本机运行的是 pi 1.6.1，不在核对名单内，加之 `fullscreenCopyOnSelect` 设为 `false`（见 [ref-settings.md](ref-settings.md)），使用时需先复制选区再按 <kbd>Alt</kbd>+<kbd>Q</kbd>。

插件没有配置文件，全部选项通过环境变量设置。

**我的配置**：全默认，未设置任何环境变量。

| `PI_QUOTE_KEY_MANAGE` | `alt+e` | 打开块管理器的快捷键，写法同上。 |
